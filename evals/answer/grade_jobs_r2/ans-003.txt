QUESTION: how are embedding vectors stored inside the sqlite index

(no extra note for this question)

CHECKS:
1. Vectors are stored as 16-bit float (fp16) blobs beside their segment rows
2. Vectors live in the same SQLite file as the rows that describe them, so a crash can never leave them out of step
3. The whole vector table is loaded once per command

ANSWER:
Embedding vectors are stored as fp16-encoded BLOBs in the `vec` column of the `segments` table, living in the same SQLite database right beside the rows they describe, so a crash can never leave them out of step [3]. The on-disk index is one SQLite file that holds the files, their segments (with fp16 vectors), and an FTS5 keyword table [1]. There is no separate vector store or vector database; the whole vector table is loaded once per command [2]. At search time the blobs are unpacked from fp16 to float32 in blocks of 8192 rows, and brute-force search over that in-memory copy takes a few milliseconds at this scale (~20k vectors, ~30 MB) [1][3].
