QUESTION: how do the query prompt and the document prompt differ before text is embedded

CHECKS:
1. Queries are wrapped as 'task: search result | query: {text}'
2. Documents are wrapped as 'title: {title} | text: {text}'

ANSWER:
Before embedding, the query is wrapped in the prompt `task: search result | query: {text}`, while documents are wrapped in `title: {title} | text: {text}` — both verbatim per the EmbeddingGemma 2 model card [1]. The query prompt adds only a search-result task instruction around the raw text, whereas the document prompt prepends a separate title slot (the file stem or page-number label) alongside the text [1][2]. In code, `document_prompt` substitutes `"none"` when the title is None [2]. The prompts are applied outside the backends: the pipeline applies the document prompt and the CLI/search apply the query prompt before calling `embed_texts` [2]. These prompt strings are part of the embed fingerprint, so changing either forces a reindex [2]. Media vectors carry no prompt at all [1].
