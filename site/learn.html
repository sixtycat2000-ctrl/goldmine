准入门槛

Admission Gate

定义 候选池的唯一硬规则：z ≥ 3.0（z_gate）；词覆盖率 ≥ 0.5 的文件也进。3.0 由 v2.1 校准 A/B 定下（n=146 真模型评测）：从 2.0 提到 3.0，s@5 0.747→0.781、MRR 0.646→0.665、零命中诚实度 0.4→0.6，train 与 holdout 一致、零单题回归。扫描中 3.5 更好（0.822）但故意不采纳——一次扫描、过拟合风险，记录在案（「不做质量重试」纪律的来源）。

大白话 海选。不是所有自称「有点像」的文件都能进下一轮：要么语义上真的鹤立鸡群，要么查询词真的出现在它身上。门槛是拿 146 道真题做 A/B 试验定下来的，不是拍脑袋。曾看到 3.5 更好看，但只试了一次不敢信，忍住没改。

实例 A/B 记录：z_gate 2.0→3.0 使 s@5 0.747→0.781、MRR 0.646→0.665、zero-hit honesty 0.4→0.6；3.5 得 0.822 但弃用。对照回归门：python3 scripts/eval_real.py --suite legacy --backend llama --gate 应见 gate: green。

  • goldmine/admission.py

见证规则

Witness Rule

定义 search.v7 规则：混合模式查询下，一个文件若 z 分够高但没有任何词法证据（无 BM25 排名、coverage 为 0），不准进候选池。防的是语义模型的「空吸」——embedding 对某些查询天然亲近某些内容。例外：纯媒体文件（只有图片/音频向量、没有文字可沾）豁免——它们没资格提供见证，不能因此被判死刑。新增媒体段型时 _files_with_text 的口径要跟着审。

大白话 一个嫌疑人 DNA 匹配 99%，但案发现场、时间线、证人一样都对不上——光 DNA 一条孤证不放人。除非这个案子根本没有别的证据可查（比如纯图片文件，没文字可沾），那才破例。

实例 z=4.5、coverage=0、无 BM25 排名的文本文件 → 拒。同一文件若是纯图片（无文本段）→ 豁免放行。这是第一讲十问第 4 题的原题。

  • goldmine/admission.py
  • goldmine/search.py

证据选择

Evidence Selection

定义 每个命中的文件内部再选一次证据段：z 够高时主证据 = 语义最佳段，否则 = 关键词命中段；精确短语命中强制做主证据。evidence-window 规则：某段里 200 字符窗口内聚着的查询词比语义最佳段多 ≥2 个不同词时，主证据让位——语义模型偶尔被标题党吸走，词证密集处更可信。supporting 段随行，之后近重复折叠（同文件近似段只展一条）、«» 高亮、渲染输出。

大白话 找到一本书只是第一步，还得翻到最该给你看的那一页。通常翻到「意思最像」的那页；但如果有一页上你问的词密密麻麻挤在一起，就翻那一页——满页都是你问的词，比「感觉像」更实在。

实例 goldmine search 加 --why 可见每个命中的 primary/supporting 段选择；标题党场景：标题含全部查询词但正文无关 → 词证密集窗口接管主证据。

  • goldmine/search.py
  • goldmine/render.py

pack 预算

Pack Budget

定义 search --pack 把命中装成「答案材料包」：平铺记录（# 头块 + [n] 逐字记录 + # sources 尾块），整个 stdout 的 token 数用 backend.count_tokens 实测（估算器兜底，模式打印在头部）。装包顺序：整条主证据按排名序，再 supporting 段，再邻居上下文；装不下的整条跳过、后面候选递补；正文与引用永不截断。默认预算 4000 token，区间 [512, 32768]，至多 24 条记录；尾部 used N 是「渲染-测量不动点」，不收敛就丢最后一条重试——绝不打印一个没测过的数。

大白话 给 AI 助手的资料袋有大小限额。装袋规矩：最重要的整篇先装，装不下的整篇不装（不许撕半页），装不下就换下一篇试试；袋口写着「实际用了多少」——这个数是量出来的，不是估出来的。

实例 python3 -m goldmine search '环氧垫片' --pack --budget 4000 --db evals/eval.sqlite；--budget 必须跟 --pack 一起用（--context 半径钳到 ≤3）。头块打印 token 模式（tokenize 或 estimate），尾块打印 used N 与 sources。

  • goldmine/pack.py
  • goldmine/pack_allocation.py

常驻媒体边车

Resident Media Sidecar

定义 llama-server 的 HTTP 接口不暴露 mtmd（多模态）嵌入——图片/音频进不了它。于是自写 1412 行纯 C11 的 goldmine-embed，静态链接 llama.cpp + mtmd 七个静态库，作为常驻边车与主程序同生共死。协议简单到不会错：每行一个 JSON（请求带 path_b64/wav_b64，回一个 768 维向量）。模型加载要搬约 1GB 进内存，常驻省的是加载与逐次 spawn，不是缓存计算图——gemma-embedding2 没有 KV 记忆，批次间只能清空重来。清理纪律：close() 按 pid 只杀自己 spawn 的子进程。

大白话 主程序旁边挂一辆挎斗摩托：主车管文字，挎斗管图片和声音。挎斗一次造好、随叫随到，不用每送一单重新发动。俩车说话的规矩简单到极点——一次递一张纸条，纸条上只写一行字。

实例 启动握手：--version 探活 + mmproj sha 校验；健康失败 → NotSupported/BackendStartupError（exit 2）。源码 1412 行在 tools/embed/goldmine-embed.c。杀别人的 llama-server 是上古事故，pid 记账只杀自己的。

  • tools/embed/goldmine-embed.c
  • goldmine/backends/embed_helper.py

媒体 token 预算

Media Token Budget

定义 图片进模型不是无脑塞满：照片 140 token、截图 280、PDF 页 280、视频帧 70（合法集 70–1120）。预算决定图片进模型前的缩放尺寸，是成本与信息量的权衡（DigUp 实测先验）。预算写进指纹的 media_budgets 键——动预算 = 全量重嵌，不许悄悄动。

大白话 看照片用放大镜看细节，看一页文件扫一眼就够——不同东西花不同功夫。这张「功夫价目表」是白纸黑字公布的：改价目表等于承认所有旧照片都要重新看一遍。

实例 预算表：photo 140 / screenshot 280 / pdf_page 280 / video_frame 70。改动任何一个数字都会改变指纹的 media_budgets 键 ⇒ 旧库被门拒绝 exit 3。

  • goldmine/backends/llama.py
  • goldmine/ingest/media.py

指纹门

Fingerprint Gate

定义 一切「决定向量取值」的东西——模型身份、维度、提示词、池化、归一化、媒体加工串、预算——打包成 JSON，canonical 化后取 sha256 前 16 位。任何一项变 → 指纹变 → 旧库被门拒绝 exit 3。动机：两种指纹的向量混在一个库里互比分数 = 搜索静默变坏且无从察觉。它是四层身份模型（指纹 / embed_id 管哪些行重嵌 / 提取器注册表管哪些行重抽 / 评测基线管分母没被偷换）的第一层执法点。词法检索不过这道门，--lexical 永远可用；llama.cpp 构建串也刻意不进指纹——「向量没变」由参考向量测试证明，动了才升指纹字段。

大白话 菜品的配方指纹：原料、火候、厨具全部记下来盖个章。换任何一样，章就变了，老批次必须全部下架——新做法的菜和老批次摆在一起比味道，比试已经不公平了。另有一本分层的账：大门管「这个库还能不能用」，车间账本管「哪排货要返工」，别混成一团。

实例 亲手看它开火（ANCHORS 第 2 条）：python3 -m goldmine search 'copper gasket' --db evals/eval.sqlite.pre-p2b.sqlite; echo rc=$? → refused: ... different embedding fingerprint（differs in: media）+ rc=3；加 --lexical 再跑 → rc=0 有结果。

  • goldmine/fingerprints.py
  • goldmine/backends/llama.py

一文件一事务

One Transaction Per File

定义 摄取的最小提交单位是「一个文件」：该文件的段、FTS 行、向量行在同一个事务里原子替换（旧段先删净、新段整体落库）。崩溃或 Ctrl-C（exit 130）最坏丢掉正在写的这一个文件的这一次，绝不留半个文件的段在库里。重跑靠内容哈希跳过未变文件，几乎零成本续传。配合 WAL，读写互不阻塞：扫描进行中也能随时搜索。

大白话 登记卡片一张一张写：写一张、盖一张的章。中途停电，最坏坏掉手里那张，抽屉里已盖章的卡片都完好——绝不会出现半张卡（半张卡比没有卡可怕得多，检索会撞上残缺的段）。

实例 摄取中途 Ctrl-C → rc=130；重跑摄取，内容 sha256 未变的文件全部跳过（进度日志可见 skipped 计数），只补写被打断的那一个。库目录下 -wal/-shm 伴生文件是 WAL 模式的痕迹。

基线与审计门

Baseline & Audit Gate

定义 基线 = 冻结的历史分数（比较的锚）；gate = 每次 CI 式重跑与基线比、超阈值即红。基线确实需要重生时（语料或身份合法变化）唯一合法通道是审计门：先备份 → 重建 → 逐条对账每处差异（预期内放行、未解释的漂移追责）——杜绝「顺手夹带」。评测基线带 corpus_version + corpus_sha，语料漂移会让 gate 响亮作废，而不是静默拿旧分母比新语料。

大白话 成绩单锁在保险柜，平时只能对照、不能改。真到了必须重考（比如换了考场），流程是：旧成绩单复印存档 → 重考 → 每一处分差说清来历。说不清的那一分，不许悄悄抹平。

实例 现场范例 reports/execution/digup-p2-closeout-001/eval-rebuild-audit.md（批次 B）：8 项差异逐条归属，其中「+1 文件」查实是新命令文件落进摄取根、不是夹带；双 gate 全 0 delta、参考向量逐位复现，旧库备份保留作审计证据。

  • scripts/eval_real.py
  • reports/execution/digup-p2-closeout-001/eval-rebuild-audit.md

预注册

Preregistration

定义 结构性改动前把设计、逐文件哈希、通过判据冻结成文——先承诺再动手，防止「边做边改标准」。判负就回滚：digup-plan-001 的检索改进在 DigUp 有实测正收益，goldmine 自己 A/B 后零改善，按预注册判负回滚；另一项撞了冻结基线，按规则回滚。DigUp 的数字是先验不是证明——此为铁律。批次 B 的尾窗语义偏差也明写进预注册。

大白话 动工前把图纸、验收标准和「什么情况算失败」白纸黑字公证一份，完工时对照公证书说话，不许赛后改标准把失败说成成功。别家工地考了 90 分，不代表你的考场一定行——各考各的。

实例 现场范例：reports/execution/digup-plan-001/ 与 digup-plan-002/（预注册 + 判负回滚全程留痕）。零改善回滚是它的标志性判例——不是「再调调」。

  • reports/execution/digup-plan-001/
  • docs/execution-plan/REVIEW.md

对抗评审

Adversarial Review

定义 另一个独立 AI 上下文专职攻击设计（找反例、验主张），裁决 ADOPT / ADOPT-WITH-CHANGES / REJECT。两次关键拦截都来自它：查询期已删文件过滤的第一版会打挂 21 个用假路径的离线测试（改为只在 roots 内过滤后放行）；批次 B 抓到三处硬编码版本字面量的「永久重抽」陷阱（D1）。

大白话 图纸画完先请一位专门唱反调的审图员，他的工作就是找「什么情况下会塌」。他不许客套，只给三种结论：照单全收、改完再收、推倒重来。

实例 拦截一：A2 删除过滤初版被拦（21 个离线测试用假路径建库），改为只在 roots_json 范围内过滤。拦截二：三处 media-ffmpeg-mm.v2 字面量漂移被抓，修成单一共享常量 + 相等性测试。

音频路由

Audio Routing (MM-D3)

定义 MM-D3 路由规则：whisper 转写成功的音频，转写块同时进 FTS 并用提示词文本向量（任何文本后端都行）——文字向量更准；只有非语音内容或 whisper 缺席时才回退原始音频窗口向量。每行 info 写明「这条向量为什么存在/不存在」（如 raw:no-transcript(asr_status)）——路由决策本身是可审计的数据，不是黑盒。幻觉防护：对静音/音乐硬转会产生幻觉，转写段按置信度与字符率双门丢弃（asr_dropped 逐行记录）。

大白话 录音带先请速记员抄成文字，抄成功的按文字归档（查文字比查声音准）；实在抄不出来（纯音乐、或速记员不在），才把原始声音本身做成「声音指纹」入库。每条记录都注明走的是哪条路——账目清楚，日后才知道为什么搜得到/搜不到。

实例 转写成功 → 文本段（FTS + 文字向量）；whisper 缺席 → 回退音频窗口向量，info 逐行记 asr_status。验证媒体向量未被改坏：GOLDMINE_LIVE=1 python3 -m pytest -q tests/test_reference_media_vectors.py。

  • goldmine/ingest/asr.py
  • goldmine/ingest/media.py

尾窗 ≥2 秒新音频门

Tail Window ≥ 2s New Audio

定义 音频按 30 秒窗、25 秒步进分窗时，最后一个不满 30 秒的尾窗只有在携带 ≥2 秒「超出上一窗覆盖的新音频」时才保留。源码考古发现：goal prompt 写的「丢 <2s 尾窗」在 30/25 参数下字面上不可达（尾窗最短 5 秒），prompt 的 62 秒例子还与源码相反——按源码移植，偏差写进预注册。教训：「prompt 当规格」有风险，流程要求对照源码。

大白话 交接班时，下一班只比上一班多听了两分钟以上，才值得把记录本续写一页；只多几秒的重复内容，上一页里已经有了。

实例 30 秒窗、25 秒步进下：62 秒音频 → 窗 [0,30)、[25,55)、尾窗 [50,62) 带 7 秒新音频（超出上一窗覆盖）→ 保留；56 秒音频 → 尾窗 [50,56) 只带 1 秒新音频 → 不保留。而「尾窗长度 <2 秒」在这种参数下根本不可能出现（最短 5 秒）——这正是死代码考古的发现。

  • goldmine/ingest/media.py

RMS 静音门

RMS Silence Gate

定义 均方根（RMS）≈ 响度代理；低于 0.003（约 −50 dBFS）的音频窗口没有信息，跳过不浪费嵌入。与 30 秒窗、25 秒步进的分窗配合，静音窗直接丢弃；该参数进媒体加工串（rms-gate0.003），是 DigUp 先验。它是「省钱三连」的第一道：静音门丢静音窗 → 尾门丢重复窗 → aHash 丢重复帧。

大白话 录音里大段的「没人说话」不用请速记员记：先量一量这一段有多安静，安静到听不见的整段跳过，省时省钱。

实例 media.py 的常量：SILENCE_RMS = 0.003（≈ −50 dBFS，DigUp 先验）；v5 加工串片段 window30s,hop25s,rms-gate0.003,tail-min2s。

  • goldmine/ingest/media.py

阿拉伯丢字页 OCR 替换

Arabic lostLetters OCR Replacement

定义 某类 PDF 的阿拉伯语文本层丢 lam-连写字形（lostLetters 病理）：显示与复制都残缺。goldmine 检测该病理并用 OCR 替换文本层。病理复现验证诚实失败：macOS 原生工具链产出的阿拉伯 PDF 全带完整 ToUnicode，造不出病——按预注册回退为合成病理 + 机制测试，真实资产记 MISSING。版本串按组合登记（如 pdftotext+arocr+visionocr@24.08.0，四种组合全部入册）。

大白话 有些 PDF 看着是阿拉伯文，复制出来却缺胳膊少腿。医生说治得了；想先造个病人验证疗法，结果本地根本造不出这种病人——于是老老实实记下「这种病例没验证过」，先用塑料模特练手。

实例 检测在 extract_pdf.py：lostLetters = lam-连写丢失（bare alef 出现在本该连写的位置）。升级串如 pdftotext+arocr+visionocr@24.08.0 由统一组装函数按字母序拼出，注册表登记全部四种组合——组装函数与注册表同源。

  • goldmine/ingest/extract_pdf.py
  • goldmine/fingerprints.py

查询期删文件过滤

Query-time Deleted-file Filter

定义 A2 规则（2026-10-25 批次 A）：候选集确定后、取前 limit 之前，对文件来源的候选查一次磁盘存在性，已删的剔掉并计数（settings.deleted_filtered，--json 与 MCP 都能看到）。两个刻意限定：URL 行豁免（网页在不在磁盘没意义）；只管本索引真实摄取过的目录范围（roots_json）内的行——离线测试用假路径建库，不该被误伤。发生在 limit 之前 = 取前 20 条的前提是「全是活文件」，预算不因死文件缩水。第一版被对抗评审拦下，改为 roots 内过滤后才放行。

大白话 报出的每条结果都答应「现在点得开」。查无此物的就别端上桌，还得数清楚剔了几条。但只在自己管辖的文件夹里核对——别人家测试用的假门牌，不归这条规矩管。

实例 python3 -m goldmine search x --db evals/eval.sqlite --json 里看 settings.deleted_filtered 计数。对照摄取侧：路径消失但 inode 出现在别处 = 移动而非删除（见 move-detection），两边语义对称。

  • goldmine/search.py
  • goldmine/ingest/pipeline.py

iCloud dataless 跳过

iCloud dataless Skip

定义 macOS 的 st_flags 标志位里 SF_DATALESS（0x40000000）=「iCloud 占位，实体在云上」。对这种文件 open() 即触发下载（可能几百 MB、要走网络）。所以拦截必须在一切会 open 的操作（包括格式嗅探）之前，用 lstat 看标志而不打开文件。Python 的 stat 模块不导出 SF_DATALESS，代码显式定义（walk.py:63）。文件符号链跟到目标后查的是目标的标志——符号链进 iCloud Drive 也拦得住。

大白话 云盘文件夹里有很多「空盒子」：看一眼标签就知道是什么，但真要打开，就得现场从云端搬货——又慢又费流量。规矩：先看标签，是空盒子就绕着走，绝对不手贱打开。

inode 移动检测

inode Move Detection

定义 inode = 文件系统里文件的唯一编号，改名、挪目录都不变。删除检测时「路径消失但 POSIX 身份（dev+ino+大小+mtime）出现在本轮候选里」= 移动而非删除——改个路径保住全部已嵌内容，不删不重嵌。配套守卫：根/子树不可读 ≠ 空（弹出硬盘、TCC 弹窗绝不能读成「全删了」），unreachable 前缀守卫保留这些行。收尾挂在每波摄取之后：moves = walk.detect_moves(self.store, resolved_roots, candidates)。

行走门禁

定义 目录行走的三大门禁，全部刻意确定性：①跳过表——构建产物目录（build/target/dist/out/.next）、密钥、许可文件、压缩包（zip 炸弹面）不索引，理由逐条写在 rules.py；②符号链政策——目录符号链永不跟随（防 a→b→a 死循环），文件符号链跟到内容；③顺序钉死——roots 与每个目录的 entries 都 sorted，单线程行走：同样的磁盘永远产出同样的候选序列，重跑才敢跳过、对比才有意义。

断管纪律

EPIPE Discipline

定义 goldmine search | head 里 head 拿够就走，goldmine 再写时内核回 EPIPE，默认行为是 SIGPIPE 信号杀死进程。Python 把 SIGPIPE 转成 BrokenPipeError，但要主动接住才能安静退出。深层坑：小输出躺在用户态缓冲区没进管道，执行期不报错，只在解释器退出 flush 时爆（退出码 120）——修法 = 执行期 handler + 退出前主动 flush 探针（师承 DigUp IndexService.swift:331-336 的 EPIPE 纪律）。边车一侧同款纪律：吞 EPIPE + 忽略 SIGPIPE。

大白话 你往传送带上放包裹，对面收货的下班了。放的那一刻传送带还转着（东西堆在缓冲区），等你下班前最后一搬才听见「对面早没人了」的警报——这时想体面收工已经晚了。所以收工前主动按一下警报器试试。

轮询与裸读纪律

poll & Raw-read Discipline

定义 poll = 问内核「这个 fd 现在有数据吗」（level-triggered：有就一直报有）。BufferedReader 会预读——把管道里的数据提前搬进自己的内部缓冲，poll 看管道永远空 → 永远不醒（观测过的真事故：ready 行被 BufferedReader 吃掉、poll 饿死、启动超时）。所以边车协议读必须用裸 fd 的 os.read，要多少读多少。这是边车「四条命」之二，注释原话：Raw os.read on the fd — NEVER the BufferedReader。

FTS5 与 BM25

FTS5 & BM25

定义 FTS5 是 SQLite 内置的全文索引，本质是倒排索引：词 → 含它的行，像书后的索引页。BM25 是它的排名公式——查询词越稀有、在文档中出现越密、文档越短，排名越靠前。本项目只用 BM25 的排名（词法臂），从不把它的分值加进最终分数：BM25 低 = 好，方向与最终分数相反。词覆盖率 coverage（查询词在文件中的覆盖比例）是这条臂对融合的真正贡献。

大白话 一本书后面的索引页：「关键词 → 第几页」。翻索引比翻全书快得多。BM25 是给命中结果排队的规矩：命中一个全书只有三处提到的生僻词，比命中满篇都是的「的」值钱得多。

实例 查 TRX50（主板编号）：语义模型不认识这个编号，只有 FTS5 能精确命中。跑 python3 -m goldmine search TRX50 --db evals/eval.sqlite；--why 输出里能看到 BM25 排名，但它只决定词法臂的顺序，对最终分数的贡献是 0。

提示词方案

定义 embeddinggemma 这类模型要求输入带固定模板：查询侧 'task: search result | query: {text}'，文档侧 'title: {title} | text: {text}'（base.py 的 QUERY_PROMPT / DOCUMENT_PROMPT）。穿错外衣向量就变味——所以 prompts 是指纹八字段之一。细分纪律：文档提示词进 embed_id（它变了，每个存量向量的取值都变，必须全量重嵌），查询提示词不进（只影响查询那一个向量，零重嵌）。2026-10 的 v1→v2 提示词重构因此是零重嵌迁移；同月给代码文件加标题提示词的 A/B 零改善，按预注册回滚。

Q8_0 与 GGUF

定义 神经网络权重本是 16 位浮点；量化把它们压成 8 位整数（Q8_0 是 llama.cpp 的 8 位格式，_0 表示对称分组，组内共享缩放因子摊薄误差），装在 GGUF 单文件容器里。模型文件约 1.5GB → 约 800MB，推理快数倍，精度损失极小。更激进的 Q4 精度损失开始可测；F16 被明确禁止——同模型家族实测激活值溢出 float16，记录在案。whisper 走同一思路：large-v3-turbo 的 Q5_0。

fp16 向量存储

fp16 Vector Store

定义 存储合同（D7）：768 个 float32 向量压成 1536 字节的小端 float16 BLOB 落库（util.pack_fp16 / unpack_fp16），检索时按 8192 行的块批量还原成 float32 再算余弦。权衡：存储减半、缓存更友好，fp16 的 10 位尾数对归一化向量的余弦排序无影响——这是「存储侧量化」，与模型权重的 Q8_0 是同一家族的两个决定，各自独立钉进合同。

SHA-256 内容哈希

定义 SHA-256 把任意数据映射为 64 位十六进制摘要；输入变一位，输出面目全非（雪崩效应）。本项目的三处用途：摄取每波先比对文件内容是否变化（未变则跳过，G10 语义）；给模型文件验明正身（model_sha256、mmproj_sha256 进指纹）；作为指纹身份本身的哈希原料（canonical 字节串 → sha256[:16]）。一处实现、三种身份用途——都吃「雪崩」这碗饭。

嵌入

Embedding

定义 嵌入把任意一段文本映射为一个 768 维浮点向量（embeddinggemma-2，MEAN 池化，归一化）。训练目标是「含义相近 ⇒ 向量夹角小」，于是几何关系成了含义的代理。检索时查询与文档各算一个向量，比较就变成比夹角。这是语义检索领域的通用方法：把「理解」外包给一个预训练模型，工程只负责比较。

大白话 想象一张巨大的地图，每个意思都有一个坐标——坐标不是两个数，是 768 个数。意思越接近的两段话，坐标离得越近：「猫」和「狗」挨着，「猫」和「资产负债表」隔得很远。电脑不认识字，但它特别擅长算坐标之间的远近。

实例 查询「怎么给长书的分页做索引」能命中讲「长文件续读」的段落——两个短语一个词都不重合，但向量方向接近。亲手验证嵌入没被改坏：GOLDMINE_LIVE=1 python3 -m pytest -q tests/test_reference_vectors.py tests/test_reference_media_vectors.py → 应见 2 passed, 2 skipped（逐位相同）。

余弦相似度

Cosine Similarity

定义 两个向量夹角的余弦，等于点积除以模长之积（本项目向量已归一化，点积即余弦）。值域 [0,1]，1 = 方向完全一致。选它而非欧氏距离：文本长短只改变向量长度（幅度），方向才编码含义。这是向量检索的标准比较法——从学术 IR 到工业 ANN 索引通吃。

大白话 两支手电筒从同一点照出去：照向同一个东西，光柱方向几乎重合；照向不同的东西，光柱张开一个角。余弦就是量这个张角——零度得满分 1，九十度得 0。光柱本身多长（文章多长）不重要。

实例 z 分数手算锚点的起点：26 个向量行，1 个目标行余弦 = 1、其余 25 行 = 0（见 z-score 条目，最终 z = √(26−1) = 5）。goldmine search 加 --why 会把每个命中的余弦与 z 分解打印出来。

z 分数

z-score

定义 z = (单个余弦 − 均值) / 标准差。原始余弦没有绝对意义——同一模型对不同查询的分数分布完全不同（A 查询全体 0.8，B 查询全体 0.3），标准化后「出众程度」才可跨查询、跨模态比较。这是统计学最老牌的标准化手法在检索里的应用；准入门槛建在 z 上而非余弦上，正因为 z 随库大小自适应。

大白话 考试 90 分算高吗？要看全班的平均分和分数波动。平均 85、波动 2 分，你的 90 就非常突出；平均 89、波动 5 分，90 分平平无奇。z 分数就是「你比平均分高出几个波动单位」。

实例 手算（测试里钉死）：26 个向量行，1 个目标行余弦 = 1、25 个填充行 = 0。均值 = 1/26，目标偏离 = 25/26，全局 std = 5/26。z = (25/26)/(5/26) = 5 = √(26−1)。通用规律：一行鹤立鸡群时 z ≈ √(n−1)——库越大，同样的领先换来越大的 z。

分模态均值

Per-modality Mean

定义 z 分数的均值按模态分组计算（文本一组、图片一组、音频一组……），但标准差用全库统一。这是被 DigUp 实测教育出的折中：全按模态分组会让窄组（如 PDF 页）被吹爆——同组一个高分除以极小的组内 std，z 虚高，实测 91→94/105 变差，于是退回全局 std。新增模态组行数 <20 时均值不稳，是维护者要盯的点。多模态检索系统做分数标准化时的通用难题：不同模态的分数基线天然不同。

大白话 班级平均分怎么算才公平？把体育特长班和普通班混在一起算一个平均，普通班全显得很差。所以平均分分班算，各班跟各班的均值比；但「分数波动的幅度」用全校同一把尺——尺子也分班的话，小班随便一次起伏都被放大成惊天动地。

实例 一次搜索里文本行均值 0.42、图片行均值 0.31：同一个余弦 0.40 在图片里「高于平均」，在文本里「低于平均」，z 的符号因此不同。DigUp 全按模态分组的实测代价：91→94/105（变差）。

混合融合

Hybrid Fusion

定义 score = 1.0·max(z,0) + 2.0·coverage^1.5（+ 类型命中加 1.0，平坦封顶不叠）。词证权重刻意更重；查询含「字母数字混合带数字」或 ≥4 位纯数字（发票号、工单号）时反转为 (0.5, 4.0)，词法压倒。为什么混合：两条臂各有盲区——纯语义抓不住精确编号，纯词法抓不住同义改写。这是检索领域「hybrid search」的标准命题；融合方式本身也经过实证选择：DigUp 自己的数据里 RRF 融合输给加法融合，故不用 RRF。

大白话 断案同时听两个证人：一个懂「意思」，一个记性好、认得每个编号。平时更信记性好的那个；问到一串编号时，干脆几乎全听他的。

实例 常态权重 (w_m, w_c) = (1.0, 2.0)；查询含 TRX50 或 1234567 这类编号时自动翻转为 (0.5, 4.0)。goldmine search TRX50 --why 逐项打印每个命中的 z、coverage 与最终 score 分解。

查找型反转

定义 检索领域的老洞察：查询分两种意图——「描述型」（找意思相近的）与「查找型」（找精确编号/代号：TRX50、1234567、CVE-2021-44228）。查找型查询里语义向量几乎无信息量（模型不认识编号），词法精确命中才是唯一可靠证据。落地为权重反转：查询里任一词是「字母数字混合含数字」或 ≥4 位纯数字时，(w_m, w_c) 从 (1.0, 2.0) 翻成 (0.5, 4.0)。这是 query understanding 的最小实现：先判意图，再选打分策略。

大白话 问「讲垫片密封的书」和问「编号 TRX50 的主板」是两种问题：前者要懂意思的书，后者要那块板子本身。接待员先听清你问的是哪种，再决定派谁去找——问编号时，记忆型店员一锤定音。

实例 判定规则可跟算：'TRX50' 含字母+数字 → 反转；'gasket' 纯字母 → 不反转；'1234567' 七位纯数字 → 反转。用 goldmine search TRX50 --why 对照 goldmine search 垫片 --why，看权重分解的差异。

BM25 打分原理

BM25 Scoring Theory

定义 BM25 是概率检索框架长出的排名函数，三股力量：IDF（词越稀有越值钱——满篇的「的」不值钱，全书三处的「垫片」值钱）、词频饱和（一个词出现越多越好，但边际收益递减，参数 k1 控制）、长度归一（同样命中密度下短文档占优，参数 b 控制）。它不依赖训练、可解释、快——是倒排索引上几十年不变的默认排名。本项目只用其排名不用其分数：BM25 低 = 好，方向与最终分相反。

大白话 图书馆的排队规矩：你问的词在馆里越少见，找到的那本越金贵；一本书里这词出现得越密越像真讲这个的（但刷屏不算，边际递减）；同样密度下薄书比厚书更像专讲这个词的。

实例 跟算 IDF 的味道：词出现在 1/1000 的文档里比出现在 1/10 的文档里「值钱」约 log(1000/999·10/1) 倍量级。FTS5 内置实现，无需训练数据；--why 里看到的 bm25 排名就是它排的。

池化

Pooling

定义 Transformer 对一段文本的每个位置各输出一个 768 维向量；池化把它们合成单向量，本项目用 MEAN（取平均）。「一段文字一个向量」才好建索引。其他流派：CLS（取特殊首位置的向量）、LAST（取末位置）。池化方式是指纹的规范字段之一——换 MEAN/CLS/LAST 等于换向量家族，旧库会被指纹门拒绝。这是所有句向量模型的共同工序，各家方言不同。

大白话 一篇文章每个段落各打一次分，但索引里一格只能放一个分数——于是取平均。怎么合并是「方言」的一部分：换个合并规矩，所有向量全变了味，必须全部重算。

实例 embeddinggemma-2 + MEAN 池化写进指纹八字段之一（pooling 字段，llama-server --pooling mean）。把 MEAN 改成 CLS 会改变每个存量向量的取值 ⇒ 指纹变 ⇒ search 拒绝服务 exit 3，直到重建索引。

共享嵌入空间

Shared Embedding Space

定义 多模态表示学习的核心方法：训练一个投影头，把图片/音频编码器的输出映射进文本嵌入的同一空间，使「一张猫的照片」与「猫」这个词可直接比夹角。与之相对的是双塔分离空间（各自编码、靠对比损失对齐）或跨空间检索映射。本项目的实例是 mmproj：图片/音频向量与文本向量同为 768 维、同受一套 z 与准入规则管辖——多模态检索才不需要「每模态一套算法」。

大白话 让所有材料说同一种坐标语言：文字、图片、声音都登记在同一张巨幅地图上。只有这样，「用文字问、拿图片答」才可能——问的人和答的人在同一张地图上找对方。

实例 goldmine search 'a cat on a keyboard' 能命中猫趴键盘的照片：查询文字向量与照片向量在同一 768 维空间里夹角很小。验证：GOLDMINE_LIVE=1 python3 -m pytest -q tests/test_reference_media_vectors.py（媒体向量与文本向量同一合同）。

模型量化

Model Quantization

定义 把模型权重从浮点压到低位整数的方法族：Q8_0（8 位对称分组）、Q5_0、Q4 等。原理：权重数值分布集中，低位整数十缩放因子足够表达；组内共享缩放因子摊薄误差。收益是空间减半以上、推理快数倍；代价是精度损失随位宽下降而可测上升——所以有「Q8_0 够好、Q4 危险、F16 反而溢出」这种实测边界。同一思想也用在存储侧（fp16 向量）与像素侧（定点缩放）：本质都是「用有限格点近似连续值，并实测钉住边界」。

大白话 行李装箱法：衣服真空压缩（Q8）省一半空间；压得太狠（Q4）西装就皱得不能穿了。奇怪的是有个行李箱（F16）看着更高级，装这个牌子的衣服反而会撑破——实测过，不猜。

实例 本项目的三处量化跟算：权重 Q8_0（1.5GB→800MB）、whisper Q5_0、向量存储 fp16（1536 字节/条）。每处都有一条实测边界（F16 禁令/Q4 警戒/排序无影响）写进文档。

s@5 / MRR / nDCG

s@5 / MRR / nDCG

定义 s@5 = 前 5 条里有没有正确答案（0/1）；MRR = 正确答案排名的倒数（第 1 名 1.0、第 3 名约 0.33）；nDCG@10 = 前 10 条带位置折扣的综合分。三者互补：s@5 看「捞没捞到」，MRR 看「排多前」，nDCG 看「整个榜单的质量分布」。另有 zero-hit honesty 尺量噪音查询是否正确返回零。选尺即选价值观：本项目的门用 s@5/MRR 主尺 + 诚实度辅尺。

大白话 找东西的三种打分法：一、前五个结果里有没有对的（及格/不及格）；二、对的排第几（越靠前越好）；三、整个榜单排得像不像话（好东西越靠前越好）。

实例 z_gate 2.0→3.0 的 A/B 用这些尺记录：s@5 0.747→0.781、MRR 0.646→0.665（n=146 真模型评测）。自己跑回归门：python3 scripts/eval_real.py --suite legacy --backend llama --gate → 结尾 gate: green 且各指标 delta 全 +0.0000。

显著性检验

Significance Testing

定义 判断「新旧分数之差是真改进还是噪声」的统计检验。McNemar 只看一增一失的题（两边都对的题不提供信息）；成对 bootstrap 反复重抽样本算差的置信区间。结论形如「p=1.0 / CI 含 0」= 没证据说是真变化。数学根据：128 题的样本里一题摆动就是 0.8%——不检验就会把噪声当成果，这是「不做质量重试」纪律的来源。

大白话 两个学生考试差 2 分，能说谁更厉害吗？先只看「甲对乙错」和「甲错乙对」的题——两人都对的题不算数。再看班里的正常波动：分差小于波动幅度，就老老实实说「分不出高下」。

实例 digup-plan-001 的 A/B 零改善即按预注册判负回滚，而不是「再试试别的参数」。128 题套件上任何 ±0.8% 的摆动都要先过统计检验再谈采纳。

留出集

Holdout

定义 题库分两半：train 用来调参，holdout 封存只在最后验收打开。只用 train 调出的「改进」可能只是背题（过拟合）；holdout 是防背题的考卷。这是机器学习的通用方法（train/validation/test 划分）在检索评测里的最小实现。本项目 holdout 密封（有 freeze 测试守卫），任何 reports 外的 holdout 路径不碰；校准纪律要求 train 与 holdout 一致才算数。

大白话 复习题和考试卷分开印。天天对着考试卷练，成绩再高也是背题。平时只许看复习题，考试卷锁在柜子里，最后真刀真枪才算数。

实例 z_gate=3.0 的采纳依据之一是「train 和 holdout 一致」；3.5 虽在 train 更好（0.822）但只扫了一次，不敢信。守卫测试：python3 -m pytest -q tests/test_joint_holdout.py tests/test_joint_holdout_freeze.py。

回归门思想

Regression Gate

定义 回归门 = CI 式的重跑与冻结基线对表、超阈值即红的机制。思想内核：改动的影响不由作者声称，而由「重跑同一套题、对比同一把尺」暴露。配套纪律：基线必须冻结（否则没有稳定的比较锚）；语料或身份漂移要响亮作废基线（corpus_version + corpus_sha），而不是静默换分母；基线重生的唯一通道是审计门。这是从 CI 回归测试到评测门共用的工程方法。

大白话 体测成绩贴在墙上不许改：每次训练完重新测一遍，跟墙上的数字比——退步了墙上就亮红字。哪天换了体测项目（语料变了），墙上旧成绩立即作废重贴，绝不拿「跳绳时代的成绩」跟「跑步时代」比。

实例 python3 scripts/eval_real.py --suite legacy --backend llama --gate：与冻结基线逐指标对比，结尾 gate: green 或红。双 gate（legacy 109 题 + 全媒体套件）都过才算不回归。

科学预注册

Scientific Preregistration

定义 预注册源自临床试验与心理学可重复性危机：试验开始前把假设、方法、分析计划、通过判据登记在案（如 OSF 注册），防「事后挑好看的结论」（HARKing、p-hacking）。动机：数据一到手，人的诚实就开始打折——先承诺再动手是对自己诚实的制度化。工程里对应「结构性改动前冻结设计与判据」；两者共享同一条根：判据先于证据冻结，事后解释必须让位于事前承诺。

大白话 赌局开始前把「算谁赢」写在公证处，而不是看完成绩再定规则。临床试验几十年血泪：先看数据再定标准的研究，结论总能「变好」——所以规矩改成先押注后开奖。

实例 心理学界的标志性案例：预注册与不预注册的同类研究，效应量系统性差一截（许多 p<0.05 的结果复现失败）——这就是 goldmine 把「判负即回滚」写进流程的方法源头。

键序规范化

Canonical JSON

定义 把 JSON 的键递归排序、去掉无关空白后序列化为确定字节串再哈希。这样 {"a":1,"b":2} 与 {"b":2,"a":1} 得到同一身份——语义相同的配置不该因为序列化顺序的巧合而分裂向量家族。这是分布式系统与密码工程的通用手法（canonical serialization）：凡「要被哈希/签名的结构化数据」，先定义其规范形，再谈身份。tests/test_fingerprints.py 的 test_id_stable_across_key_order 钉死这条性质。

大白话 两张购物清单，一张按拼音排、一张随手写，买的东西一模一样就该算同一张单子。先统一按字母排序再比对，顺序就再也搅不了局。

实例 goldmine/fingerprints.py 的 canonical()：keys=sorted + 无空白 separators，产出字节串供 sha256。测试 test_id_stable_across_key_order 明确验证键序不同 → 指纹相同。

分支模型

Branching Model

定义 版本控制的分支方法：每条工作线在自己的分支上提交，主线只经评审/验收合入。价值有二：并行工作互不踩踏（写者隔离）；变更以「可评审的单元」进入主线（合并即评审点）。本项目的实例化：一会话一分支 + 合并经用户 + stash A/B 归因。方法源头从 CVS 年代到 git flow/trunk-based 演化多年，共识始终是「隔离线 + 受控合入」。

大白话 装修队各占一面墙刷，刷完请房东挨面验收再算「完工」。谁的活儿谁认领：出问题先看是谁的墙，不会一笔糊涂账。

实例 撞车事件的归因实验就是分支方法的应用：git stash 掉对方改动 → 重跑测试 → 全绿即归因成立——隔离线让「谁的改动导致失败」变成可实验的问题。

同行评审方法

Peer Review Method

定义 科学界的质量机制：独立于作者的评审人专职攻击稿件（找反例、验主张、查统计），裁决接受/修改/拒绝。要点有三：独立性（评审人不与作者共谋）、对抗性（职责是找错不是捧场）、结构化裁决（有限选项，不许客套话）。本项目的实例化是对抗评审（另一个 AI 上下文，ADOPT/ADOPT-WITH-CHANGES/REJECT）与「合并经用户」；方法上的共同点：把「自查」升级为「异查」。

大白话 论文投出去不是让朋友夸，是请三位陌生专家专门找茬：数据撑得起结论吗？有没有反例？统计过关吗？他们的职责就是让错误活不过投稿这一关。

实例 本项目的两次关键拦截（21 个离线测试、版本字面量漂移）都是「异查」抓到「自查」漏掉的问题——评审者的独立性比聪明更重要。

分块

Chunking

定义 块是检索的原子：嵌入按块算、命中按块报、证据窗按块选、邻块展开按块邻接。约 450 token（一段半）是「指路」与「自含」的折中。分块规则进指纹/身份体系：chunker 变更使存量行 chunker_stale，下次摄取重切。块切得不好（答案跨块）由邻块展开与证据窗仲裁兜底。

大白话 书撕成页，页撕成段——每段约一段半正文。答案恰好被切在两段之间是常态，所以才有「带前后邻居」的补救。

实例 render 输出里每条命中的位置标记就是块坐标；--context 1 直接演示块邻接。

固定分母

The Fixed Denominator

定义 评测口径的诚实条款：某次请求失败/超时/解析失败，不能把它从分母里拿掉——它计入固定分母并贡献零分，产出「下界」聚合。对比框架里未知 URI 的命中同样计入分母并判零。反口径（只算成功的）是评测界最常见的自欺：分数随事故率波动而不是随质量波动。

大白话 缺考按零分算，不许「缺席的不算」。分数才有下限的意义。

成对 bootstrap

Paired Bootstrap

定义 与 McNemar 并用的显著性机器：对每道题的指标差值做 bootstrap 重抽样，得到差值置信区间。选成对设计是因为题目难度方差远大于改动效应——不配对的话信号全被「有的题本来就难」淹没。判定纪律：区间含零 = 不可采纳也不可宣称退化；这是回归门的两台裁判之一。

大白话 同一批学生前后两次考试，只看每人涨了多少分，再随机重排无数次看「纯靠运气能不能涨这么多」。运气解释不了才许说有效。

实例 回归门的输出里每项指标带区间；「区间含零」在 FEATURE_STATUS 的 current005 对照里逐项可见。

幂等与续跑

Idempotency & Resume

定义 幂等是摄取管线的设计性质：内容 sha256 跳过使「重跑」几乎零成本（没变的文件直接略过）；一文件一事务使中断最坏丢一个文件的这一次；watch crash-only 设计实测 SIGKILL 重启零重复工作。幂等的价值是把「失败」从需要善后的事故降级为「再跑一遍就行」的普通事件——这是敢自动重试、敢断电续跑的底气。

大白话 断电重开后接着干、绝不重做已完成的活——这不是运气，是「做过的活有收条、收条在就跳过」的设计。

实例 ingest 大目录中途 Ctrl-C 再重跑：第二遍日志里绝大多数文件是 skipped。

向量与坐标

Vectors & Coordinates

定义 向量 = 一组有序的数（分量），可看作高维空间里从原点出发的一个箭头：2 个分量是平面，3 个是房间，768 个只是继续加轴。两个箭头可以相加、相减、数乘，更重要的可以量夹角与距离——所有向量检索的数学都建立在这几个操作上。「维数高」不神秘：它只是「用很多个数描述一个东西」。

大白话 用几个数说清一个位置：教室里第几排第几列是两个数；城市里经度纬度海拔是三个数。说一个「意思」用了 768 个数——听起来吓人，其实就是把「第几排第几列」问了很多很多遍。

实例 跟算：平面上的点 (3,4) 到原点距离 = √(3²+4²) = 5（勾股定理）。768 维同理，只是把 768 个平方加起来再开方——公式没变，轴变多了。

距离与夹角

Distance vs Angle

定义 比较两个向量的两种基本量：欧氏距离（箭头尖到尖的直线长度，对向量的「大小」敏感）与夹角（两条箭头张开多少度，只看「方向」）。归一化向量上两者等价；未归一化时含义不同——文本嵌入里长度多对应文本长短/信息量，方向才对应含义，所以语义比较选夹角（余弦）。

大白话 两支手电筒：一支大手电一支小手电，都照向同一棵树。论光柱长短（距离）它俩差很远；论照的方向（夹角）它俩一模一样。找「意思相近」的东西，该比方向，不是比亮度。

实例 跟算：向量 (1,0) 与 (2,0)——距离 = 1，夹角 = 0°（余弦 1）。同样的方向、不同的长度：距离变了，夹角没变。这就是「长短不同不影响含义相近」的几何版本。

倒排索引

Inverted Index

定义 正排是「文档 → 它含哪些词」；倒排把它反过来：「词 → 哪些文档含它」。查询时不用扫全部文档，只查查询词对应的那几个 posting list。这是全文检索几十年的地基（Lucene、SQLite FTS5 都是它），BM25 之类的排名函数就跑在 posting list 上。

大白话 书后的索引页就是倒排索引：正文是「第 3 页有哪些词」（正排），索引页反过来「『垫片』出现在第 3、47、102 页」。查词翻索引，不用一页页读全书。

实例 跟算：三篇文档 D1={a,b}、D2={b,c}、D3={a,c}。倒排后 a→{D1,D3}、b→{D1,D2}、c→{D2,D3}。查「b」只碰两个 posting 项，不碰 D3——文档越多省得越多。

均值与标准差

Mean & Standard Deviation

定义 均值 = 所有数相加除以个数（重心）；标准差 = 每个数偏离均值的典型幅度（方差的平方根）。二者合起来回答「这个数在这个群体里正常吗」：高出均值几个标准差就有几个 z。它是从考试分数到实验测量再到音频响度（RMS 是能量版的均值）通用的描述统计底座。

大白话 先算全班平均分，再看大家离平均分平均有多远——前者是「平常什么样」，后者是「波动多大」。知道这两件事，任何一个分数你都能说清它是「正常」还是「离谱」。

实例 跟算：分数 [80, 82, 84, 86, 88]。均值 = 84；每个偏差 [−4,−2,0,2,4]，平方均值 = (16+4+0+4+16)/5 = 8，标准差 = √8 ≈ 2.83。考 90 分 = 高出均值约 2.1 个标准差。

p 值与置信区间

p-values & Confidence Intervals

定义 p 值 =「假如根本没有真实差异，光靠运气看到这么大差异」的概率——p 小说明运气很难解释，不是「差异为真的概率」。置信区间 =「真实差异大概落在哪段」的区间估计；含 0 即「说不好方向」。小样本的残酷算术：128 题里一题翻转就是 0.8%，所以小差异必须先过这两道语言关再谈结论。

大白话 抛硬币连出 5 次正面，能说这硬币偏心吗？先算「好硬币也有多大概率连出 5 次」（这就是 p 值）——三十二分之一，不算稀奇，证据不足。置信区间是另一种说法：「硬币偏心的程度，大概在 −2% 到 +8% 之间，连方向都说不准」。

实例 跟算：好硬币连出 5 次正面的概率 = (1/2)^5 = 1/32 ≈ 0.031。若事先定显著水平 0.05，p=0.031 < 0.05 才算「运气难解释」。注意方向：p 小 ≠ 结论为真，只 = 该怀疑运气。

哈希函数

Hash Function

定义 哈希函数把任意长度输入映射为固定长度摘要，理想性质：确定性（同输入同输出）、雪崩（改一位全变）、抗碰撞（找两个同摘要的输入极难）。两大用途家族：密码学哈希（SHA-256，身份与完整性）与感知哈希（aHash，相似输入得相近摘要——刻意放弃雪崩换相似性）。从 git 的 commit id 到区块链到文件校验，全是它。

大白话 给任意东西盖一个固定大小的章：一颗钻石和一座山，章都一样大。章的规矩很怪但很好用——东西只动一点点，章面就完全认不出；两个东西章面撞在一起，几乎不可能。

实例 跟算雪崩的味道：sha256('hello') = 2cf24d...，sha256('hellp') 完全不同。终端自试：printf hello | shasum -a 256 与 printf hellp | shasum -a 256 对照。

事务

Transaction

定义 事务把一组读写打包成不可分割的单元：提交则全部生效，失败或中断则全部回滚，旁观者永远看不到中间态（ACID 里的 A 与 I）。银行转账是教科书例子：扣款与入账必须同生共死。数据库用它保证崩溃一致性；git 的分支/合并是同一思想在版本控制上的化身（一次合并是一个原子提交）。

大白话 换零钱：把 100 元递出去和收到五个 20 元必须同时发生——递出去一半卡住是最糟糕的。事务就是「这一手要么做完，要么当没发生」，桌上永远不出现半手。

实例 跟算思想实验：转账 = 扣 A 100 + 加 B 100。无事务时第一步后断电 → A 少了 B 没多（钱消失）。有事务时断电 → 两步都当没发生，对账永远平。

定点数

Fixed-point Numbers

定义 定点数用整数 + 约定的缩放因子表示小数：如 22 位定点把 0.5 存成 2097152（0.5×2²¹再取整）。与浮点的区别：定点没有每档不同的指数，算术退化为纯整数运算——在不同 CPU 上结果逐位一致，代价是表示范围与精度固定。凡是「末位差异不可接受」的场合（货币、像素插值、嵌入式）都选它。

大白话 把「元」全换成「分」来记账：从此只算整数，谁算都一样，绝无「四舍五入到你那儿是一位、到我这儿是另一位」的纠纷。代价是数不了特别大或特别小的数——但像素插值用不着。

实例 跟算：22 位定点存 0.5 → 0.5 × 2²¹ = 1048576... 实际按实现取 2²¹ = 2097152 的一半 = 1048576。要点不在具体数：同一公式在同一整数下永远同值——goldmine-embed.c 的 bicubic 靠它逐位钉死。

Unicode 与规范化

Unicode & Normalization

定义 Unicode 给每个字符一个码位（U+0627 是阿拉伯字母 alef）；实际字节流还要经 UTF-8 编码。两个坑与本项目直接相关：①同一文字可有多种码位组合（é 一码位或 e+组合符），规范化（NFC/NFD）负责统一——否则「看起来一样」的词搜不到彼此；②PDF 的文本层靠 ToUnicode 表从字形编号映射回码位，表缺了帖（如阿拉伯 lam-连写），复制出的文字就残缺——这正是丢字病理的根。

大白话 全世界的文字共用一本编号账本：「字 → 几号」。麻烦在同一个字可以记好几笔账（一笔记整体、一笔记两个部件），记账方式不统一，账房先生就查不到对方。PDF 的账本还会缺页——缺的那页上的字，抄出来就缺胳膊少腿。

实例 终端自试：python3 -c "print(len('é'), len('é'))" — 两个看起来一样的 é 长度分别是 1 和 2（组合符），NFC 规范化后才能相等。这正是 normalize_text 存在的理由。

进程与管道

Processes & Pipes

定义 进程 = 一次运行中的程序，有自己的内存与文件描述符；退出码 = 进程结束时给 shell 的一个 0–255 整数（0 惯例为成功；130 = 128+SIGINT）。管道 = 内核里的字节队列，连接两个进程；它有容量上限，写满阻塞、读端关闭后写端得 EPIPE（默认 SIGPIPE 杀进程）。另一关键：语言运行时的用户态缓冲（BufferedReader、stdio 缓冲）会先于内核囤数据——poll 只看得见内核，看不见用户态肚子里的货。

大白话 工厂里的传送带连接两个车间：带子有长度限制（装满就得等），下游下班（读端关闭）后上游再放货就触发警报（EPIPE）。还有个看不见的环节——上游车间内部先有个暂存货架（用户态缓冲），货可能压根没上皮带。每班车结束司机都留一张编号字条（退出码）。

实例 跟算退出码：python3 -c 'import sys; sys.exit(7)'; echo $? → 7。Ctrl-C 一个前台进程 → echo $? 是 130（128 + 信号 2）。管道容量自试：yes | head -1 秒回——head 读一走，yes 的下一次写就撞 EPIPE。

文件系统元数据（inode/stat）

Filesystem Metadata (inode/stat)

定义 文件系统把「文件」拆成两层：inode（编号 + 大小 + 时间戳 + 权限 + 标志位，存在文件系统表里）与目录项（名字 → inode 的指针）。改名/挪目录只改目录项，inode 不变——这是移动检测的地基。stat/lstat 是读取这层信息的系统调用（stat 跟随符号链，lstat 不）；符号链本身是「存路径的小文件」；macOS 还在 st_flags 里放扩展标志（SF_DATALESS = iCloud 占位）。

大白话 每辆车有车架号（inode），车牌（文件名）只是贴上去的一块铁皮：换车牌、挪车位，车架号不动——查车架号就知道是同一辆车。符号链是「写着别人家地址的纸条」；有些车的登记信息里还盖着「本体在云端」的特殊章（st_flags）。

实例 终端自试：mv a.txt b.txt 前后各跑 ls -i a.txt / ls -i b.txt —— inode 编号不变。stat 与 lstat 的差别：对符号链 ln -s 真文件 链接 跑 stat 链接 与 ls -l 链接，一个报真文件、一个报链接本身。

文件描述符

File Descriptors

定义 Unix 进程通过小整数句柄引用打开的东西：0/1/2 固定是标准输入/输出/错误，其余按需分配。边车纪律②（裸 fd + os.read）正是绕开语言运行库的缓冲层、直接对句柄轮询——因为 BufferedReader 的预读会把管道数据吃进自己的缓冲区，level-triggered poll 永远等不到数据就绪。理解 fd 是理解「为什么 poll 醒不来」这类竞态的前提。

大白话 每个进程一沓取号牌：几号牌是键盘、几号是屏幕、几号是管道。牌在数据没到就被人提前揣兜里了，广播（poll）自然永远叫不醒他。

实例 goldmine search | head 的干净退出（无 traceback）依赖对 fd 1 写入失败的显式处理。

信号与 SIGPIPE

Signals & SIGPIPE

定义 信号是操作系统戳进程的机制，SIGPIPE 专管「写进没人读的管道」——默认行为是把进程直接杀掉。goldmine search | head 中 head 先退出后，goldmine 的下一次输出就会触发它；纪律是对已关闭管道的写出吞错（BrokenPipeError 处理 + SIGPIPE ignore + 解释器收尾 flush 探针 + devnull dup2），让「下游走了」成为正常结束而不是崩溃现场（DigUp main.swift:7 同源教训）。

大白话 对着挂断的电话喊话，按默认规则你会被「处决」。goldmine 学会了先看一眼对方还在不在，不在就安静收工。

实例 ANCHORS 之外的最简现场：goldmine search 常见词 | head -1 → 退出码干净、无 traceback。

竞态

Race Conditions

定义 真实案例：早期媒体边车给 stdout 和 stderr 各开一个排空线程，stderr 线程偶尔把协议响应抢先读走——请求永远等不到回包，且是否复现取决于毫秒级时序。四条边车纪律里至少三条是竞态的化石。通用防御：明确每条信道的唯一属主（stdout 归协议、stderr 归排空）、用裸 fd 消灭隐藏缓冲、坏输入丢弃不放大。

大白话 俩人同时守一个信箱，谁先拆信看运气——有时信就被读错了。解法是规矩：一个信箱只许一个人管。

实例 tests/ 的边车协议测试包含「stderr 噪声注入」夹具——把当年踩的坑变成常驻考题。

分位数

Percentiles

定义 把样本从小到大排，第 95 位取 p95。时延用分位数不用平均值，因为用户感受到的是尾部（那次 36.5 秒的查询），不是 200 次快查询的平均。对比报告同时报中位与 p95：中位是典型体验，p95 是糟糕体验的上界承诺。QMD query 臂 p95 36.5s vs goldmine 1.7s 的差距主要就在尾部。

大白话 全班平均身高说明不了最高的门框够不够用——p95 就是「95% 的人不碰头的门框高度」。
