03

对上另一个本地引擎

同 122 份真实文件、同 210 道题，回执公开

78.3% 对 66.1%

直接搜原件的成功@5：PDF、截图、录音不预处理直接扔进去。QMD 原生读不了其中 62 份——它看不见的文件，搜不回来。

1.4s 对 21.8s

每题中位耗时（含模型加载），p95 是 1.7s 对 36.5s——约 15 倍。快不是赌气，是「敢天天用」的前提。

43–60% 对 0%

30 条没有答案的捣乱查询：我们交了一半白卷，QMD 的混合模式一条没敢空过。识别「没有答案」是能力，不是失败。

诚实起见：纯文本精搜 QMD 更强——大家搜同一份预处理好的文字时，它成功@5 100%、我们 91.7%，这是路线图的下一个战场。完整矩阵、失败与岔子、逐行回执：仓库 docs/COMPARISON.md 与 reports/execution/P2-08/。

05

工作原理

从磁盘到可搜，四步

01 · SCOPE

你指定文件夹，只索引这些

没有全盘扫描。构建产物、密钥、iCloud 未下载占位一律跳过并留原因——索引永远不会触发一次 iCloud 下载。

02 · EMBED

内容变向量，每种媒体一条路

文本走钉版 embeddinggemma-2；装上可选边车后：图像/音频向量、视频约每 3 秒一帧、截图走 OCR、录音走 whisper——命中跳到那一秒。

03 · HYBRID SEARCH

含义 + 精确词融合，算术可查

score = 1.0·语义 z 分 + 2.0·词覆盖^1.5 + 类型加成；编号查询自动反转权重。--why 把每条命中的算术摆出来。

04 · ONE FILE

一文件一事务，一库一文件

每个文件的写入是单个 SQLite 事务——中断最坏丢这一个文件的这一次。备份就是复制那一个文件。

quickstart — 零模型也能跑
git clone https://github.com/sixtycat2000-ctrl/goldmine && cd goldmine
python3 -m venv .venv && .venv/bin/python -m pip install .
mkdir -p sample && printf '知识库：退款期限为四十五天。\n' > sample/notes.md
.venv/bin/goldmine ingest sample --db s.sqlite --lexical-only
.venv/bin/goldmine search '退款期限' --db s.sqlite --lexical --pack
