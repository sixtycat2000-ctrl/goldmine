# 第一讲：一条查询的一生 — 搜索打分子系统（search.py + admission.py）

> 轮讲制度的第一讲（2026-10-25）。读完你应该能不看资料回答文末十问。
> 代码主入口：`goldmine/search.py` 的 `Searcher.search/_search`（~980 行）；
> 准入规则在 `goldmine/admission.py`。本文按查询流动顺序讲。

## 0. 一张图

```
查询字符串
  → 清洗（滤掉 kind:/under: 这类过滤词，剩下纯内容词 terms）
  → 两臂并行：
      词法臂：FTS5 全文索引 → 每个文件的 bm25 排名 + 词覆盖率 coverage
      语义臂：查询向量 × 全库向量矩阵 → 余弦 → 分模态 z 分数
  → 准入（admission）：谁能进候选池（z ≥ 3.0 或词覆盖够，见下）
  → A2 过滤：候选里文件已从磁盘删除的剔掉（2026-10-25 新增）
  → 融合打分 + 排序 → 取前 limit 个
  → 每个命中选"证据段落"（primary + supporting）
  → 近重复折叠、«» 高亮 → 输出
```

## 1. 语义臂的数学（本项目最容易被神化的部分，其实很简单）

查询向量 q 和库里每个向量算余弦，得到一堆 [0,1] 的分数。**原始余弦分数
本身没有意义**——模型给不同查询的分数分布完全不同。所以做标准化：

- **按模态分组算均值**（文本一组、图片一组、音频一组……），**但标准差用
  全库统一的**。这是被 DigUp 实测教育过的选择：他们试过每组用自己的
  标准差，结果是"窄组被吹爆、PDF 页被图片埋了"（91→94/105 分变差），
  退回全局 std。
- z = (该文件的余弦 − 该模态均值) / 全局 std。

**手算例**（测试里钉死的）：26 个向量行，1 个目标行余弦=1、25 个填充行=0。
均值 = 1/26，目标偏离 = 25/26，全局 std = √25/26。z = (25/26)/(√25/26)
= **5.0 = √(26−1)**。通用规律：一行鹤立鸡群时 z ≈ √(n−1)。库越大，同样
的绝对优势换来的 z 越大——这是为什么门槛建在 z 上而不是余弦上。

## 2. 准入（admission）——谁能进候选池

**唯一的硬规则：z ≥ 3.0（z_gate）。** 词覆盖足够（coverage ≥ 0.5）的文件
也进。这个 3.0 是 v2.1 校准 A/B 定下的（n=146 真模型评测）：从 2.0 提到
3.0，s@5 0.747→0.781、MRR 0.646→0.665、零命中诚实度 0.4→0.6，train 和
holdout 一致，零单题回归。曾扫到 3.5 更好（0.822）但**故意没采纳**——
一次扫描，过拟合风险，记录在案（不做质量重试的纪律从这来的）。

**见证规则（search.v7）**：一个混合模式查询下的文件，如果只靠 z 分高、
但**一个查询词都不沾**（无 bm25 排名、覆盖为 0）——不准进。防的是语义
模型的"空吸"（embedding 对某些查询天然亲近某些内容）。例外：**纯媒体
文件**（只有图片/音频向量、没有文字可沾的）豁免——它们没资格见证，不能
因此被判死刑。

## 3. 融合打分

```
score = w_m · max(z, 0) + w_c · coverage^1.5 + kind命中加1.0（平坦，封顶，不叠）
```

- 常态权重 (w_m, w_c) = **(1.0, 2.0)**——词证比语义重。
- **查找型查询反转**为 (0.5, 4.0)：任何一个词是"字母数字混合含数字"或
  纯数字 ≥4 位（发票号、工单号这类），词法压倒一切。
- bm25 **只用来排序，永不加进分数**（它低=好，方向和分数相反）。
- 精确命中（引号短语、锚点契约验证过的）在最终排序里**整体提前**，
  按精确等级排。

## 4. A2 已删文件过滤（2026-10-25，批次 A）

候选集确定后、取前 limit **之前**：对文件来源的候选查一次磁盘存在性，
已删的剔掉并计数（`settings.deleted_filtered`，--json 和 MCP 都能看到）。
两个刻意的限定：**URL 行豁免**（网页在不在磁盘没意义）；**只管本索引
真实摄取过的目录范围（roots_json）内的行**——离线测试用假路径建库，
不该被这条规则误伤。发生在 limit 之前 = 前提是"取前 20 条全是活文件"，
预算不因死文件缩水。

## 5. 证据选择——一个命中给你看哪段

每个命中的文件内部再选一次：z 够高时主证据=语义最佳段，否则=关键词
命中段；精确短语命中强制做主证据。还有一条 evidence-window 规则：如果
某段里 200 字符窗口内聚着的查询词 ≥ 比语义最佳段多 2 个不同词，主证据
让位给它（语义模型偶尔被标题党吸走，词证密集处更可信）。supporting
段随行。之后近重复折叠（同文件近似段只展一条）、«» 高亮、渲染输出。

## 6. 诚实契约（这个子系统的"宪法"）

- 零命中就是零命中：打印 `nothing found` + 一步建议，退出码 0，永不硬凑。
- 语义身份不符（指纹变了）→ 拒绝服务 exit 3，绝不混着旧向量答分
  （现场演示见 docs/ANCHORS.md 第 2 条）。
- `--why` 给每个命中的分数分解——每个数字可追问来源。

## 7. 这个子系统的腐烂风险清单（维护者要盯的地方）

1. **z_gate 与权重的再校准**：任何改动必须是 A/B + train/holdout 一致，
   不许"看着调"。历史先例都在 search.py 头注释里。
2. **见证规则的纯媒体豁免**：媒体段型新增（比如以后加视频文本轨）时，
   `_files_with_text` 的口径要跟着审，否则新段型会被误判"无见证"。
3. **A2 的 roots 限定**：离线测试生态依赖"无 roots_json = 不过滤"这个
   约定；动 roots_json 的写入口径时这里要重审。
4. **分模态均值**：新增模态（新 media kind）自动进各自组——组太小
   （<20 行）时均值不稳，注意 zscores 里的小组处理。
