# 第一讲：一条查询的一生 — 搜索打分子系统（search.py + admission.py）

> 轮讲制度的第一讲（2026-10-25）。读完你应该能不看资料回答文末十问。
> 代码主入口：`goldmine/search.py` 的 `Searcher.search/_search`；
> 准入规则在 `goldmine/admission.py`。本文按查询流动顺序讲。

## 0. 一张图

```
查询字符串
  → 清洗（滤掉 kind:/under: 这类过滤词，剩下纯内容词 terms）
  → 两路信号（当前实现先词法、后语义，并非并行任务）：
      词法臂：FTS5 全文索引 → 每个文件的 bm25 排名 + 词覆盖率 coverage
      语义臂：查询向量 × 全库向量矩阵 → 余弦 → 分模态 z 分数
  → 精确文件最大值 → 只为可能准入的文件建立 Python 记录
  → 准入（admission）：语义、词法、完整锚点和名称入口，见下
  → A2 过滤：候选里文件已从磁盘删除的剔掉（2026-10-25 新增）
  → 融合打分 + 排序 → 取前 limit 个
  → 每个命中选"证据段落"（primary + supporting）
  → 近重复折叠、«» 高亮 → 输出
```

## 1. 语义臂的数学（本项目最容易被神化的部分，其实很简单）

几何上，单位查询向量 q 与单位片段向量的点积等于余弦，范围为
**[-1, 1]**。实际存储是 fp16，恢复后没有再次归一化，量化误差可能让点积
略超这个范围。它表示方向的相近程度，不能单独证明来源回答了问题。
代码先在**全部向量行**上计算，再做标准化：

1. 计算原始余弦的全库均值。某模态至少有 20 行时，每行减去该模态均值；
   不足 20 行时减去全库均值，得到 r。
2. 在全部 r 上再次求全库均值与总体标准差。
3. `z_i = (r_i - mean(r)) / max(std(r), 0.02)`。标准差下限防止极窄分布
   把细微差异无限放大。之后才取每个文件的最大 z。

z 是本次查询、当前语料中的标准化反差，**不是相关概率、置信度或 p 值**。
没有正态分布假设，也不能从 z=3 推出“99.7% 相关”。换查询、换语料或换
模态组成都可能改变它。

**手算例**（测试里钉死的）：26 个向量行，1 个目标行余弦=1、25 个填充行=0。
均值 = 1/26，目标偏离 = 25/26，全局 std = √25/26。z = (25/26)/(√25/26)
= **5.0 = √(26−1)**。这里假定同一模态、只有两个分值，且 0.02 下限没有
生效；√(n−1) 只适用于这种构造。增加一般文档不保证 z 上升，更不保证搜索
质量变好。

## 2. 准入（admission）——谁能进候选池

默认 hybrid 有多个入口：经完整余项验证的精确锚点、名称集中命中、词覆盖
达到 0.5，以及满足见证规则的 z ≥ 3.0。词法与 RRF 对照保留各自的词法入口，
纯语义对照只使用语义门。来源过滤、完整锚点和最终组合约束仍须成立。

3.0 是历史 v2.1 校准 A/B 定下的（n=146 真模型评测）：从 2.0 提到
3.0，s@5 0.747→0.781、MRR 0.646→0.665、零命中诚实度 0.4→0.6；源码头
注释记录 train/holdout 方向一致、按标签无回退。这些数字只属于当时快照。
曾扫到 3.5 更好（0.822）但**故意没采纳**——
一次扫描，过拟合风险，记录在案（不做质量重试的纪律从这来的）。

**见证规则（search.v7）**：一个混合模式查询下的文件，如果只靠 z 分高、
但**一个查询词都不沾**（无 bm25 排名、覆盖为 0）——不准进。防的是语义
模型的"空吸"（embedding 对某些查询天然亲近某些内容）。例外：**纯媒体
文件**（只有图片/音频向量、没有文字可沾的）豁免——它们没资格见证，不能
因此被判死刑。

## 3. 融合打分

```
score = w_m · max(z, 0) + w_c · coverage^1.5 + hint
```

- 常态权重 (w_m, w_c) = **(1.0, 2.0)**。实际贡献由 z 和 coverage 共同决定：
  例如 z=4、coverage=0.5 时，两项分别约为 4 与 0.707。
- **查找型查询反转**为 (0.5, 4.0)：任何一个词是"字母数字混合含数字"或
  纯数字 ≥4 位（发票号、工单号这类），减小语义系数、增大词法系数；实际
  贡献仍随输入而变。
- bm25 **只用来排序，永不加进分数**（它低=好，方向和分数相反）。
- hint 取一个：名称集中命中为 2.5，否则类型命中为 1.0，否则为 0；不叠加。
- 精确命中（引号短语、锚点契约验证过的）在最终排序里**整体提前**，
  按精确等级排。
- `--scorer rrf` 仍是可用对照：按各路排名倒数融合。它与默认加权公式是
  不同策略，没有一个在所有语料上自动更好。

## 4. A2 已删文件过滤（2026-10-25，批次 A）

候选集确定后、取前 limit **之前**：对文件来源的候选查一次磁盘存在性，
已删的剔掉并计数（`settings.deleted_filtered`，--json 和 MCP 都能看到）。
两个刻意的限定：**URL 行豁免**（网页在不在磁盘没意义）；**只管本索引
真实摄取过的目录范围（roots_json）内的行**——离线测试用假路径建库，
不该被这条规则误伤。发生在 limit 之前 = 前提是"取前 20 条全是活文件"，
预算不因死文件缩水。

## 5. 证据选择——一个命中给你看哪段

每个命中的文件内部再选一次：z 够高时主证据=语义最佳段，否则=关键词
命中段；精确短语命中强制做主证据。还有一条 evidence-window 规则：如果
某段里 200 字符窗口内聚着的查询词比语义最佳段多至少 2 个不同词，且整段
命中的查询单元数不少于主段，主证据让位给它。若只领先 1 个词，还要求
挑战段语义合格且 z 与主段相差不超过
1.5。pack 请求还可能使用已安装的本地重排器仲裁剩余窗口平局；这与显式
quality 模式的文件重排是两条路径。supporting 段随行，再做折叠、高亮和
预算打包。找到文件、找到证据、让证据装进 pack，是三个不同检查点。

## 6. 诚实契约（这个子系统的"宪法"）

- 零命中就是零命中：打印 `nothing found` + 一步建议，退出码 0，永不硬凑。
- 语义身份不符（指纹变了）→ 拒绝服务 exit 3，绝不混着旧向量答分
  （现场演示见 docs/ANCHORS.md 第 2 条）。
- `--why` 给每个命中的分数分解——每个数字可追问来源。

## 7. 省工为什么不改变数学

令 V 为有向量的文件，Z[f] 为全库标准化后该文件的精确最大 z；L 是词法排名、
coverage、精确锚点与名称入口的文件并集。建立 Python 字典前只保留：

`R = {f in V: Z[f] >= z_gate} union (V intersect L)`。

一个被省掉的文件既没过语义门，也没有其他入口，在原准入函数中必然落选。
保留文件的 z、余弦、首个最大值片段、排名与证据照旧。**全库向量点积、模态
均值和标准差一个没少算**；这不是全局向量 top-K，也不是近似检索。

两个回退不能省：hybrid 的 coverage_quorum=0 会让缺省覆盖率 0 的文件也
入选，因此走完整路径；z 或门槛非有限时也保留原路径。改变数值策略需要
单独评审，不能混进性能优化。

另一个省工来自集合恒等式：正文 posting 集 P 与候选 C 的交集，在 C 为空
时必为空。因此先检查取消/死线，再返回空映射，无须执行 MATCH。候选非空
时仍做原有的词法核验；缺失必需 FTS 表的真实查询仍报错。

亲手预测：一个文件 z=0.8，但有完整精确锚点，应该被筛掉吗？若把全库向量
先裁成最相似的 20 行再求 z，为什么它不再属于这次等价优化？

## 8. 这个子系统的腐烂风险清单（维护者要盯的地方）

1. **z_gate 与权重的再校准**：任何改动必须是 A/B + train/holdout 一致，
   不许"看着调"。历史先例都在 search.py 头注释里。
2. **见证规则的纯媒体豁免**：媒体段型新增（比如以后加视频文本轨）时，
   `_files_with_text` 的口径要跟着审，否则新段型会被误判"无见证"。
3. **A2 的 roots 限定**：离线测试生态依赖"无 roots_json = 不过滤"这个
   约定；动 roots_json 的写入口径时这里要重审。
4. **分模态均值**：新增模态（新 media kind）自动进各自组——组太小
   （<20 行）时均值不稳，注意 zscores 里的小组处理。
