## 0b. Review amendments (2026-10-19, adversarial pass — absorbed BEFORE implementation)

- **F1 (P1) — fetch-deep-then-cut.** D9b's "drop qid==docid hits" is applied **after a deep
  retrieval, not post-hoc**: every query retrieves `limit=20`, the (at most one — see F2)
  self-doc hit is dropped, the list is cut to 10, THEN scored. Rationale: the arguana
  self-doc is byte-identical to its query, so it is a near-certain rank-1 hit on BOTH legs;
  a cut-to-10-then-drop would (a) hand every affected query a 9-hit list and (b) pull
  rank-11 content into the window only for the 69% of the suite where the drop fires —
  a systematic asymmetry vs the published numbers. Fixture assertion included
  (self-doc at rank 1 + relevant doc at raw rank 11 must survive at rank 10).
- **F2 (P2) — one-hit-per-doc invariant, stated.** The drop rule can remove at most one
  hit per query because the Searcher's fusion is file-keyed: `hit.path → docid` is 1:1
  (one .md per doc, D5). The adapter asserts the invariant (duplicate paths → loud error).
  Comparison-table divergence footnotes gain two entries: chunk-fragmented BM25 (docs
  exceeding one chunk — INDEX-MEASURED 2026-10-20 on the shipped chunk.v2-tok
  llama path: scifact 13.0% (672/5,183) / nfcorpus 17.4% (633/3,633) / arguana
  21.9% (1,899/8,674); these SUPERSEDE the review's 2026-10-19 estimator
  figures 18.7/22.1/7.3, which were char-budget-based and badly wrong for
  arguana), so published BM25 ranks whole docs while ours ranks chunks; and
  title-in-header framing (D5) differs from published baselines' title+text concatenation.
- **F3 (P2) — cost math corrected; arguana stays.** The §8 numbers were wrong-class: the
  llama-server is spawned ONCE per run (not per query) and `load_vectors` caches per Store,
  so the warm loop is ≈ 0.02–0.2 s/query and a full hybrid run is ≈ **3–10 min**, not 68.
  §8 now labels every number an ESTIMATE, not a measurement. **Open Question 1 is CLOSED:
  arguana stays in the default suite** (the 47-minute objection evaporated; `--dataset`
  still allows one-dataset days).
- **F4 (P2) — licenses in the manifest.** Each dataset gains a `license` field:
  scifact CC BY 4.0 (corpus) / ODC-By (as applicable per field); nfcorpus **CC BY-NC 4.0**;
  arguana CC BY-NC 4.0 per the BEIR wiki. NC terms REINFORCE D4's cache-only-never-commit
  rule — derived corpora and indexes stay under the local cache root, never in git.
  §3 notes the NC terms explicitly.
- **F5 (P2) — empty-title branch.** arguana is 69% empty titles. The `.md` route SKIPS the
  `# ` header line when the title is empty (the title slot stays the docid slug via the
  pipeline's `title or file-stem` fallback, ingest/commit.py:215) — no invented
  `"Untitled"` noise in the embed framing or FTS. Fixture includes an empty-title doc.
  (Implementation note, stronger than §4 assumed: `extract_markdown` DOES lift a leading
  `# ` heading into `outcome.title`, so titled docs frame as `title: {real title} |
  text: {chunk}` on EVERY chunk, and the header words also land in chunk-1 text + FTS.)
- **F6 (P3) — name-segment footnote.** Our index also has name segments over docid slugs
  (arguana slugs carry topical words, e.g. `paths-training-reasoning-abort-con03a`);
  published BM25 has no such field. Mild apples-oranges, lexical arm only — footnoted.
- **F7 (P3) — mirror recovery.** The UKP URLs are unversioned; upstream drift is handled
  by the sha pin going loud, and recovery is a DELIBERATE manifest edit (same review
  discipline as `model_manifest.py`), re-measured and re-reviewed — never a silent URL
  swap. Noted in the manifest `provenance`.
- **F8 (P3) — determinism + provenance.** The live test runs scifact twice and asserts
  identical 4-dp metrics (determinism is MEASURED there, not assumed). `public_baseline.json`
  gains a `provenance` block recording the llama-server build string (D2 treats build as
  provenance, not fingerprint — the baseline records it for humans, drift does not
  invalidate by itself).
- **F9 (P3) — backend-switch discipline.** Backend-switch forces `--rebuild` (the
  ingest fingerprint gate refuses mixing vectors across embed identities — V2 CRITICAL —
  so a mock-built index is never silently re-scored under llama). Index naming is
  per-dataset: `<root>/beir/<name>/index.sqlite` + `<root>/beir/<name>/.evalhome`
  (D6 layout, restated here because it is now load-bearing).

## 1. Scope and non-goals

- **What**: a neutral external validation of the hybrid retriever — "someone else's exam".
  Per-dataset table {ours-hybrid, ours-BM25, published BM25, delta}, a committed baseline, an
  optional regression gate. One script, ~1 day.
- **What it is NOT**: not the golden gate (`eval_real.py --gate` + the R4 answer gate are
  untouched and remain the only release gates); no changes to `goldmine/search.py` semantics
  (the suite calls `Searcher.search(..., limit=10, scorer=…)` exactly as eval_real does,
  eval_real.py:543); no new Python dependencies (stdlib + numpy only — parquet/ir_datasets
  routes would have broken this; see D3/D4).
- **Dataset network use**: one-time downloads only, cached and sha-verified (D3/D4);
  `--offline` mode never touches the network.
- **CJK**: none exists in BEIR; explicitly deferred to R10b (D12).

Measured facts that shaped the choices (Appendix A has the probe session):

- **The "BEIR graded 0-2 qrels" lore is wrong for this trio's zips**: scifact test qrels are
  binary (rel=1 only — the graded 0-2 mapping belongs to the original SciFact dataset, not
  BEIR's release). Only nfcorpus is genuinely graded (1, 2 — max grade 2, which is why the
  D8 threshold maps the house rule exactly onto nfcorpus and cleanly onto the binary pair).
- **arguana quirks** (all verified in the downloaded bytes): 1,298 of 1,406 query ids are
  corpus ids and their corpus text is byte-identical to the query text (the counter-argument
  task's self-inclusion); 5 qrel positives are missing from corpus.jsonl entirely
  (`test-free-speech-debate-yfsdfkhbwu-con03a→…-con03b` etc.); queries are long (mean 194
  words, max 868). The published 0.397 has a known reproduction spread (Anserini ≈0.3168,
  id-removal sensitivity) — cited, never gated (D10).
- **scifact/nfcorpus queries.jsonl are supersets of the test split**: 1,109 and 3,237 rows;
  only qids with a `qrels/test.tsv` row are evaluated (D9a).
- **Rejected**: climate-fever (BEIR corpus = 5,416,593 docs; zip measured 1,228,666,652 B,
  sha `9d6cf031…` — the 5,416 figure seen in secondary sources is FEVER's doc count);
  fiqa 57,638 docs; trec-covid 171k; touche2020 38k; dbpedia/hotpotqa/fever far larger.
- **R10 synergy, purposes separate**: 2,029 queries vs the house real-146 gives real
  statistical power for future tuning, but R5 delivers only the frozen reference table
  (test splits); any tuning happens on the published train/dev splits, never by iterating
  against the committed test table (D11/D12).

## 4. Ingestion — the .md corpus-dir route (D5/D6)

- Per doc, deterministic byte format (docs sorted by `_id` before writing):
  ```
  # {title}

  {text}
  ```
  filename `<docid>.md` (ids in this trio are `[A-Za-z0-9-]`; the writer asserts the
  charset and percent-escapes anything else rather than improvising). Rationale for the
  `# ` header: the pipeline's embed framing is `title: {file stem} | text: {chunk}`
  (DOCUMENT_PROMPT_TEMPLATE, backends/base.py:21-31; title = file stem, extraction.py:254),
  so the stem alone would embed `title: 4983` — the header puts the real title words into
  chunk 1's text AND into FTS, matching how BEIR baselines index title+text. Accepted
  asymmetry: title boosts chunk 1 only (median docs here are 1.0-1.3 chunks).
- `build_index` pattern copied from build_eval_corpus.py:491-535: `Config(home=str(…/.evalhome))`,
  `IngestPipeline(cfg, store, backend).run([corpus_md_root], code=True)` — no exclude list
  needed (the corpus dir contains only the .md files), no `_patch_walk_file_roots` needed
  (a dir root, not file roots). Chunker = the production `chunk_text_tokens` path
  (pipeline.py:453-455), token budget 450 (chunker.py:23-26, chunker.py:430-438).
- The corpus_md dir + index are derived artifacts, regenerable from the sha-pinned zip:
  a `--rebuild` flag exists; nothing derived is committed.
- Determinism: sorted docid write order, fixed query order (sorted qid), fixed client batch
  (`cfg.batch`, config.py:27 default 16), seeded bootstrap (reuse `BOOTSTRAP_SEED`, eval_real.py:89).
  Metrics are rounded to 4 dp before any comparison. llama-server per-batch float noise is
  accepted as below reporting precision (each sequence is embedded independently; mean-pool
  has no cross-batch interaction).

## 5. Scoring adapter (D7/D8/D9)

New `score_query_public()` in `scripts/eval_public.py` — ~40 lines, **nDCG block is the
verified-identical formula**, then reuses the eval_real machinery by emitting
eval_real-shaped rows:

- nDCG@10: `Σ gain_i / log2(i+2)` over the top-10, linear gain (= qrel grade; trec_eval
  default `gain = (double) i`, gain_init.c — VERIFIED from source; identical to
  eval_real.py:291-299, whose comment already says "linear gain, log2(i+1) discount").
  IDCG from the query's own qrel grades sorted desc, cut 10 — **including dangling qrels**
  (D9c), so the 5 arguana queries cap below 1.0 exactly as trec_eval reports them.
- success@5 / success@1 / MRR: first hit whose qrel grade == dataset max grade
  (manifest `grade_range[1]`); nfcorpus therefore runs the literal house rule
  (grade ≥ 2, eval_real.py:274-280), scifact/arguana run it at grade 1 (D8).
- Pre-scoring hit filter: drop hits whose docid == qid (D9b). Implemented at the adapter,
  never in search.py.
- Hit → docid: strip the `corpus_md/` prefix and `.md` suffix from `hit.path`.
- Rows are `{"query": {"id": qid, "tag": f"public/{dataset}"}, "metrics": {success1,
  success5, rr, ndcg, n_hits, noise: False}, …}` — so `summarize` / `per_query_maps` /
  `bootstrap_ci` / `headline_cis` / `compare_to_baseline` (eval_real.py:311, 783, 434,
  612, 451) run unchanged. `lookup success@1` / `zero-hit honesty` come out "n/a — not
  computable on this run" (BEIR ships no noise queries; that house metric is skipped by
  construction).
- Per-run uncertainty in every headline (F2 discipline): Clopper-Pearson for s@5/s@1,
  seeded percentile bootstrap for MRR/nDCG — free via `headline_cis`.

## 6. Arms and the comparison table (D10)

- **hybrid (ours)**: `searcher.search(q, limit=10, scorer="hybrid")` — untouched semantics
  (z-gate 3.0, near-dup folds, zero-hit honesty). Honest caveat printed with the table:
  BEIR's BM25 always returns 10 ranked hits; our z-gate may return fewer — that sparsity is
  part of what the exam measures, and the delta column must be read with it.
- **lexical (ours-BM25)**: `scorer="lexical"` — SQLite FTS5 `bm25(fts,3.0,1.0)`
  (store.py:7-8, store.py:172; search.py:272-273). Unicode61 tokenizer, no stemming —
  it is our keyword leg, not a tuned BM25; the published column exists precisely so that
  gap is visible.
- Table (per dataset, one row per arm + a published reference row and a delta row):
  nDCG@10 / success@5 / success@1 / MRR with 95% CIs, n queries; published BM25 cells
  carry their source tags (`paper` / `2CR` / `anserini`); delta = ours-hybrid − best cited
  published BM25, footnoted as cross-implementation context (D10).
- Reference numbers (committed in the manifest, sources in Appendix B): scifact 0.665
  (paper); nfcorpus 0.318 (paper) / 0.322 (2CR flat) / 0.325 (2CR MF); arguana 0.397
  (paper, = 2CR flat) / 0.414 (2CR MF) / ≈0.3168 (Anserini-class repro, id-removal
  sensitivity). No published BEIR nDCG@10 exists for EmbeddingGemma-2; MTEB aggregates are
  not dataset-comparable → the reference column is BM25-only (D10).

## 7. Baseline + advisory gate (D11)

- `evals/public_baseline.json` (committed) — schema modeled on baseline.json (eval_real.py:909-937):
  `schema, date, backend, arms, datasets{name → {zip sha256, n_queries, metrics per arm,
  per_query per arm}}, identities{fingerprint_fields(), CHUNKER_VERSION, manifest shas}, gate:{…}`.
  Any identity/sha mismatch on `--gate` → exit 2 loudly (never compare across identities —
  the eval_real.py:953-978 discipline).
- `--gate` runs `compare_to_baseline` per dataset+arm with the house rule
  (drop > 0.02 AND McNemar p<0.05 for count metrics / paired-bootstrap CI for MRR-nDCG)
  and exits 1 on trip. **Advisory v1**: not wired to any cron/CI or release flow, and it
  can never block the product gates. It exists so that when R10 starts tuning against
  train/dev, test-side movement is already being watched.

Wall-clock honesty (F3: ESTIMATES, not measurements — the live run records the real
numbers): corpus embed one-time ≈ 20.8k chunks / 16-18 texts/s ≈ **17-21 min** for all

dataset. Per-dataset index naming + backend-switch-forces-`--rebuild`: see §0b F9.
