# Goldmine P0 P1 P2 执行计划

这套计划覆盖 2026 年 10 月 21 日评估中提出的全部 P0–P2 优化，供执行 agent 逐项实现。起点为 `7694837`，包版本 `0.2.0`。用户现已授权完整实施。2026-10-21.2 版先完成三路专业角色对抗审查，处理记录见 [REVIEW.md](REVIEW.md)；任务状态以 tasks.json 与原始证据为准。文中的新增接口在实际通过对应检查前仍不代表已交付。

产品目标固定为：**在用户明确添加的资料范围内，提供本地、可追溯、可解释、可按预算交给 Agent 的检索材料。** 不增加聊天产品、云端推理、账号、埋点、全盘扫描或企业权限平台。

## 阅读与执行顺序

1. 完整阅读 [执行合同](CONTRACTS.md)，再阅读当前阶段的任务文件。
2. 按下面的任务表和 `depends_on` 顺序执行；依赖关系的机器可读副本为 [tasks.json](tasks.json)。
3. 同一执行 agent 每次只领取一个任务；并行 agent 必须明确文件所有权，由协调者整合。先记录任务前状态，再实现、局部验证、提交证据，最后更新任务状态。
4. 统一验收和拒收规则见 [ACCEPTANCE.md](ACCEPTANCE.md)。缺少真实模型、语料或评分结果时，不得用 mock、skip、历史结果代替。
5. 给下一位 agent 的完整入口提示词见 [AGENT_PROMPT.md](AGENT_PROMPT.md)。

任务详细说明分为 [P0 评测](P0.md)、[P1 检索与 Agent 接入](P1.md)、[P2 工程与交付](P2.md)。只有本文件及这些关联文件组成执行规格；旧路线图中的 SAVED/DONE 标签不能覆盖这里的验收要求。

## 当前事实与新目标

历史证据固定在 [baseline-20261021.json](baseline-20261021.json)。其中：995 项离线测试通过；冻结检索集有 145 道可答题和 5 道无答案题，Top-5 为 0.7862；纳入 19 道媒体题后的 Top-5 为 0.7744，分母 164。常驻 p50 121.3ms、冷启动 p50 1021.3ms 来自 22 次独立进程调用，测试固定了模型驻留。

当前 llama 后端明确报告 `image=False`、`audio=False`：音频通过 ASR 转为文本，截图通过 OCR 转为文本，普通照片主要依赖名称和元数据。不得把 EmbeddingGemma 模型本身的潜在多模态能力当成当前调用端点已实现的能力。

`evals/answer_baseline.json` 的历史均分 1.875/2 可以作为记录保留，但其校准无效：文本 SHA 差异被用于估计答题波动，记录的 `measured_no_change_trip_p=1.0` 不满足 0.05 目标。P0 修复后，不能直接宣布这份历史门禁有效。

所有新验收目标统一定义在 CONTRACTS.md。它们是工程交付要求，不是对现有能力的描述，也不是可以通过重新生成基线绕过的指标。

## 阶段里程碑

| 里程碑 | 满足条件 | 不允许的替代 |
|---|---|---|
| M0 评测可用 | 六个 P0 全部 VERIFIED；旧数据已归档；新实际幅度门禁和稳定性诊断有效（无证据时明确 uncalibrated）；新数据分母与身份完整 | 把旧的答题门禁继续标绿 |
| M1 检索质量 | P1-01 至 P1-06 通过，满足 CONTRACTS 的 dev 快速检索质量门槛，最终发布质量另经一次联合 holdout 审计 | 只增加易题、去掉难题、直接套 z=3.5 |
| M2 Agent 接入 | P1-07 至 P1-10 通过；重排实验有通过或拒绝结论；MCP 和 pack 协议完整 | 用 shell 文本解析包装假 MCP；伪造重排收益 |
| M3 本地可交付 | P2-01 至 P2-07 通过，local_rc 原始检查退出 0；随后派生任务状态 | pytest 全 skip、源码目录掩盖漏打包 |
| M4 竞争判断可复核 | P2-08 对照数据完整；未支持的能力明确分开 | 把转换后检索结果冒充原生多格式能力 |

不能达到目标时保留候选、失败样例与测量结果，状态为 BLOCKED 或 EXPERIMENT_REJECTED；不得降低阈值、重写参考结果或删题使里程碑通过。

## 预计工作量与切分

按单个熟悉 Python 的工程师估计：P0 约 6–10 个工作日；P1 约 14–23 个工作日；P2 约 8–13 个工作日。语料标注、评分模型运行、安装环境和质量达标时间另计。这是排期估计，不是验收依据。

每个 ID 默认一个可审阅变更；较大的任务可拆为 `ID-a` 实现、`ID-b` 测试/实测，但父任务的范围和验收不变。数据库迁移、排序行为改变与纯结构调整分别提交，便于定位和回滚。本轮已获本地实施授权，允许本地分支和检查点；不自动推送、发 PR、发布包或设置自动化。
