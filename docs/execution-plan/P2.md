# Goldmine P2 工程与交付任务

先读 [执行合同](CONTRACTS.md)。P2 收敛维护、规模、安装和对照证据；不以“优化架构”为理由重写已经通过验收的搜索算法。

## P2 01

**拆分 CLI 并收敛模块依赖。** 依赖：P1-01。主文件：`goldmine/cli.py`、`parser.py`、`render.py`、`output.py`、`application.py`、`pyproject.toml`；新增 `goldmine/commands/` 与 `tests/test_module_boundaries.py`。

执行步骤：

1. 在改前保存每个现有子命令的 help、代表性人类/JSON 输出、exit code 和副作用清单；包括 ingest/search/status/model/distill/doctor/backup/reset/open/init/help/serve/watch，以及新增 mcp/reindex。
2. 命令模块按功能分组为 search、ingest、inspection、models、distill、maintenance、lifecycle；每组只包含相关 adapter。共享参数在 parser，通用错误转换在独立命令支持模块；具体检索留 application/Searcher。
3. cli.py 最终只保留 main/dispatch/向后兼容 re-export，目标≤350 非空非注释行。单个 command handler 目标≤120 行，超出时按解析/执行/渲染拆函数；不得为了过行数制造无意义的一行包装器。
4. 保留当前测试和外部代码使用的 `goldmine.cli` import 名；包发现改为显式覆盖新子包或 setuptools find，必须在 wheel 内验证实际模块存在。
5. 依赖方向固定：CLI/MCP adapters→application→search/pack/store/backend；核心模块不 import CLI 或 MCP，不通过全局对象共享 Store。commands 之间不能互相 import。
6. distill 的算法、持久化和渲染若仍混杂，仅在有清晰边界时拆到 `distill_render.py`/`distill_state.py`；不改变 τ、聚类成员或摘录内容。serve/watch 生命周期保持现有归属，不为统一而造通用 daemon 框架。

验收：所有原 nodeid 保留；改前/后固定输入结果、退出码、声明的文件写入一致；新模块能从已安装 wheel 导入；AST/import 图无环且核心不依赖 adapter。全量离线测试、MCP 协议测试、真实 retrieval gate 通过，热搜索 p50 不因拆包增加>20%。不要求靠新增大量镜像测试提高测试数量。

交付：模块地图、改前/后对照、兼容 re-export 列表。纯结构提交不能同时包含参数调优、重新建基线或更换模型。

## P2 02

**建立规模与内存基准，只在触发条件满足时扩容。** 依赖：P1-01。主文件：`scripts/bench.py`、`goldmine/store.py`、`search.py`；新增 `scripts/bench_scale.py`、`tests/test_scale_bench.py`。

执行步骤：

1. 固定 seed=20261021、768 维、fp16 持久化、每文件 1/10/100 段三种分布，生成 10k/100k/250k/500k 向量库。随机向量按固定大小分块以float32生成、L2 normalize后转fp16流式写入；禁止一次创建500k×768的默认float64大矩阵。ID、模态和文件映射随fixture保存；禁止全零或重复向量伪造扫描速度。生成进程退出后才启动测量进程。
2. 分开测：进程/导入、SQLite 冷载向量、同 Store 热缓存、cosine、模态 z、文件聚合、准入/排序、详情/pack、完整 CLI。warm-up 3 次，计量≥10 次；完整 CLI 至少 30 次。
3. 每个规模×分布×参考/候选臂使用全新测量进程；在同Store内测热缓存，另启进程测冷加载。不要通过清系统cache或杀其他应用制造所谓冷盘。记录缓存定义、内存压力、模型驻留状态、系统信息和磁盘大小。分别记录fixture构建峰值、查询进程峰值、模型子进程峰值，RSS统一为bytes并保留平台原始单位（Darwin ru_maxrss为bytes、Linux为KiB）；不能把同进程累积高水位当作当前臂峰值。
4. 参考与候选在相同fixture/主机按相同query交错轮换运行，校验top-k和分数误差（绝对误差≤1e-5，平分使用稳定ID）；特别覆盖“一个文件许多高分段挤占其他文件”的分布。完整CLI参考/候选各至少30次，warm/cold各至少30次；计入全部有效尝试及失败/降级，按ACCEPTANCE统一nearest-rank算法算分位数，不能先跑完全部参考再跑全部候选。
5. 不触发扩容时保留 SQLite+numpy，并输出容量建议。只有真实库≥250k，或该规模实测 cold-load p50>500ms/峰值RSS>1.5GiB，才进入已有 C3 向量 pack 方案的实现；不能因 synthetic 10k 快/慢就引入 ANN。
6. 若触发，向量 pack 只能是 SQLite 的可重建派生缓存：事务内维护 vector_epoch；构建使用一致读快照；临时完整写入后 fsync/原子发布 manifest；指纹/epoch/长度不一致或文件缺失直接回退 SQLite。SQLite 永远是真值，不维护两套独立索引。
7. pack 的并发/崩溃用例：写到一半 SIGKILL、写后发布前 SIGKILL、构建期间 ingest、旧 reader 仍持有 mmap、磁盘不足、损坏 header。不能让 reader 得到跨 generation 的 IDs 和向量。

验收：

- [ ] 四个规模和三种分布都有分阶段时间/RSS/磁盘数据，复现命令和 fixture SHA 齐全。
- [ ] 生成内存受分块大小限制；同一测量进程不能承载多个规模或参考/候选臂；报告能证明生成高水位没有污染查询峰值。
- [ ] 现有 `python3 scripts/bench.py --gate` 通过；不能修改原预算使之通过。
- [ ] 新优化在参考小库不破坏 fast 门槛；100k/250k 相同结果一致。
- [ ] 若实现 pack，在触发规模 cold-load p50 至少改善30%，峰值RSS至少减少30%；否则拒绝默认使用并保留对照。
- [ ] 跨进程 ingest 后首次查询正确失效，后续热查询确实命中缓存；无 stale-hit 或 lost-hit。

新增 ANN、向量数据库、常驻搜索状态和任意 schema 重构都不属于本任务。未触发缓存实现条件时，VERIFIED 的交付就是基准工具与有数据支持的维持现状结论。

## P2 03

**降低增量导入与 watch 空转成本。** 依赖：P2-02。主文件：`ingest/pipeline.py`、`ingest/commit.py`、`watch.py`、`serve.py`、`doctor.py`；相关现有测试加定点故障用例，不新建队列系统。

执行步骤：

1. 增加可关闭的运行计数：scan_ms、hash_ms、extract_ms、embed_ms、commit_ms、files_skipped、实际模型 spawn、OCR/ASR 调用。仪表不改变默认 stdout；详细数据通过 JSON/报告输出。
2. 对“首次导入→完全不变→修改1个→删除1个→失败恢复”建立对照。未变文件不做 OCR/ASR/embed，修改文件只替换该文件段，失败时旧完整段保持一致或按既有明确状态处理。
3. watch 复用现有 snapshot/hash-skip；修复重复 walk、空 delta pass 和无变更仍建 backend 的实测原因。保留 min_pass_gap、battery gap、scan-duration floor、defer/heartbeat/backoff 规则。
4. 对连续编辑、文件 rename、原大小/mtime但内容变化、无权限路径、含毒文件、部分删除做 delta/sweep 一致性验证。不能为了快跳过周期性 hash 自愈。
5. 继续按现有模型分工：watch 每个实际 ingest pass 使用自己的 backend；本任务不加入 serve lease、共享写连接、FSEvents、持久作业队列或 launchd 安装。若冷启动仍主导耗电，只出下一阶段有测量的提案。
6. 保留电源/热/真实内存压力保护：正常测试不固定压力；固定信号的测试单列 controlled。进程清理必须验证 PID 与启动身份，只处理本次测试/服务创建的进程。
7. 升级现有22次latency测试至warm/cold各≥30次的相同query交错测量，保存每次JSON/退出码/时延，实际断言p50及p95合同。controlled residency与不固定压力的真实门控验收分别运行；两者不能复用掩盖压力的环境。MCP额外开销另用同请求配对差值的p95，不能拿独立分位数相减。

验收：全不变重导入的 embed/OCR/ASR 调用=0，SQLite 内容/向量/卡片成员不重复；drop→JSON 真命中≤90s；4s 编辑周期10min的实际 embed spawn≤24（版本探测不计 spawn）；SIGKILL 后重启无重复段/遗留进程；电池/热/内存门控和退避全部按合同运行。

命令：`python3 -m pytest tests/test_pipeline.py tests/test_watch.py tests/test_serve.py tests/test_v2_identity.py -q`；`GOLDMINE_LIVE=1 python3 -m pytest tests/test_live_watch.py tests/test_live_serve.py -q -rP`。真实机器压力导致必要性能用例skip时local_rc返回MISSING，不能伪装为测试通过；旧22样本、无p95断言的报告也不能满足新验收。

## P2 04

**为知识卡片建立真实语料验收。** 依赖：P0-05、P1-01。主文件：`scripts/eval_distill.py`、`goldmine/distill.py`、`tests/test_eval_distill.py`、`tests/test_distill.py`；新增 `evals/distill_real/` 的小型标签与 manifest。

执行步骤：

1. 保留当前 mock hard-variant 门禁，并在所有报告注明 synthetic/mock。0.880 purity、8/8 topic recovery 不能直接称为真实语料质量。
2. 选择 product corpus 中至少 100 篇文档、至少 8 个已冻结主题，每主题≥8篇，另含跨主题与噪声文档；主题标签不进入被索引原文。只用已许可、可搬运内容。
3. 使用真实 llama 向量跑 `--report-real`，记录 τ 来源、分位点、卡片大小分布、最大卡片占比、未聚类比例和运行时间；不要只看校准函数是否返回数字。
4. 对卡片所有摘录，验证逐字来自其指向的存储原文，引用可回读。不同语言、同主题不同措辞、重复文档、被删除成员和旧 citation 都有检查。
5. 按冻结主题计算 purity/coverage，不让本次聚类结果反向决定主题标签。固定抽样20张卡（不足20则全量）审查标题是否有原文依据、来源是否能定位；保存逐卡 verdict。
6. 再加入10篇新文档并做增量 distill，对比全量重算；不得改变 τ 以掩盖差异，继续执行已设计的冻结成员、dissolve 和继承规则。

验收：真实 purity≥0.70、至少找回6/8主题；在这个刻意多主题集最大卡片占比≤0.50；100% 摘录逐字与位置校验通过；增量重聚类量/去重后总量≤10%，变化成员解释完整。无法满足时保留真实报告，任务最多 IMPLEMENTED，不能改用 mock 宣称完成。

分别运行现有 `python3 scripts/eval_distill.py --variant main`、`python3 scripts/eval_distill.py --variant hard`、`python3 scripts/eval_distill.py --variant incremental` 和 `python3 scripts/eval_distill.py --report-real DB`。若需新增真实标签评分开关，使用 `--labels PATH --json`，默认 report-real 不写 DB。保持摘录式卡片，不增加 LLM 标题/总结、图谱或未经测量的聚类算法替换。

## P2 05

**增加普通 PR CI 和严格 live 验收入口。** 依赖：P0-06。新增 `.github/workflows/ci.yml`；修改现有 build-release workflow 时只处理已验证的构建问题；新增可选 `live-validation.yml`，不得自动上传/发布。

执行步骤：

1. PR/push CI至少运行Python 3.12/3.13的macOS arm64与Linux组合，并记录runner实际架构；按当前官方runner标签核验，不能只凭标签注释猜架构。hermetic offline不安装模型/cache/native工具；native job另行安装poppler/ffmpeg等、记录版本。原生macOS能力只在实际macOS job验证；Linux只声称对应可移植子集。
2. 为offline/assets/native/optional-mcp/optional-foresight建立固定marker与collection，维护逐nodeid的平台例外、原因和原nodeid迁移表。系统壁纸改可搬运fixture；真实模型/BEIR哈希检查归assets。importorskip导致模块没收集、集合为空或漏原测试都必须被发现，不能让macOS干净clone被偶然资产阻塞。
3. 分开执行base、MCP、Foresight可选依赖的安装与测试；每个子环境有固定必需nodeid。base环境没有extra也必须help和词法搜索可用，不能在模块import时强制导入extra；缺extra的降级是base要验证的行为，不能让SDK协议测试以skip冒充通过。
4. 增加 wheel 构建、twine check、包版本一致性、从源码目录外导入的 job。缓存按 Python/OS/依赖锁区分，不缓存用户配置、SQLite 或私有语料。
5. live 仅 workflow_dispatch 或已配置且明确启用的参考机器 job；先验证模型/语料/原生工具和必要测试清单。缺任一项必须 nonzero/标记未完成，不能用 pytest skip=0 exit 蒙混。
6. 上传报告作为 CI artifact；不要提交大型日志到仓库，不输出 secrets。不创建自动更新 baseline 的 job，不把公开 BEIR advisory 旧脚本直接当唯一质量门禁。

验收：在分支/本地可复核的 CI 环境里，分别注入一个单元失败、删除一个 wheel 模块、让 live 缺模型、让 collection 为空，四种情况都不能绿。普通正确提交完成各平台声明范围；JSON/JUnit/manifest 可下载且哈希一致。

本项分开记录`local_verification`与`hosted_verification`。若没有remote/runner，保存workflow并用同一脚本完成本地声明范围与失败注入，足以通过local_rc的本地CI检查；hosted_verification仍为MISSING，不能写“CI已在GitHub通过”。hosted_release必须有实际run URL及artifact绑定，缺少时exit2。不得为补hosted证据自行建remote、推送或把Linux/其他Python版本的未实跑结果写成成功。本项实现完成即允许P2-06继续；P2-07/M3的本地证据不依赖hosted完成。

## P2 06

**验证 wheel 和无源码安装流程。** 依赖：P2-05 的实现。主文件：`pyproject.toml`、`scripts/build_llama_tar.sh`、model/init 帮助；新增 `scripts/smoke_install.py`、`tests/test_distribution.py`。

执行步骤：

1. 构建本次run独立目录下的wheel/sdist，在新临时venv安装确切文件；把cwd切到不含源码的临时目录，清除PYTHONPATH/开发editable安装影响，断言`goldmine.__file__`位于该venv site-packages。分别从wheel及sdist构建后安装，运行version/help/search/ingest/status/doctor最小流程；不能只检查源码能import。
2. 所有 HOME 相关产品路径通过 GOLDMINE_HOME/GOLDMINE_CONFIG 指向临时目录；不覆盖 shell 的 HOME，不访问真实 config/models/index，不启动已有用户 daemon。
3. base-only 环境测试“没有模型/服务器/ffmpeg/poppler/OCR/MCP SDK”：词法 ingest/search 正常，其他能力给准确缺依赖提示和退出码。不能因本机 vendor 恰好存在而把 wheel 判为可安装。
4. extra 环境验证 `goldmine mcp` 的完整握手、包内命令子包与文档示例；分别验证缺 SDK、SDK 版本不兼容时的可理解错误。
5. 修复现有native构建脚本的发布假设：固定上游精确revision并核验patch SHA；已有checkout错revision、patch既不能apply也不能reverse-check都必须nonzero，不能警告后继续。每次创建全新staging，禁止夹带旧OCR；架构用`file`/`lipo`实测后决定资产名，版本探测失败不能`|| true`吞掉。用`otool -L`递归收集非系统动态库依赖闭包，选择打包并修复install_name/rpath或可证明的静态链接；不能遗留指向vendor/build或/opt/homebrew的运行时依赖。签名、二进制/库/patch/源码SHA和构建参数进入native manifest。
6. 模型从显式传入的既有文件或已验证模型安装流程获得，检查 SHA；search 不下载模型。无网络安装测试必须不发出请求；下载能力另列联网测试，不伪称离线无需准备模型。
7. v4 用户索引→v5/v6 派生升级、备份、只读旧库提示、旧 citation 失效、未来 schema 拒绝均通过安装后的 CLI 验证。
8. 将native tar提取到全新无源码目录，清除DYLD_LIBRARY_PATH等构建环境覆盖，只用该目录与系统依赖实跑llama-server版本、OCR、固定模型embedding请求；记录实际加载库来源。错revision/未知patch/缺dylib/旧staging污染各有反例，均不能生成成功manifest。测试资产不需要创建release或上传。

验收：`python3 -m build --outdir RUN_DIST`成功，并对该run明确列出的wheel/sdist执行`python3 -m twine check PATH...`，不扫描可能含tar/陈旧包的`dist/*`；smoke_install base与mcp两个profile在源码目录外通过；sdist重建安装通过；native依赖闭包与隔离运行通过；确认wheel含新子包，版本两处一致，默认依赖没有意外增多；三条实际安装/使用示例能逐字执行。

无真实 release URL 时删除占位 project URL 或保留为未配置的清楚状态，不能发请求到虚构仓库；本地 tar 成功不能写成“公开二进制已发布”。平台声明仅覆盖真正运行过的环境，arm64 成功不代表 Intel/Windows。

## P2 08

**建立 QMD 与 Recoll 的可复核公平对照。** 依赖：P2-02、P2-06；主文件：新增 `scripts/compare_search.py`、`evals/comparison/manifest.json`、`docs/COMPARISON.md`、解析器 fixture 测试。使用官方来源：[QMD](https://github.com/tobi/qmd)、[Recoll](https://www.recoll.org/)。

执行步骤：

1. 在隔离目录安装一个可运行的稳定 QMD 版本和 Recoll 版本，记录精确 revision、依赖、模型/配置 SHA、来源 URL、构建命令和硬件。执行前读取所安装版本 help，不猜参数或用网页宣传数字代替运行结果。
2. 建两个独立视图：native 视图使用同份原始多格式资料，记录各自原生支持/失败情况；text-common 视图使用冻结、带来源/页标的统一文本，比较共同检索能力。转换器、输出和模型差异全部记录。
3. QMD 默认/高质量模式和 goldmine fast/quality 分列；Recoll 默认词法与其可运行的可选语义能力分列，不能写“Recoll 不支持语义”。模型不同的系统比较不能解释为单纯算法胜负。
4. 在相同题 ID、同 qrels 和共同支持的过滤条件上测 file-level success@1/5、MRR、nDCG@10。位置级指标只有各方可提供可验证位置时才比较；unsupported 与漏召回分栏，不暗中把困难题从某方分母删除。
5. 日常只看dev；三方参数与接受规则正式冻结后，在一次联合发布审计中运行sealed holdout对照，不使用竞品错误来修改题目。保存每题原始输出、adapter 映射和评分；qmd:// URI/Recoll docid 用预建 manifest 映射到相同 corpus-relative 文件身份。
6. 分别测首次准备耗时、索引磁盘、驻留RSS、冷/热延迟≥30题、增量更新和缺依赖体验；搜索请求无 shell 注入，参数用 argv 数组，限制进程资源并只清理自己的安装/服务。
