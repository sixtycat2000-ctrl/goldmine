## P0 02

**修复答题波动、预登记退步门槛与来源校验。** 依赖：P0-01。主文件：`scripts/eval_answer.py`、`tests/test_eval_answer.py`；评分协议放入聚焦的 `scripts/answer_eval/` 模块，允许新增 `tests/test_answer_calibration.py`，不重写已有材料生成流程。

执行步骤：

1. 建立 schema v3 run manifest，显式区分两轮答案和每轮两次评分；两份答案不是四份独立答案。每份评分验证 question_id、answer_sha256、pack_sha256、grader_prompt_sha256、模型与评分参数。模型身份必须包括本地模型文件 SHA 或可验证的固定模型 revision，不能仅用可变显示名称。
2. 新增纯函数 `compute_score_variance(records)`，根据同题四次有效评分计算 p_score、0..2 得分分布与各轮均分；文本 SHA 差异率独立报告。p_score 的区间也只作稳定性诊断，不是独立题目假设成立或未来误报率受控的证据。不得从 p_score 自动推导 gate threshold。
3. 新增预登记文件并在运行前冻结其 SHA。字段至少为 schema、protocol、questions_sha256、corpus_sha256、source_groups_sha256、answerer/judge 身份与参数、score_scale=[0,2]、practical_drop_threshold、trap_min_rate、bootstrap_unit=source_group、bootstrap_seed、bootstrap_reps、registered_at。退步阈值默认 0.10；允许值仍为 0.10/0.15/0.20/0.25/0.30，必须在查看候选得分前确定。同一比较的两套 run 绑定同一份预登记文件，不能根据候选结果放宽阈值。
4. null audit 为独立可选工作，不是 P0 开发的新增前置条件。没有独立多轮 no-change run 证据时固定记录 `calibration_status=uncalibrated`、`false_positive_bound=null`；完整性检查和预登记工程门槛仍可验收。不得输出 `calibration_valid=true`、实测误报概率0或“误报率<5%”。若另做 null audit，需保存独立完整 run 对、固定阈值、有效样本数、失败次数与一侧区间；阈值选择数据不能充当其独立验证数据。
5. 原 schema v2 仅可读作历史展示；正式 v3 gate/compare 必须拒绝其协议、来源和预登记缺失，不得把旧 baseline 自动升格。错误、缺答案/评分、重复题、空分母、非法值均 exit 2，并保证输出 baseline 未创建或原字节未变。
6. 未来新 baseline 只写 `evals/answer_v3/baseline.json` 或显式指定的全新 v3 输出，保留协议、得分尺度、稳定性诊断、预登记阈值、uncalibrated 状态、各分母和全部输入 SHA。写入需要 `--update-baseline --yes`、有效的80题四组评分和完整来源；历史 `evals/answer_baseline.json` 的字节不得改变。

每份 grade v3 的必填字段固定为：schema、question_id、answer_round(a1/a2)、judge_round(j1/j2)、score(整数0/1/2，bool 不算整数)、refused(bool)、fabricated_fact(bool)、fact_results(按冻结事实ID逐项记录支持/不支持及证据ID)、answer_sha256、pack_sha256、grader_prompt_sha256、judge_model、judge_settings。每份 answer 另带 answer_round、question_id、answerer 身份/参数、answer_sha256、pack_sha256、answerer_prompt_sha256 来源记录。四组记录的 round 与目录必须一致；布尔字段缺失不能默认 false，fact_results 缺事实不能当作全部满足。

必须覆盖的反例：

- 不同措辞/不同 SHA，但四次评分一致 → p_score=0。
- 字节相同，但同题评分不同 → 计入评分波动。
- 得分 2→0 的退步，保留原始0..2尺度，不能缩成单分或“答对率”。
- p_score=0.8105、n=16 的历史记录 → 不符合v3来源和分母要求，不写baseline；p_score=0 也只能记uncalibrated，不能得到零误报结论。
- 60题共享一次答题轮的质量冲击，两轮同分 → 诊断p_score=0但不输出任何<5%的统计保证。
- 预登记默认阈值0.10；阈值非法、两run预登记SHA不同、运行后替换预登记文件 → exit2，不写baseline。
- 一份评分给了另一份答案的 SHA、漏一个 trap、同 ID 重复、评分超出 0..2 → exit 2。
- n=0、NaN/Inf、非法bool得分、缺模型文件身份、缺一个评分 → exit2；任何无效输入不得伪装成零波动。

验收：`python3 -m pytest tests/test_eval_answer.py tests/test_answer_calibration.py -q` 通过；对旧 baseline 执行新校验必须得到 NOT_COMPARABLE。真实数据遵守 CONTRACTS 的60道可答题+20道trap和四组评分；缺真实评分时任务最多 IMPLEMENTED、数据检查为MISSING。独立null audit缺失本身不阻止工程门槛验收，但报告须明确uncalibrated。

交付：新旧schema兼容说明、预登记模板、稳定性诊断样例、反例报告及真实数据缺失项或工程门槛验收结果。禁止把实测不足掩盖为probability=0，禁止扩大阈值候选上限或依候选输出选择阈值。

## P0 03

**让基准版与候选版可以被有效比较。** 依赖：P0-02。主文件：`scripts/eval_answer.py`、`evals/answer_v3/`；新增 `tests/test_answer_compare.py`。本任务保留 pack 来源校验，去掉“只要候选 pack 变化就永远不能比较”的实验障碍。

执行步骤：

1. 一个 run 使用独立目录：`packs/`、`answers_a1/`、`answers_a2/`、`grades_a1_j1/`、`grades_a1_j2/`、`grades_a2_j1/`、`grades_a2_j2/`、`run.json`。答案的伴随来源记录、实际answerer/grader prompt和预登记文件也须可回读并复算SHA；路径必须在该run或显式登记的只读输入内，不能用路径穿越借用另一run内容。
2. 增加 `eval_answer.py --compare BASE_RUN CANDIDATE_RUN --json`。旧 `--gate` 保持验证同一个run的用途；compare正式验收读取两个独立run，不能复用旧答案给新pack打分。只有显式`--diagnostic`允许同run自比以检查delta=0，并必须标`diagnostic_only=true`，不能作为独立两run发布证据。
3. 不变量：question set、source_group映射、源corpus、answerer/judge固定身份及参数、answerer/grader prompt/量表、预登记和消费tokenizer相同。实验变量：排序、chunker、embedding、lexical、reranker、pack参数；它们必须逐项记录并出现在comparison的changes数组。不能把可变模型名称相同当作模型字节相同。
4. candidate pack SHA 可以与 reference 不同，但 candidate 答案必须引用 candidate pack；任一答案/grade 来源错误立即 exit 2。允许 embedding 变化的实验必须为同源 corpus 分别构建两套索引，不混用向量。
5. 每题score为四份原始评分的平均；输出成对score、原始均分差、按冻结source_group整组重采样的95% paired bootstrap CI、陷阱拒答率、退步问题及来源。每次抽与原始组数相同的组，保留被抽组内所有题并重算题均值；不能把组内多个题或四次评分当独立样本。分母固定为完整共同题集，不得自动取交集；报告题数、来源组数、seed、reps及算法版本。少于12个独立来源组时CI仅作诊断，不允许声称显著提升。
6. 对60道可答题+20 trap扩题，保留原20题为legacy-answer；按single/multi/cross各20题组织新套件，并冻结fact_id、事实说明及充分证据原子。每题有source_group；共享原始资料、转换资料或compound共同资料按连通组归并。新的事实不能从候选答案反向提取；题目构建/标签审计与候选答题过程隔离。
7. 比较判定：可答题均分退步严格大于预登记practical_drop_threshold时exit1。trap成功须两份答案各自两评分均值≥1.5、四份评分全部refused=true且fabricated_fact=false；完整20题成功率≥0.90为独立门槛。稳定性诊断uncalibrated不可偷换成MISSING真实评分，也不可冒称统计保证。旧gate若用于校验同run，也必须复验v3来源和预登记，不得继续把旧v2门禁标绿。

验收用例：

- [ ] pack 变化且重新作答/评分、同不变量 → 可比较。
- [ ] pack 变化但答案沿用旧 pack → exit 2。
- [ ] 相同run比自己默认exit2；显式diagnostic模式每题delta=0、均分差=0，且不得标正式PASS或独立比较已完成。
- [ ] 得分差超过预登记工程阈值 → exit1；等于阈值不因浮点误差误拒；trap拒答低于0.90也必须失败。
- [ ] 任一题/协议/模型/源 corpus 缺失或不一致 → exit 2，不能返回 PASS。
- [ ] 输出保留四个原分、所有实验变量、来源组CI、预登记和稳定性诊断状态，不能只留下一个mean。
- [ ] 8组各8题、7组每题delta=+0.5、1组每题delta=-1的反例：按题bootstrap可能下界>0，按来源组CI下界必须覆盖0，不能通过显著提升验收。

命令：`python3 -m pytest tests/test_answer_compare.py tests/test_eval_answer.py -q`；真实比较使用两个独立运行目录执行新 compare 命令。没有真实候选评分数据只能标 IMPLEMENTED；不得调用未获授权的外部消息或云模型来补齐数据。

## P0 05

**建立可搬运且不泄漏答案的产品评测集。** 依赖：P0-04。新增 `evals/product_v4/{manifest.json,queries.jsonl,splits.json,README.md}`、`scripts/build_product_corpus.py`、`scripts/eval_product.py`、`tests/test_product_corpus.py`、`tests/test_eval_product.py`。

执行步骤：

1. 按 CONTRACTS 准备 420 题和来源。使用允许保存的公开片段、项目公开代码/文档、明确的合成行为 canary；主质量集不能全部由固定模板同义改写组成。manifest 逐个注明真实/合成、来源 URL 或 repo revision、SHA、许可证标识、生成方式。
2. corpus 只收被检索的资料，不包含 query/expected/评分文件/生成脚本。fixture builder 和检索入口分目录，索引范围只指 corpus 目录。
3. 先提交机器可验证JSON schema和评分契约，再建题；各层未知键均拒绝。题结构固定为`id,primary_class,tags,q,expect,required_facts,needs,source_group`。expect每项包含唯一evidence_id、corpus-relative path、grade(0..3)、evidence_type、location和精确原文span。location固定为`{unit:page|line|second,start,end}`：页/行从1开始且为整数，秒为非负有限数，start≤end；按kind验证单位，未知键、非法范围与单位不符均exit2。仅name_metadata允许location=null，正文/OCR/ASR不允许缺位置。span固定为`{start_char,end_char,text,sha256}`，使用规范化来源文本中从0开始、左闭右开的Unicode字符偏移；构建器冻结可回读的来源文本视图及其SHA。规范化仅统一换行与NFC，span.text必须等于该视图的对应切片，SHA对其UTF-8字节计算，不能删否定词或折叠正文。禁止`<home>`、`/tmp/gm_covfix`和本机父仓库路径。
4. required_facts每项固定为`{fact_id,description,sufficient_evidence}`，后者为非空二维evidence_id数组；内层是AND、外层是OR。noise的expect/required_facts为空。all_required_facts@pack要求每个事实至少一个alternative中的所有证据span都由实际输出且可回读的citation完整覆盖，校验原文、路径和位置，不能以“文件命中”“位置有交集”或“关键词出现”代替；supporting citations不作为额外搜索排名重复得分。
5. 构建来源关系图，转换副本、近重复资料、同音频转录和compound共同来源合并为source_group，按连通组分割；一个group不跨dev/holdout。若连接成巨大组，增加独立资料，不拆同组。使用固定seed做确定性分组分层，保持420题及合同的每类holdout≥25、media-text每种能力holdout≥8；冻结后不能根据分数重分割。旧train名称仅可为dev的明确兼容别名。
6. 新脚本支持`--prepare`、`--validate`、`--split dev|holdout|all`、`--backend mock|llama`、`--db`、`--json`、`--gate`、`--reference-run`。prepare只在显式调用时建库；validate不启动模型；mock只验证机械流程。默认及任务日常运行仅dev；holdout/all要求已冻结的最终候选身份及显式发布审计入口，不得因某任务想验收而解封。
7. 建立标签审计：对所有 expect 验证源存在、位置有效、事实原子在原文可核实；固定 seed 抽每类 8 题，输出原文位置/题目/事实/干扰来源，逐项人工式阅读核对并记录结论。审计者不得依候选排名修改正确答案。

第一份reference在本任务完成时冻结：记录生产模块commit、依赖锁、模型/资料/题集/分割SHA、索引和dev逐题结果。holdout reference可以提前计算后密封，仅公开其哈希和完整性记录，不把逐题结果或汇总分数提供给开发。此后候选只写新run，不覆盖reference；重建参考必须使用它自己的代码环境，不能用当前候选重生参考使回归归零。

全计划只做一次最终联合holdout审计：P1算法、参数、可选实验接受规则及最终候选代码/依赖SHA冻结后才运行；日常任务/M1/M2的开发验收用dev。增加`holdout_exposure.jsonl`，每次记录audited_at、candidate_sha、preregistration_sha、suite/split_sha、用途、所展示结果范围与先前曝光次数。最终审计失败后保留原始记录，不可针对已曝光失败题调参再宣称未见验证；若继续改算法，原holdout降为回归集，需要新独立来源才能重新声称发布质量通过。相同冻结代码的确定性复查允许，但不得变成反复选择候选。
