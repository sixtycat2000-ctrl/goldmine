# Goldmine P1 检索与 Agent 接入任务

先读 [执行合同](CONTRACTS.md)。按任务依赖实施；独立的协议适配、数据处理和实验不互相等待。允许修改排序的任务必须给出 per-query 变化；纯接口/结构任务不允许借机调权重。开发和逐任务回归只使用 train/dev；最终组合候选冻结后由 jointrelease 统一执行一次 holdout，不能把每个任务的最终质量门槛解释为反复查看 holdout 的授权。[架构审查](review/architecture.md)中的 ARCH-01 至 ARCH-06 已纳入以下步骤。

## P1 01

**抽出 CLI 与 MCP 共用的应用服务。** 依赖：P0-01；P0-06 完成后再接入统一验收 registry，不阻塞共享服务实现。入口：`goldmine/cli.py::cmd_search`、`Searcher.search`、`pack.build_pack_from_hits`、`Store`；新增 `goldmine/application.py`、`goldmine/contracts.py`、`tests/test_application.py`。

执行步骤：

1. 把搜索的“配置/打开索引/模型指纹检查/检索/上下文/打包/关闭资源”抽为应用服务；渲染、stdout/stderr 和 exit code 留在 CLI adapter。复用 Searcher 与 pack，不复制评分公式。
2. 定义类型：SearchRequest、SearchResult、Citation、ContextRequest、ContextResult、IndexStatus。请求携带 query、解析后的 filters、scorer、mode、limit、budget、context、why；结果携带实际执行设置、证据段和降级原因。Citation 的 evidence_type 固定为 content、name_metadata、vector_only，媒体细类使用独立字段，不能把 name/metadata 当正文。
3. 应用服务提供 search/get/context/status 四个方法，接受显式 index path 和可注入 backend factory。请求 context manager 拥有 Store 和临时 backend；独立 MCP 会话可拥有可复用 reranker，须显式借用/归还，不能由单次请求关闭，也不复用共享 SQLite 连接。异常、超时、取消及会话退出均释放相应自有资源。
4. 所有查询使用只读 Store；不存在的库明确报错，不创建空库、不迁移。SQLite URI 必须用绝对 Path.as_uri() 正确编码后追加 mode=ro；不能直接将路径拼接进 file: URI。get/context 仅取索引存储内容与元数据，不调用 opener 或读取源文件。旧库无所需列时明确返回升级前置条件，不伪造新 schema。
5. 每个操作显式开启一个只读事务；search 的指纹/身份检查、向量与词法召回、段正文、引用和 pack 必须在同一快照内完成，取完所需数据后才结束事务。不得只为 load_vectors 加快照，再用另一代数据生成引用。覆盖其他连接在召回后、正文读取前及 pack 前提交替换/删除的并发场景。
6. citation ID 按 CONTRACTS 定义。digest 输入固定为数组 ["gm-citation/v1", file.id, file.path, file.source, file.sha256, segment.id, segment.kind, segment.modality, segment.loc, segment.loc_end, evidence_type, parsed_file_info, stored_text]；JSON 使用 ensure_ascii=false、sort_keys=true、separators=(",", ":")、allow_nan=false，UTF-8 编码后 SHA256，ID 取前16位。parsed_file_info 使用已存 JSON 或 null；stored_text 使用 coalesce(fts.original, fts.body)，无文本为 null，空字符串保持为空。不能加入分数、indexed_at、PID 或当前时间；CLI/MCP 共享同一个实现。schema v4 缺 index_uuid 时，普通 CLI 搜索继续可用；需要 opaque ID 的 API 明确返回词法升级前置条件，不能查询时偷偷补写。name_metadata 的 get 返回已存元数据、可用的 name 段文字及“无正文”状态；vector_only 明确无可引用正文。
7. 一个 monotonic deadline 覆盖连接/锁等待、模型启动、RPC、重试、tokenize 与后续质量模式；每个阻塞步骤使用剩余时间，耗尽后不再重试、cold fallback 或提交后台调用。不能仅在工作线程外包装 timeout，让底层继续运行。保留用户可识别的 timeout 与实际降级状态。
8. cmd_search 改用服务，但保留当前参数、默认排序、错误形状、JSON envelope 和 `goldmine.cli` 的既有 import surface；此任务不启用后续新功能。搜索 adapter 在本次服务边界移到独立 commands/search 模块或等价聚焦模块，cli 保留 dispatch/兼容 re-export；其余命令由 P2-01 拆分，不把新 MCP/reindex handler 继续写进大 CLI。

必须验证：相同 fixture 和 mock backend 下，改前改后的默认人类/JSON/pack/fzf 输出一致；词法模式不构建 embedding backend；过滤器在查询前解析一次；`--limit 0`、只含过滤器的查询与原 clamp 行为保持；模型指纹错误仍保留原 exit 3；异常和取消后的自有子进程清零。只读调用前后 DB 逻辑内容与 schema 不变，?/#/%/中文/空格路径均打开正确库且父目录不多出空库。并发写入时不能返回旧向量分数加新正文；metadata-only 与无 FTS 的向量段引用可诚实回读。受控阻塞/重试后 deadline 有界，取消后不继续调用。

验收命令：`python3 -m pytest tests/test_application.py tests/test_cli.py tests/test_search_v2_output.py tests/test_pack.py tests/test_fingerprints.py -q`。任务证据包括至少 12 个改前/改后输出对照，以及 backend/Store 创建与关闭计数。禁止把所有 CLI 命令一次重写，本任务只抽出共享应用层。

## P1 02

**补上中文及混合文本关键词检索。** 依赖：P1-01。主文件：`goldmine/search.py`、`goldmine/store.py`、`goldmine/migrations.py`、`goldmine/ingest/commit.py`；新增 `goldmine/lexical.py`、`tests/test_lexical_cjk.py`、`tests/test_lexical_migration.py`。

执行步骤：

1. 新建纯词法模块，统一 NFKC + casefold 的索引用归一化、Latin token、CJK 连续串和二元组生成。原文、引用文本与位置保持不变；不能把归一化文本覆盖存储原文。
2. 识别汉字、平/片假名、韩文串；每个串同时产生去重单字与相邻二元组。普通多字查询用二元组，单字查询才用单字；Latin 查询继续使用原 FTS 规则，英文 stopword 不能套到 CJK 字符。
3. schema v5 增加 fts_cjk，维护 rowid=segment_id 和 lexical_version；加入 index_uuid。迁移从原 FTS/已存路径生成派生数据，同一事务提交，不读取源文件，不生成向量。新库直接创建当前目标版本。增加数据库级写入版本栅栏：新连接注册受支持 writer schema 函数；已提交库的 files/segments/meta 持久触发器无条件 RAISE(ROLLBACK)。唯一新 writer_scope 在 BEGIN IMMEDIATE 下核验版本，事务内暂时移除栅栏、完成相关写入、恢复栅栏再提交；其他连接不能观察到移除窗口。不能让触发器只调用旧连接不存在的函数，因为“no such function”只中止当前语句，不能回滚旧路径此前的 FTS 删除。须覆盖升级前已经打开、不会重新执行 Store 构造检查的旧连接。
4. 所有 replace/delete/failed-file cleanup 路径同时维护新 FTS，测试 rollback 不留孤行。对升级前已打开的旧版 writer，升级后 upsert/replace/delete/失败清理须全部拒写且事务回滚，不能先删 FTS 再仅拒绝段写入而留下半状态。Store.write_transaction() 是原始 SQLite 批量写的唯一入口；嵌套 Store 操作不自行 commit，异常回滚完整外层事务。reset、ingest reindex、benchmark 及测试的显式原始写均迁入该范围，禁止 scope 内手工 commit。允许等价的可靠数据库级栅栏，不建立通用锁服务。旧只读库不迁移，只报告缺少 CJK 索引；新增显式 `goldmine reindex lexical --db PATH` 用于派生索引升级/重建。
5. Searcher 合并两个词法通道，coverage 分母按实际有效查询单元计算；不能把一条中文词的多个 gram 当作多个独立强证据叠加。候选数量上限仍受控，不把整库装进 Python 做 substring 检索。
6. 引号中的中文短语：先用 gram 召回，再对存储原文归一化后的连续短语验证；错序/跨段/散落字词不能满足精确短语。
7. 指纹报告新增 lexical_version，词法升级不改变 embed_id、模型 SHA、chunker ID、向量数量和任何向量 BLOB。

必须覆盖的样例：`中文知识库搜索`；中英混合 `中文 invoice 2026`；全角 Latin/数字；日文假名、韩文；单字；emoji；空白；引号内“知识管理”；不连续“知识…管理”的反例；删文件、换内容、迁移被 SIGKILL 后重跑。

验收：

- [ ] `--lexical` 在中文 fixture 上能找到正文命中；遮掉语义 backend 后仍成立。
- [ ] 原英文 fixture 的相关结果无无解释倒退，Latin 短语和 prefix-last 行为保留。
- [ ] v4→v5 前后向量 BLOB 哈希集合完全相同；迁移与 reindex 的模型调用数为 0。
- [ ] `integrity_check=ok`、`foreign_key_check` 为空；两次 reindex 逻辑内容和数量一致。
- [ ] 运行 `tests/test_lexical_cjk.py`、`tests/test_lexical_migration.py`、现有 migrations/store/search 测试全部通过；开发报告只列 train/dev，最终 jointrelease 的 product.v4 cjk 达合同门槛，legacy 总体不触发回归。

禁止新加 jieba/模型分词器、改默认 embedding 或用评测词表定制分词。若 gram 策略达不到目标，保存失败样例，不能直接切成全库模糊匹配。

## P1 03

**让文件名、路径和编号排到正确位置。** 依赖：P1-02。主文件：`lexical.py`、`store.py`、`search.py`、`migrations.py`；新增 `tests/test_exact_lookup.py`。

执行步骤：

1. schema v6 新增 `lookup_terms` 派生表：保存 normalized_term、原始 token、file_id、segment_id、source（basename/path/title/body）。segment_id 必须有效；文件级词条关联该文件的 name segment，禁止 NULL/哨兵 ID 破坏唯一约束。
2. 为 normalized_term 建索引；从已存 FTS 与路径回填，不读取原文件。段替换和删除通过同事务更新/外键级联，重复导入不增加重复词条。v6 同步提升数据库写入栅栏要求，v4/v5 已打开旧 writer 都不能在升级后绕过 lookup_terms 维护。
3. 规范化先 NFKC+casefold，再保留 `-_.:/` 的完整 token；额外生成去分隔符 alias，但保留匹配类型。原串精确命中优先于 alias，`AB-12` 与 `AB12` 的歧义不能隐藏。
4. 排序层次固定：整个查询精确等于 basename/path 的命中；完整编号在有效内容/标题中的命中；alias；一般 lexical/semantic。相同层按原混合分及稳定 file/segment ID 排序。
5. 编号出现只是一个锚点：查询其余有意义词必须有词面或语义支持；不能因为包含 `8899` 就把“随机无关词 8899”当答案。纯完整编号查询可以靠精确锚点入选。
6. `--why` 增加 exact_source、raw/alias、匹配字符串、最终提升原因；不伪装成高 cosine。引用正文应指向包含编号的内容段，不能拿文件名位置冒充正文位置。

测试至少覆盖：大小写、全角、`LH-2209`、`K7Q2LM`、`key_value_store.sqlite`、空格路径、中文路径、前后缀近似编号、下划线/百分号转义、同 basename 不同目录、单个长数字、随机词+有效编号的 noise 反例。测试数据不得使用真实 eval ID 的白名单。

验收：`python3 -m pytest tests/test_exact_lookup.py tests/test_migrations.py tests/test_store.py tests/test_search_offline.py -q`；v5→v6 向量哈希不变、0 embedding 调用，升级前已打开的旧 writer 不能造成派生失配；开发只看 train/dev，最终 jointrelease 的 lookup holdout Top-1 ≥0.90，noise 同时满足合同；任何靠忽略不匹配词达成的提升拒收。

## P1 04

**修复 PDF 页定位与同文件多段证据。** 依赖：P1-03。主文件：`search.py`、`ingest/extract_pdf.py`、`ingest/extraction.py`、`chunker.py`、`pack.py`；新增 `tests/test_pdf_evidence.py`。

执行步骤：

1. 对 train/dev 的 pdf-page 全部失败样例分为：没提取正文、正确页没有召回、文件命中但展示错页、OCR 错误、邻页遗漏。报告每题归因，未看实际段不能直接决定“换 embedding”；开发不得展开最终 holdout 的失败题。
2. 内容段与 name/元数据段分开评分和选展示段。同一文件先保留至多 3 个内容候选，按该段的精确锚点、词面与语义证据选择主命中；metadata 不能覆盖一个已验证的正文精确锚点。
3. 对外搜索列表仍一文件一结果；额外支持段只放 `supporting_citations`/pack，不能破坏 public suite 的一文档一 hit 合同或重复刷排名。
4. 超长页按真实 token 切块；块不能跨页。若改变持久化语义，版本为 chunk.v3-page；每块 loc/loc_end 仍为真实页号。旧文件只标 stale，显式 ingest 时重切。
5. pack 同文件支持多处不连续证据；同页多块按位置顺序合并；跨页保留各自页标。±N 邻页只取存在且相邻的页，不跨到别的文件，也不把未 OCR 页当作空白页掩盖。
6. 正确页的定位分数必须由该页文本证明；文件级相关但页错时仍按原评测规则记为未解决。不得放宽页约束或把范围扩大到整个 PDF。

验收：

- [ ] 20 页 fixture 中第 3/17 页有相同主题、不同数字，相关查询各返回正确页；干扰页不能因文件名命中顶替。
- [ ] 单页超过 embedding 上限仍全部切为合法块，无跨页和 token overflow。
- [ ] 同文件两个相隔多页的事实都能进入 compound pack，两个 citation 均可回读。
- [ ] 原搜索列表一文件一 hit，公开评测语义不变。
- [ ] `tests/test_pdf_evidence.py`、PDF extraction/token chunking/pack/context 相关现有测试通过；最终 jointrelease 的 pdf-page holdout Top-5 ≥0.60、Top-1 ≥0.40，错页计数如实保留，日常只运行 train/dev。

禁止本任务重写为版面分析平台或引入大解析服务；若归因证明表格/版面是主要剩余问题，记录具体页和失败比例，单列后续提案，不能无限扩展。

## P1 05

**修复媒体检索并把能力状态说清楚。** 依赖：P1-04。主文件：`ingest/extraction.py`、`ingest/asr.py`、`ocr.py`、`ingest/media.py`、`search.py`、`doctor.py`、`render.py`；新增 `tests/test_media_evidence.py`。

执行步骤：

1. 每份媒体记录明确 evidence_type：name_metadata、ocr_text、asr_text、image_vector；一份文件可有多个，不用“image”一个标签混淆能力。
2. 照片名称与目录词进入 P1-03 精确/词法通道，日期/EXIF 进入实际字段和已有过滤逻辑；text-only llama 下明确 visual_search=false，不生成图片 caption 来伪装画面检索。

## P1 06

**减少无答案误命中，并校准融合规则。** 依赖：P1-05。主文件：`search.py`、`config.py`、产品评测脚本；新增 `tests/test_search_admission.py`、`evals/search_parameters.json`。

执行步骤：

1. 保留 query→候选→准入→排序→展示的分层。记录每个 hit 的 admission_reason：verified_exact、lexical_quorum、semantic_standout；同一证据不能重复加多次 kind boost。
2. 对 noise 和弱可答题诊断词面假锚点、长文 max-of-N、模态分布差、最高与次高差距；不能把低相关的正分数当概率置信度。
3. 在 train 运行之前写参数候选文件，最多 3 组，必须含当前规则控制臂。可选择调整 z gate、语义 margin、coverage 条件，但参数选择只依据预登记 train 门槛和目标，不能读取 holdout 后再改。
4. 选择规则：先满足 noise≥0.90 且可答题门槛；再最大化整体 success@5；并列按 MRR，再按更少新参数。无候选合格则报告 FAIL，不自动追加第四组或把 target 降低。
5. 选中参数写搜索行为版本和配套 why；在 dev 确认，并复跑 legacy、media-full、公开三集。holdout 留给所有变更冻结后的唯一 jointrelease 验收，不在本任务独立打开。一般 query 无法准入时返回空结果，解释留诊断字段/why，不制造一个“最接近”答案。

必须测试：全不相关向量仍有最高值、单文件含很多弱相关段、精确编号强锚点、编号加随机词、过滤后零结果、只有单一模态小组、全部无向量、CJK noise。准入逻辑不能依赖 eval ID 或原题字符串。

验收：`tests/test_search_admission.py` 与既有 search/parser/output 测试通过；product.v4 全部快速模式指标达合同，noise≥0.90；无答案判断使用结构化 hits=[]，不能用 stdout 是否包含 query 词判断。保存参数选择过程与所有失败题；未达门槛时 M1 不通过。

## P1 07

**增加可选本地重排并验证实际收益。** 依赖：P1-06。新增 `goldmine/rerank.py`、`tests/test_rerank.py`、`tests/test_live_rerank.py`；允许扩展 model manifest、配置、parser 和 application。

执行步骤：

1. 固定唯一候选模型族为 Qwen3-Reranker-0.6B 的 GGUF；执行时从发布者模型卡核对来源、精确 revision、文件 SHA、tokenizer、输入格式和文件大小，记录 artifact。下载只能显式发生在模型安装阶段，search/MCP 不下载。
2. 先验证项目已固定的 llama-server 是否支持该模型与重排端点；读取本机 vendor 文档，保存实际请求响应 fixture。不能猜 HTTP 路径，也不能为实验偷偷升级 embedding server 或引入 PyTorch。
3. 不兼容则形成 EXPERIMENT_REJECTED 报告，包含错误与兼容性证据；不暴露一个永远降级的“已完成重排”。兼容时实现独立 backend 生命周期，不与现有 embedding fingerprint 混用。
4. 仅 quality + rerank=local 运行，最多 20 段，每段 384 个重排模型 token；按稳定 ID 排序处理平分。只重排已准入候选，不把已拒绝的 noise 复活。
5. 为置信度、NaN、缺结果、维度/ID 乱序、超时设校验；失败回到原排名并返回 fallback_reason。quality 有效执行和 fallback 分开统计；默认 fast 不加载重排模块或模型。
6. 单独测质量与资源：same candidates 的 off/local 两臂，不混入多查询收益。开发仅运行 train/dev；预登记最终接受条件：train 与 jointrelease holdout 的 nDCG@10 至少各 +0.02，简单查询 Top-1 不显著退步，noise 门槛不下降，并满足合同延迟/内存。模型进程归显式请求或 MCP 会话所有；五分钟空闲释放测试针对会话复用，单请求 CLI 结束立即释放自有临时模型。

验收：请求反例测试、off 模式零模型调用、超时清理、内存压力释放、5min 空闲释放通过。`python3 -m pytest tests/test_rerank.py -q`；真实条件齐备运行 `GOLDMINE_LIVE=1 python3 -m pytest tests/test_live_rerank.py -q -rP`。

未达到收益/资源门槛可按 EXPERIMENT_REJECTED 完成本实验，但默认保持 off，安装说明不推荐启用；必须保留完整对照，不得只报告最有利子集。

## P1 08

**增加确定性多查询与证据合并。** 依赖：P1-06 的实现；与重排组合的验收另需 P1-07 实现或有完整 EXPERIMENT_REJECTED 证据，基础 planner 不等待该实验。新增 `goldmine/query_plan.py`、`tests/test_query_plan.py`；改 application、pack、parser；不添加生成式 planner。

执行步骤：

1. `--mode quality --multi-query` 才启用；原 query 永远保留，最多追加 2 个子查询。子查询由原文子串和明确共享的限定词组成，不生成新事实或实体。
2. 仅支持可机械验证的语法：分号/中文分号分隔的两个非空子句；`比较 A 与 B 在 C` / `compare A and B on C`。其他“和/and/与”不自动拆，防止产品名和标题被误拆。
3. 过滤器解析一次，所有子查询共用同一 filters；引号短语、编号、路径不能在拆分时损坏。子句不足 2 个有效词或重复时不新增。
4. 各子查询取受限候选，合并最多 60 段；按 segment identity 去重，RRF k=60，原 query 权重 2，子 query 权重 1。每条候选保存命中子查询 ID，不把几次召回算成多条独立证据。
5. 如同时开启重排，对合并后的候选最多重排 20 段一次，不逐子查询各加载模型。总调用仍受 quality 10s deadline。
6. pack 按已命中的子主题轮转优先取证据，最多 3 个主题，再按总分填剩余预算；任何文本仍来自真实存储段，不能自行加结论。

验收：

- [ ] 固定输入与设置产生字节相同的查询计划；max_queries 永不大于 3。
- [ ] `Research and Development`、带分号的引号、`under:` 路径、中文编号等反例不被错误拆解。
- [ ] 任一子查询异常/超时可降级但明确标记；取消后不继续发后台请求。
- [ ] 开发只运行 train/dev；最终 jointrelease 的 compound holdout all_required_facts@pack≥0.75，且较单 query +0.10；简单题无显著回归。
- [ ] `tests/test_query_plan.py`、pack 与 application 相关测试通过，预算及来源不回归。

若确定性语法在真实题上未达收益，报告 EXPERIMENT_REJECTED，保留 off 默认；不得改成调用 LLM 拆题，或用 expected facts 生成子查询。

## P1 09

**提供只读 stdio MCP 服务。** 依赖：P1-01、P1-02 的应用服务与 index_uuid 实现；基础协议不等待 P1-07/P1-08 的可选实验，质量选项组合验收在相应实现后补齐。新增 `goldmine/mcp_server.py`、`tests/test_mcp.py`、`tests/test_live_mcp.py`、`docs/MCP.md`；在可选 extras 和包发现中增加实际模块。

实现使用 [官方 Python SDK](https://github.com/modelcontextprotocol/python-sdk)；本任务开始先核对其[当前官方文档](https://py.sdk.modelcontextprotocol.io/)，在隔离环境选择并安装一个非预发布稳定版本，测试握手后将精确版本锁入约束文件。不得照抄过时 v1 的 API 名称再假定兼容当前版本。可用 [MCP Inspector](https://modelcontextprotocol.io/docs/tools/inspector) 辅助人工查看，但自动验收使用 SDK 客户端。

启动接口：`goldmine mcp --db PATH`，默认且只支持 stdio；`--help` 不 import 可选 SDK。未装 extra 返回现有四行错误和安装命令，不 traceback。

工具 schema 固定，未知字段拒绝：

| 工具 | 参数 | 结果 |
|---|---|---|
| goldmine_search | query；limit=10；mode=fast；rerank=off；multi_query=false；pack=false；budget=4000；context=1；why=false；filters 对象可选 | pack=false 返回 hits/citation_id；pack=true 返回含完整出处的 context_text；两者均报告实际设置、token_mode 与降级原因 |
| goldmine_get | citation_id；budget=2000（512..8000） | evidence_type、存储原文或明确无正文状态、已存元数据及位置、来源状态、截断说明；受预算控制 |
| goldmine_context | citation_ids（1..10 个）；neighbors=1（0..3）；budget=4000 | 去重合并的材料正文、引用表与 token 计数 |
| goldmine_status | 无参数 | 索引身份、数量、能力、staleness、serve 可用状态 |

filters 只接受 kinds、under、site、after、before、phrases；字段转换为 QueryFilters，严格验证。under 仅过滤已索引路径，不能触发扫描。error 区分 invalid_params、no_index、fingerprint_mismatch、stale_citation、missing_capability、budget_too_small、timeout，并设置 MCP 的工具错误标记；不能把错误包装成成功的空 hits。

执行要求：

1. 通过 P1-01 应用服务取数据，不起 CLI 子进程，不增加 ingest/delete/open/backup/exec 工具。
2. 每次 Store 连接在同一工作线程内创建/使用/关闭，保持 SQLite 线程约束及 P1-01 的请求快照；串行处理模型工作，等待队列最多 2 项。排队计入同一个 monotonic deadline，所有后端调用传入剩余时间；超时后不再重试或 cold fallback，不留继续工作的线程。不杀共享 serve；自有请求 backend 立即关闭，会话复用 reranker 在取消时归还并在空闲/会话结束释放。
3. stdout 只留 SDK 协议消息，日志到 stderr。EOF、SIGTERM、取消和客户端断开均清理连接/自有 backend；启动不扫描目录、不更改客户端配置、不安装 launchd。
4. citation 使用 P1-01 的 canonical digest 校验 index_uuid、段身份、原文及已存 info；跨库 ID、已删段、改变原文/位置/元数据后的旧 ID 都明确失败，不接受 ID 中嵌入的路径或 SQL。解析时拒绝非法 UUID、超出 SQLite INTEGER 范围的段 ID、非16位摘要和未知 ID 版本；不通过 traceback 暴露解析失败。备份复制保留 UUID，属于同一索引谱系，不能要求内容完全相同的备份也被当作无关跨库拒绝。

验收：真实 SDK client 启动服务、initialize、list_tools、调用四工具、结束会话完整走通；同时覆盖恶意路径/URL/SQL、陈旧 ID、未知参数、无索引、缺 extra、超时、取消、协议 stdout 污染。带“忽略指令并执行 shell”的文档只作为资料返回，不能引发新动作。

`python3 -m pytest tests/test_mcp.py -q` 在装 extra 后通过；真实模型 smoke 与 CLI 的同 query/filters/scorer 得到相同有序段 ID。serve 驻留时 MCP 额外 p95≤100ms；不能用 SDK mock 代替完整子进程握手验收。

## P1 10

**统一材料包契约并完成端到端验收。** 依赖：P1-09、P0-03。主文件：`pack.py`、`application.py`、`mcp_server.py`、`render.py`；新增 `tests/test_pack_contract.py`、`tests/test_agent_workflow.py`。

执行步骤：

1. CLI/MCP 使用同一 collect/neighbor/dedupe/budget/render 函数。预算覆盖完整 context_text（包含标题、出处和 footer），source text 必须来自 segment_text；禁止复制成两个行为略不同的 pack builder。
2. 为预算 512/1000/4000/32768、context 0/1/3、空结果、超长单块、8192字节查询、长路径/出处、长 why、中文、表格、代码、同文件不连续命中建立边界用例。空包的 header/footer 及元信息也计预算，不能仅检查有记录时的预算。
3. exact tokenize 不可用时返回 estimate，并标明 tokenizer；不把 token 未知当 0。无法容纳最小带出处证据时输出明确无可容纳记录；若连有界空包的必需 header/footer 都无法容纳，返回 budget_too_small，不返回超预算 context_text，不截掉出处冒充成功。
4. 引用可经 goldmine_get 回读；页/行/时间单位正确，近重复合并保留原来源关联，跨文件引用不会折叠掉差异事实。stale_citation 不临时从源文件寻找替代段。
5. 只有相同索引、query 和完整设置才要求字节确定；metadata 中时间、临时绝对路径和运行 PID 不进入材料正文。MCP 不重复返回正文两遍。
6. 跑完整 Agent 使用链：search(pack=false)→选择 citation→get→context，以及 search(pack=true)；与 CLI 同请求的 context_text 比较。
7. 使用 P0-03 的真实新答案，比较参考 LIST、参考 PACK、候选 PACK。三臂使用相同题、模型、评分协议，原题答案不能泄漏给 answerer；分别报告得分、事实覆盖、trap 拒答和使用 token。

验收：完整包 exact token 计数全部≤budget；相同输入两次 byte-identical；100% 非空引用可回读且位置正确；所有离线契约/Agent 链测试通过。候选 PACK 不触发校准后的答题退步门禁，trap 拒答≥0.90；相对 LIST 的成对得分提升其 95% bootstrap CI 下界>0，不能只比一次均分。
