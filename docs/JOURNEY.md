# 第一部分：八幕旅程

## 第〇幕（背景）：这个项目想解决什么

goldmine 是一个**本地优先**的 macOS 命令行搜索工具：只搜你明确指定的
文件夹、数据全部在本地一个 SQLite 文件里、不上传任何东西。对标并师承
一个同作者的 Swift 项目 DigUp。它要同时做两种搜索：

- **词法检索**：像数据库一样精确匹配词（"TRX50" 这种编号只有这条路）。
- **语义检索**：按含义找（"怎么给长书的分页做索引"能命中讲"长文件
  续读"的段落，哪怕一个词都不重合）。

技术底座（术语考古见词典 A1–A5）：文本嵌入模型 embeddinggemma-2 的
Q8_0 量化版，由 llama.cpp 推理；词法靠 SQLite 的 FTS5。

## 第一幕：文本时代与"证据绑定"工作法的确立

最早的一批执行记录（P0-01 到 P0-06、P1/P2 系列）干了两件事：

1. **数据安全地基**（P0）：根目录中途消失不得当成"全部删除"、参考向量
   测试（把模型产出钉死到逐位）、毒文件不毒库等——全是"先保证不伤害"。
2. **工作法定型**：三态结论（PASS 必须带原始回执；FAIL 如实记；证据不足
   记 MISSING）、预注册（结构性改动先冻结设计再动手）、对抗评审（另一个
   AI 视角专挑设计毛病，裁决 ADOPT/修订/REJECT）、审计门（封存基线只许
   在留痕下最小重生成）。

**为什么先立规矩**：这个项目的开发主力是 AI 会话，AI 的失败模式是
"自信地编"——规矩的作用是让"编"在流程里活不过验证关。

**关键先例——digup-plan-001 的诚实回滚**：P1 检索改进（代码文件用仓库
路径做标题 + 独立查询提示词）在 DigUp 有实测正收益，goldmine 自己 A/B
后**零改善**，按预注册判负回滚；另一项撞了冻结基线，按规则回滚。DigUp
的数字是先验不是证明——这条此后成为铁律。

## 第二幕：DigUp 考古与"教训带出处"

把 DigUp 源码逐文件读了一遍，产出 docs/digup-derived-plan.md：哪些已
继承、哪些值得搬（每条带 file:line 出处）、哪些明确不搬（带测量依据的
拒绝——比如 RRF 融合在 DigUp 自己的数据里就输给加法融合）。DigUp 的
事故索引（每条事故 = 一条预防规则）成为 goldmine 的"宪法原料"：不可读
目录≠空、向量家族不混、截断必须标 partial。

## 第三幕：多模态里程碑（digup-plan-002）

目标：图片/音频也能被"含义"搜到（此前只有文字）。七个子问题逐个解决，
每个都有"为什么"：

1. **模型侧缺口**：llama-server 的 HTTP 接口不暴露多模态嵌入。两条路：
   给 vendored 上游打永久补丁（升级即地狱）vs 自己写 1412 行纯 C11 的
   常驻 helper 静态链接 mtmd 库。**选后者**——无补丁、协议简单到不会
   错（每行一个 JSON）。
2. **像素管线的偏执**：图片进模型前要缩放。缩放算法差一点点，向量就
   整个变味。所以把 DigUp/mtmd 的 Pillow 风格双三次缩放**逐位移植**
   （22 位定点运算），并用黄金表测试钉死——helper 与参考实现必须一位
   不差。为什么这么偏执：向量是"家族"的，混了两种缩放的向量等于两个
   家族互相比分数，搜索悄悄变坏且无从发现。
3. **token 预算制**：图片不是无脑塞——照片 140 token、截图 280、PDF 页
   280、视频帧 70（成本与信息量的权衡，DigUp 实测先验）。预算进指纹。
4. **音频路由（MM-D3）**：有转录（ASR）的音频用文字向量，没转录的才用
   原始音频向量——并在每行 info 里写明"这条向量为什么存在/不存在"。
5. **死锁血泪**：helper 边车最初两个排空线程，协议响应被吃掉永远等不到
   回包；换成只排空 stderr 后，BufferedReader 的预读又让 poll 永远不醒。
   最终纪律：**stdout 是协议信道不开线程、裸 fd + os.read**。
6. **指纹的条件附加**：媒体能力（helper+mmproj 都在）才往指纹里加四个
   键——纯文本安装指纹逐字节不变，有守卫测试。为什么：不能让装了
   媒体的机器的升级强迫纯文本用户重建索引。
7. **评测转正**：全媒体 128 题套件重定基线，legacy 109 题门无回归，
  `visual_search` 从 false 翻 true——由静态探针派生，不是配置写死。

## 第四幕：视频与 ffmpeg 抉择

视频关键帧（每 ~3 秒采一帧、8×8 aHash 去重、至多 1200 帧）由另一个
会话实现并审计通过。期间做过一次真实基准测试驱动的选型：ffmpeg vs
macOS 原生 AVFoundation——本机测出 ffmpeg 全核并行更快（5 分钟 1080p
3.88s vs 4.07s）但全内占视频更慢（2.10s vs 0.60s），最终**留 ffmpeg**：
跨平台（Win/Mac/Linux）+ 格式覆盖（ogg/opus/wma/avi/mkv/webm）值这个
权衡，AVFoundation 记录为条件性备胎。

## 第五幕：P2 收尾（digup-p2-closeout-001，本旅程主役）

与 DigUp 全面对照后确认七个真实缺口，分两批：

**批次 A（五项，不碰指纹）**——每项的"为什么"：
1. iCloud dataless 跳过：open 即下载，必须在任何 open 前拦截；拦截点
   刻意放在格式嗅探之前（嗅探会 open 文件）。
2. 查询期已删文件过滤：命中一个打不开的文件是对信任的消耗；但第一版
   被对抗评审拦下（会打挂 21 个用假路径的离线测试），改成只在索引真实
   roots 内过滤——语义与删除检测对称。
3. estimate 命令：摄取大目录前的预期管理；只读、在结构上就不带写库
   参数；速率用 DigUp 先验并明说"goldmine 校准待做"。
4. EPIPE：`| head` 断管的坑比想的深——小输出全在缓冲区、只在解释器
   收尾 flush 时爆（rc 120）。修法 = 执行期 handler + 退出前 flush 探针。
5. 构建目录表（build/target/dist/out/.next）：不值得索引的产物。

**批次 B（两项，授权改指纹/评测）**——两个最重的"考虑"：
1. **音频尾窗规则的源码考古**：goal prompt 写"丢 <2s 尾窗"，核对 DigUp
   源码发现字面规则在 30s 窗/25s 步进下是**不可达死代码**（尾窗最短 5s），
   且 prompt 的 62s 例子与源码相反。真语义：尾窗携带 ≥2s **新音频**
   （超出上一窗覆盖）才保留。按源码移植，偏差写进预注册。这暴露了
   "prompt 当规格"的风险——幸亏流程要求对照源码。
2. **阿拉伯丢字页 OCR 替换**：病理复现验证（设计第一步）诚实地失败了
   ——macOS 原生工具链产出的阿拉伯 PDF 全带完整 ToUnicode，造不出病。
   按预注册回退：合成病理 + 机制测试为主，真实资产记 MISSING。
   评审还抓到三处硬编码版本字面量的"永久重抽"陷阱——改成单一共享常量。

**收尾**：评测库审计门重建（8 项差异逐条归属）、双 gate 全 0 delta、
参考向量逐位复现。旧库备份保留作审计证据。

## 第六幕：撞车（过程事故，也是过程资产）

最终全量测试突然冒出陌生失败。排查发现**另一个 AI 会话在同一工作树上
并行干活**：27 个评测文件被改成占位符路径、一批我没碰的文件带未提交
修改。处理：把它的 27 个文件 stash 出去 → 失败全恢复绿（归因成立）→
白名单提交自己的文件（一行不吞）→ stash 它自己后来消费掉了。教训固化
成 AGENTS.md 铁律：**一会话一分支，合并经用户**。

## 第七幕：质量自省

对照顶级开源仓库的客观评价：过程纪律顶级（证据/预注册/评审/诚实工程
超过多数人类项目），产品成熟度 pre-release（自己的最终质量门还有 12 项
红、无发布、hosted CI 从未跑通、bus factor = 1）。随后"vibe code"之辩
得出核心判断：**验证是反 vibe 的，所有权是 vibe 的**——代码被检验得
很狠，但能接住它的人类太少。风险不是"没人验证"，是"AI 不在时没人接
得住"。

## 第八幕：理解密度制度（对第七幕判断的回答）

锚点卡（用户亲手可跑的验证，摆脱对会话转述的依赖）→ 五讲轮讲（用户
复述、十问自检）→ 每提交一份人读 diff 摘要（讲行和风险，不讲故事的
续集）→ 判断权清单（prompt 与源码冲突时停下来让用户拍板）→ AGENTS.md
（六条铁律 + 一会话一分支）。本文（旅程+术语考古）是这个制度的深水区
材料：把一路上每个术语挖到最底，让"理解"不再依赖任何会话的记忆。

# 第二部分：术语考古词典

> 每个词条从"它在本项目里干什么"开始，一层层往下挖，直到只剩常识。
> 编号供交叉引用。

## A. 搜索与表示

**A1 嵌入（embedding）**：把一段文字变成一串数字（这里是 768 个）。
↓ 为什么一串数字能代表含义？训练时模型学会了把"意思相近"的文本放到
这 768 维空间里相近的位置——"猫"和"狗"的向量夹角小，"猫"和"资产负债表"
夹角大。
↓ "768 维空间"是什么？想象 2 维（平面上的点）和 3 维（房间里的点），
然后把这个直觉推广到 768 根轴。每个词/句是其中一个点。
↓ 谁来算这串数字？神经网络前向推理一次（本项目用 llama.cpp 跑
embeddinggemma-2 模型）。

**A2 余弦相似度（cosine）**：两个向量的夹角余弦，忽略长度只看方向，
值域 [0,1]（本项目里 1 = 方向完全一致）。含义相近 = 夹角小 = 余弦大。
↓ 为什么不直接算距离？文本长短不同导致向量长度不同，方向才是"含义"，
长度只是"幅度"。

**A3 z 分数（z-score）**：(单个分数 − 均值) / 标准差。回答"这个分数在
今天的分布里算多出众"。z=5 意思是离均值 5 个标准差。
↓ 为什么要标准化？原始余弦没有绝对意义：模型对 A 查询可能全体打 0.8、
对 B 查询全体打 0.3。减均值除标准差后，"出众程度"才可跨查询比较。
↓ 本项目的细分：均值按模态分组（文本/图/音各自一组），标准差用全库
统一——DigUp 实测全按模态分会"窄组吹爆、埋掉 PDF 页"。
↓ 手算锚点：26 行里 1 行满分其余 0 → z = √(26−1) = 5。一行鹤立鸡群
时 z ≈ √(n−1)。

**A4 FTS5 / BM25**：FTS5 是 SQLite 内置的全文索引（倒排索引：词 →
哪些行含它，像书后的索引页）。BM25 是它的打分公式（词越稀有、出现越
密、文档越短，分越高）。本项目只用 BM25 的**排名**，不把它的分加进
最终分数（它低=好，方向相反）。

**A5 混合融合（hybrid）**：score = 语义×1.0 + 词覆盖^1.5×2.0 (+类型
命中 +1)。词证权重刻意 heavier；查询像编号（"TRX50"）时反转成
(0.5, 4.0) 词法压倒。为什么混合？两条路各有盲区：纯语义抓不住精确
编号，纯词法抓不住同义改写。

## B. 模型与推理

**B1 量化 / Q8_0**：神经网络权重本是 16 位浮点；量化把它压成 8 位整数
（Q8_0 是 llama.cpp 的一种 8 位格式，_0 表示对称分组）。模型文件从
~1.5GB 压到 ~800MB，推理快数倍，精度损失极小。
↓ 为什么敢压？权重数值分布集中，8 位足够表达；"组内共享一个缩放因子"
把误差摊薄。
↓ 为什么不 Q4 更小？精度损失开始可测；而 **F16 被明确禁止**（同模型
家族实测：激活值溢出 float16——记录在案）。

**B2 llama.cpp**：一个用纯 C/C++ 写的 LLM 推理引擎（无 Python 依赖、
单文件可执行）。llama-server 是它自带的 HTTP 服务进程。本项目 vendored
（连源码一起进仓）并钉死版本 b11461。

**B3 mmproj / 多模态投影**：embeddinggemma 是文本模型，看不见图片；
mmproj 是配套的"投影头"——把图片/音频编码器的输出**投影进文本向量
的同一个 768 维空间**，这样"一张猫的照片"和'猫'这个词就能比夹角了。
这就是"多模态搜索"的全部秘密：一切都被搬到同一空间。

**B4 池化（pooling）**：模型对一段文本输出 N 个位置各一个向量，池化把
它们合成一个（本项目用 MEAN——取平均）。"一段文字一个向量"才好建索引。

**B5 常驻进程 / 边车（sidecar）**：模型加载要搬 ~1GB 进内存，每个命令
起一次太贵。所以让服务进程**常驻**（一次加载反复使用）；"边车"指主
程序旁边挂一个辅助子进程（goldmine-embed），同生共死。

## C. 数据与身份

**C1 SQLite / WAL / 事务**：SQLite 是单文件数据库（整个索引就是
一个 .sqlite）。WAL（预写日志）让读写不互相阻塞。事务 = 一组操作要么
全成要么全不做——本项目**一个文件一个事务**，崩溃最坏丢一个文件的
这一次，绝不留半个文件的段。

**C2 sha256 / 内容哈希**：任意数据 → 64 位十六进制"指纹"，数据变一位
它就面目全非。用途：①摄取前比对文件内容有没有变（没变就跳过）；
②给模型文件验明正身；③指纹身份的原料。

**C3 指纹（本项目特指）**：一切"决定向量取值"的东西打包成 JSON 排序
后取 sha256——模型身份、维度、提示词、池化、归一化、媒体加工串、
预算……任何一个变，指纹变，旧库被门拒绝（exit 3）。为什么这么凶：
两种指纹的向量混在一个库里互相比分数 = 搜索静默变坏且无从察觉。
这是"向量家族不混"的执法机制（四层身份模型见第二讲）。

**C4 键序规范化（canonical JSON）**：把 JSON 的键排序、去空白再哈希
——这样{"a":1,"b":2}和{"b":2,"a":1}是同一身份（本该如此）。

## D. 评测与统计

**D1 s@5 / MRR / nDCG**：搜索质量的三把尺。s@5 = 前 5 条里有没有
正确答案（0/1）；MRR = 正确答案排名的倒数（第 1 名=1，第 3 名=0.33）；
nDCG@10 = 前 10 条带位置折扣的综合分（好答案排越前越高）。

**D2 McNemar / 成对 bootstrap**：判断"新分数和旧分的差是真改进还是
运气"。McNemar 只看一增一失的那些题（两边都对的题不提供信息）；
bootstrap 是反复抽样算差的置信区间。结论"p=1.0 / CI 含 0"= 没证据
说是真变化。
↓ 为什么需要统计？128 题的样本，一题摆动就是 0.8%——不检验就会把
噪声当成果（这就是"不做质量重试"的数学根据）。

**D3 holdout / train**：把题库分两半，一半用来调参（train），另一半
封存只在最后验收打开（holdout）。为什么：只用 train 调出来的"改进"，
可能只是背题；holdout 是防背题的考卷。本项目 holdout 密封，任何
reports 外的 holdout 路径不碰。

**D4 基线 / gate / 审计门**：基线 = 冻结的历史分数（比较的锚）。
gate = 每次 CI 式重跑，和基线比、超阈值就红。审计门 = 基线确实需要
重生时（比如语料或身份合法变了）的唯一合法通道：先备份、逐条对账
每处差异、全部归属清楚才放行——杜绝"顺手夹带"。

## E. 多媒体管道

**E1 双三次缩放（bicubic）**：图片缩放的一种插值（用周围 16 个像素
的三次函数拟合，比"最近邻/双线性"平滑）。a=−0.5 是一个形状参数
（Pillow 库的默认，轻微锐利）。**逐位一致**为什么重要见 C3：缩放差
一位 → 向量差一点 → 家族分裂。22 位定点 = 用整数运算模拟小数（避免
不同 CPU 浮点实现的最后一位差异）。

**E2 aHash（平均哈希）**：图片缩到 8×8 灰度、和平均值比较得 64 个
0/1——内容相似的图哈希相近（比较"不同位数"≤4 视为同帧）。用于视频
去重：静止画面连续采 100 帧也只留 1 帧。

**E3 RMS / 静音门**：一段音频的均方根（能量的平方根）≈ 响度。低于
0.003（约 −50dB）的窗口没有信息，不浪费嵌入。尾窗 ≥2s 新音频规则见
第五幕。

**E4 ASR / whisper / VAD**：ASR = 语音转文字。whisper 是 OpenAI 开源
的识别模型（本项目用 large-v3-turbo 的 Q5 量化 + llama.cpp 跑）。
VAD = 语音活动检测（silero 模型先找出"哪些段是人声"，省得对静音转写）。

**E5 OCR / Vision**：光学字符识别——把图片里的字变成文本。本项目用
macOS 系统 Vision 框架（经一个 Python helper 调用）做截图/扫描页的 OCR。

## F. 文件系统与进程

**F1 lstat / st_flags / SF_DATALESS**：lstat = 只看文件的"门牌信息"
不打开它（stat 跟随符号链，lstat 不）。st_flags = macOS 给文件标的
系统标志位；SF_DATALESS（0x40000000）= "iCloud 占位，实体在云上"。
对这种文件 **open = 触发下载**，所以拦截必须在一切 open 之前。

**F2 符号链（symlink）**：一个"快捷方式"文件，指向另一个路径。目录
符号链永不跟随（防环：a→b→a 死循环）；文件符号链跟到内容。

**F3 inode / dev / 移动检测**：inode = 文件系统里文件的唯一编号（改名、
挪目录都不变）。所以"路径没了但 inode 出现在别处" = 移动而非删除——
改个路径就能保住全部已嵌入内容。

**F4 EPIPE / SIGPIPE / 管道缓冲**：`goldmine search | head` 里两个进程
用管道相连；head 拿够就走，goldmine 再写 → 内核回 EPIPE 错误（默认
行为是 SIGPIPE 信号杀死进程）。Python 默认忽略该信号把它变成异常，
但要接住它才能安静退出。深层坑：小输出躺在用户态缓冲区没进管道，
执行期根本不报错，只在解释器退出 flush 时爆（退出码 120）——所以
需要"退出前主动 flush"当探针。

**F5 poll / os.read / 死锁**：poll = 问内核"这个 fd 有数据吗"（水平
触发 = 有就一直说有）。BufferedReader 会**预读**——把管道里的数据
提前搬进自己肚子，poll 看管道永远空 → 永远不醒。所以协议读必须用
裸 fd 的 os.read（要多少读多少，不多拿）。

## G. 过程与协作

**G1 三态结论**：PASS（带原始回执：命令行、退出码、输出哈希、前后
源码身份）/ FAIL（如实）/ MISSING（证据不可得）。“基本通过”是禁语。

**G2 预注册**：结构性改动前把设计、逐文件哈希、通过判据冻结成文——
先承诺再动手，防止"边做边改标准"。

**G3 对抗评审**：另一个独立 AI 上下文专职攻击设计（找反例、验主张），
裁决 ADOPT / ADOPT-WITH-CHANGES / REJECT。本旅程两次关键拦截（A2 的
21 个测试、版本字面量漂移）都来自它。

**G4 stash / 一会话一分支**：git stash 把未提交改动暂存起来（工作树
回到干净）。撞车事件里用它做归因实验（stash 掉对方的改动看失败是否
消失）。制度化为"每个 AI 会话在独立分支干活，合并经用户"。

**G5 flaky test / 归因**：偶发失败的测试。处置纪律：单独重跑 3 次；
若怀疑是新改动引入，用 stash A/B（改动前后各跑一遍）归因——比"重跑
到绿"诚实。
