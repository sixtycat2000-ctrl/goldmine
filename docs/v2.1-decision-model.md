## 1. Ground: the vendor pattern and what we measured

**The Jev pattern (TypeSafe AI "System One", released 2026-09-15).** Input = unstructured state +
typed questions: Noul (yes/no → calibrated probability), Choice (≤255 options → per-option
probabilities), Score (ordered levels). All questions in one request are evaluated in parallel;
output has **no free text**; claimed 70–500 ms end-to-end, $0.042/MTok input (output free),
calibration via RLCD, "no type errors by construction". **Cloud API only** (early access, no local
weights). The open-source `system-one-adapter-python` constrains regular LLMs to the same wire
format — format portability, **not** calibration portability. Microsoft and others shipped similar
"decision model" products by mid-Oct 2026, so the category may standardize around this shape; the
interface (D1) is our hedge, the adapter (D2) is our exit.

**Measured evidence in this repo (all recorded locally, none quoted from vendor material):**

| Fact | Numbers | Where |
|---|---|---|
| Query-prompt framing on long argument queries | ±6.7–14 pt nDCG@10: raw 0.572 / production search-result 0.506 / STS 0.365 / doc-style 0.444 (arguana, 2026-10-19 /tmp diagnostic) | conversation record; current routing = the `is_lookup` digit heuristic only (search.py:484-499) |
| Hybrid vs pure-semantic arm deltas (R5 arms, 2026-10-19) | scifact +0.002 / nfcorpus +0.026 / arguana −0.004 | R5 arm build (arms defined `docs/v2.1-r5-public.md` §6) — the lexical leg helps some queries, harms others; routing by query type is the R10 direction |
| Grader variance (R4 double round) | grader_flip **0.05** (1/16 score flips) | ROADMAP.md:26; the pack-eval D13 gate constant (0.1) was derived from it |
| Honest refusal (R4 traps) | 8/8 across two rounds — but the mechanism is prompt-trained, **not calibrated** | pack-eval §3/§5 (traps ans-017..020, `honest_refusal_rate`) |
| Multi-fact borderline (R4) | ans-009/010 score 1-not-2 when the pack misses one of 3 must-facts | pack-eval §3 question table — a "pack sufficiency" signal could calibrate abstention |
| Warm search latency | **116 ms** measured (R8 bench; gate ≤ 300 ms) | docs/v2.1-r8-serve.md §2 — the budget any per-query judgment must respect |

## 2. The interface (`goldmine/decisions.py`, new)

```python
class DecisionClient(Protocol):
    def noul(self, state: str, question: str) -> tuple[bool, float]: ...
    def choice(self, state: str, question: str,
               options: Sequence[str]) -> tuple[int, list[float]]: ...
    def score(self, state: str, question: str,
              levels: Sequence[str]) -> tuple[int, float]: ...
    def ask(self, requests: Sequence[DecisionRequest]) -> list[DecisionResult]:
        """ALL questions in ONE wire request (the Jev parallel property);
        the single-op helpers above delegate here."""
```

- `state` is the unstructured state: the query (routing), question+pack (sufficiency, grading),
  chunk+candidate edge (R7). Plain text, ≤ a pinned 16 KB cap per question; an oversized state is
  refused locally and tier-0 answers.
- Results are typed tuples; **no free text is ever consumed** — anything outside the typed shape is
  a `DecisionError`.
- `DecisionError(kind, message, why, fixes)` mirrors the universal error shape (errors.py:53-60),
  library-level: every call site catches it and falls back to tier-0. **Fallback is never silent** —
  the `decisions` provenance block (D12) records backend, used=false, fallback_reason.
- Determinism: argmax ties break to the first option; a backend whose probabilities jitter
  run-to-run fails Phase 1's stability check and is not adopted for gating decisions.

## 3. Backends and the tier contract

- **Tier-0 (always on, zero latency):** today's rules, unchanged — `is_lookup` (search.py:484-499),
  z_gate 3.0 fusion (search.py:261, :346-353), deterministic pack build, must-fact checklists,
  co-mention/import candidate edges, R3's deterministic split rules. Tier-0 never consults anything.
- **`LocalAdapterClient`** — the configured local chat endpoint (OpenAI-compatible
  `/v1/chat/completions`, 127.0.0.1 only; `[decisions] local_endpoint`; default empty ⇒ decisions
  are OFF and tier-0 answers everything), constrained to the `system-one-adapter-python` JSON
  format (typed questions, probabilities out). The **chat lease**: decision calls serialize through
  `<home>/decisions.lock` under a per-call deadline (`route_budget_ms`, default 500), so an
  ingest-time R7 batch can never starve an interactive routing call; kernel memory pressure ≥ 2
  (serve.py:164-190 sampler — the R9 §D7 shared signal) defers decision batches and tier-0 ships
  meanwhile. Calibration is OURS: Phase 1 measures the local model's probabilities on our data; if
  they are not calibrated we ship argmax+threshold or drop to tier-0.
- **`JevClient`** — TypeSafe cloud, early access. Constructed ONLY when `backend = "jev"`
  (hand-editing config is the consent act, §6). Honors the same deadline; network failures are
  `DecisionError` like any other backend failure.

## 4. Adoption points (evidence → type → tier → gate)

| # | Point | Type | Measured evidence | Tier-0 (always) | Tier-1 decision layer | Gating eval + acceptance |
|---|---|---|---|---|---|---|
| A | Query-type routing (short-keyword / long-argument / lookup) | Choice: framing ∈ {raw, search-result} | ±6.7–14 pt arguana framing swings; R5 arm deltas | `is_lookup` digit rule + production query_prompt for everything else | Asked ONLY when `not is_lookup(terms)` AND `len(terms) > route_max_terms` (8) AND the warm path allows (serve resident); deadline 500 ms | `eval_public --dataset arguana`: **nDCG@10 ≥ 0.56**; golden 146 `eval_real --gate` unchanged |
| B | Pack sufficiency / calibrated abstention | Noul(question, pack) | R4 traps 8/8 (uncalibrated); ans-009/010 1-not-2 borderline | No check (pack ships; honest zero-hit footer as today) | `search --pack --check`: footer/meta `sufficiency: {prob, backend}`; advisory, never blocks | R4 set: trap refusal maintained (8/8) AND answerable questions not over-refused (both rates measured) |
| C | R4 grader checks (per must-fact) | Noul × must-facts | grader_flip 0.05 | GLM blind grader (pack-eval D11/D14 protocol unchanged) | DecisionClient grades each must-fact check in one batch | A/B on the double-graded set: agreement **≥ 0.9** vs GLM; only then may it replace/augment |
| D | R7 edge verification | Noul per candidate edge | extraction-quality-gates-everything | Co-mention / git-import candidate generation; edges stay `unverified` | Batched per-file verification at ingest; evidence backpointer unchanged | Human-audited labeled sample: precision **≥ 0.9**; decisions unavailable ⇒ candidates ship unverified, search never blocks |
| E | R3 decomposition orchestration | Choice + Score | R3's multi-hop completion standard | Deterministic split rules, always available | "Needs decomposition? Which strategy?" + Score-orders rule-generated sub-queries | R3's own eval: R4-style answer uplift on 10 multi-hop questions, merged beats single-shot |

Notes pinned per point:

- **A**: the option set is CLOSED at {raw, search-result} — STS (0.365) and doc-style (0.444) are
  measured catastrophes on long queries and are never offered. Routing changes only the QUERY-side
  prompt; the stored-vector fingerprint is keyed on the document prompt (DESIGN_DECISIONS §8), so
  no reindex — `meta.query_framing_v` records the policy for provenance only. The ambiguity gate
  keys on term count (arguana mean 194 words ⇒ always ambiguous; the golden set's short queries
  never pay the 500 ms budget).
- **B**: `--check` asks ONE Noul over the built pack; the pack's BYTES are untouched (D12) — the
  signal lives in `--json` meta and the stderr footer, so pack-eval D10 determinism holds.
- **C**: the audit trade-off, explicit: Noul returns no spans, so decision-layer grading loses the
  GLM grader's per-fact quotes. `quote` becomes a nullable provenance field (the r6
  `llm_title/llm_summary/llm_model` DDL pattern); audit-grade runs keep GLM, throughput runs may
  use the decision layer — never mixed silently, the grader identity lives in the baseline
  fingerprints (pack-eval D13).
- **D**: Jev verifies, it does not discover — candidate recall stays a tier-0 heuristic problem;
  the decision layer only kills wrong candidates. Ingest-time batches defer under pressure (§3).
- **E**: sub-query TEXT generation is never a decision-layer job (no free text, by construction);
  the chat model drafts sub-queries exactly as the agent does today; the layer gates and ranks.

## 5. Explicitly rejected (with the reason)

- **Retrieval scoring itself.** z-fusion is statistical, measured, and fast (116 ms warm,
  search.py:346-353); a probability head cannot reproduce it and would blow the budget. The
  decision layer may pick the *framing* (A) — never the score.
- **serve/watch lifecycle decisions.** Power holds are pmset probes with measured parse rules
  (R9 §D6); pressure coexistence is a kernel signal shared by both daemons (R9 §D7). Deterministic,
  cheap, already reviewed — nothing to judge.
- **Distill clustering math.** τ calibration and leader clustering are deterministic and
  byte-stable (r6 D14); an ML judge inside would break the offline canary's reproducibility for no
  measured gain.

## 6. Privacy and permission policy (hard)

1. Default `backend = "local"`: with no `local_endpoint` configured, **no decision call exists** —
   zero egress, tier-0 answers. With a local endpoint, text goes only to the user's own 127.0.0.1
   process. The 铁律 (一切本地) is preserved by construction.
2. `backend = "jev"` is an explicit opt-in: hand-editing config IS the consent; on the first network
   call of each session goldmine prints a consent notice to stderr naming **TypeSafe AI as
   processor** and what leaves the machine (query text, pack excerpts, must-fact checks);
   `goldmine doctor` gains a `decisions` row always showing backend + endpoint; `--decisions
   local|jev|off` overrides for one invocation (flag > config, SPEC §10). The API key is referenced
   by ENV-VAR NAME only (`jev_api_key_env`), never stored in config.
3. **Evals may use `jev` freely** — they run on public, sha-pinned data (BEIR zips, the goldmine
   repo's own docs) with no user data. This is exactly where Phase 1 measures whether Jev's
   calibration is real before it is ever offered at runtime.

| Phase | Ships | Runtime impact | Gate |
|---|---|---|---|
| **P1 — eval-only** | `JevClient` inside `scripts/eval_*` harnesses only: (1) grader A/B vs GLM on the double-graded R4 set; (2) abstention calibration study on the R4 trap set + R5 data; (3) framing-Choice study on arguana + the golden 146; (4) the same protocol over the local adapter model | none (no `goldmine/` product code, no cron/CI wiring) | studies RECORD results (evals/ sidecars); vendor claims measured on OUR data; stability + agreement numbers decide P2 defaults |

| **P3 — ingest-time + orchestration** | Adoption points D (R7) and E (R3); B ships when P1's abstention study passes | ingest-time batches (pressure-deferred) + R3 | audited precision ≥ 0.9 (D); R3 multi-hop uplift (E); B's two-rate gate |

## 8. Risks

| Risk | Mitigation |
|---|---|
| Vendor young (2026-09-15), cloud-only, early access; category volatility (Microsoft et al.) | The interface (D1) is the product; JevClient is a plugin; the adapter keeps the format if the vendor folds or the category standardizes elsewhere |
| Calibration is self-reported (RLCD) | P1 measures it on OUR data before any runtime offering; local-adapter calibration is ours too |
| Latency 70–500 ms vs 116 ms warm search | Ambiguity-gated invocation (A), one batched request per command (D1), 500 ms deadline with tier-0 fallback, local adapter default |
| No text generation from decision models | Generation stays with the chat model (B/C/D/E are all gate/rank/verify); goldmine never wanted to generate (铁律: no chatbot) |
| Privacy drift (someone wires jev into a default) | Construction-only-under-config test (§9), consent notice, doctor row; the layering rule means the worst case is quality, never correctness |
| Local small-model probabilities uncalibrated | P2 ships only what P1 measured; otherwise argmax+threshold or tier-0 (D2) |

## 9. Test plan sketch

1. **Contract tests** (`tests/test_decisions.py`): `FakeDecisionClient` with canned deterministic
   results; every op's typed shape; malformed backend output → `DecisionError`;
   timeout/unavailable → tier-0 fallback with `fallback_reason` populated; `ask([...])` issues ONE
   wire request and matches the N single calls semantically.
2. **Tier-0 equivalence**: with decisions off/unavailable/deferred, `search`, `search --pack` and
   `--json` outputs are **byte-identical** to today (the R9 zero-change discipline; pins D12's
   "never mutates deterministic artifacts").
3. **Latency budget**: ambiguity-gate unit tests (which queries invoke, which never); invocation
   counter (a long golden query = exactly 1 request); a fake client sleeping past the deadline →
   tier-0 result ships and the latency is recorded; pressure ≥ 2 defers (sampler injectable, the
   R9 test discipline).
4. **A/B harness specs**: grader agreement protocol (double-graded set, ≥ 0.9 gate); abstention
   two-rate protocol (trap refusal kept, over-refusal ≈ 0); routing A/B (`eval_public --dataset
   arguana` + `eval_real --gate`).
5. **Privacy**: default config constructs no network client (socket-use assertion); jev opt-in
   asserts the consent notice fires and the egress payload is exactly the typed decision request;
   the key is referenced by env-var name only.
