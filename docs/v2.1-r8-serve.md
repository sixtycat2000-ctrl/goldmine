# v2.1 R8 — `goldmine serve`: the warm-search daemon (C4 + F5 implementation spec)

> Implementation-ready spec for ROADMAP R8 (秒回搜索): model resident 5 min, searches
> < 300 ms warm (today ~2 s cold), yields under memory pressure, never restart-flaps.
> Owns REDESIGN.md §5 rows **C4** (daemon) + **F5** (status/doctor/security face) of the
> v2.1 phase. Substrate contract: 05 §4.4; perf budget: 04 §6.3 (as amended by B3);
> UX face: 03 §5.4. Where this spec deviates from those sections, §11 lists the deviation
> and the reason — those lists are the reconciliation record for the owning docs.
>
> Status: spec (no code). Everything cites current code `file:line` on the R4-green
> baseline (784 offline + 15 live tests).

## 1. G0 gate — measured (REDESIGN §5, review C7: "before ANY daemon work")

Ran against the live R4 index `evals/eval.sqlite` (2026-10-19):

```
files=332  segments=2,533  vectors=2,030  vec_bytes=3,118,080 (~3.0 MB fp16)
```

**Consequences, binding for this build:**

1. `load_vectors` at this size is single-digit ms — the daemon must keep **the model**
   warm; the vector side needs nothing new. `Store`'s existing VectorTable cache
   (store.py:291-293, keyed on write-generation + `PRAGMA data_version`, store.py:600-613)
   already gives the *client* a warm cache with correct cross-process invalidation.
2. Pack (C3) not built. If a future corpus crosses 250k vectors, C3 lands per its own row
   and plugs in behind `Store.load_vectors` without protocol changes.
3. The warm-path budget (§2) is dominated by process start + query embed, not scan — so
   the daemon is an **embed/tokenize RPC over a resident llama-server**, nothing else.

## 3. Decisions (each pinned, with rationale)

### D1 — Ownership model & the client seam: `RemoteBackend(EmbeddingBackend)` in `goldmine/backends/serve.py`

- **`goldmine serve` owns one `LlamaServerBackend`** (llama.py:217), constructed with the
  daemon's own `LlamaCfg` — spawn/health/dim-probe/kill rules are *inherited verbatim*
  (never adopt a foreign server llama.py:430-432; SIGTERM→5 s→SIGKILL only our child
  llama.py:473-497; the `_start_lock` llama.py:389-392 already makes lazy concurrent
  spawn safe). Clients **never** kill it: `RemoteBackend.close()` closes the socket and
  nothing else (pinned test §9.1-T19).
- **One daemon, no index state.** The daemon never opens SQLite. Vectors stay in client
  memory (client-side `Store.load_vectors`), search math stays in `search.py`. This is
  why A3's transactional index-generation concern and B4's pack_epoch are **N/A** for R8
  (as the review amendments anticipated) and why flock contention with ingest writers
  does not exist (ingest keeps its own cold-spawned server, exactly today's path).
- **Client seam = the ABC.** `RemoteBackend` implements `EmbeddingBackend`
  (backends/base.py:74) so `Searcher` needs **zero changes** (search.py consumes only the
  ABC; embed call site search.py:321). The ABC surface fits — verified mapping:

  | ABC member (base.py) | RemoteBackend implementation |
  |---|---|
  | `backend_id` | `"llama"` (constant) — **load-bearing**: `fp_build` (fingerprints.py:54-76) keys the fingerprint on it; the fingerprint gate then compares byte-identically with cold |
  | `prompts_doc_template` | **not overridden** — inherits base default (base.py:89) = llama's; `live_embed_identity` (fingerprints.py:305-330) identical to cold |
  | `dim` (property, :91) | 768 from the handshake `info` |
  | `capability()` (:102) | text-only, computed locally, no round trip |
  | `max_input_tokens()` (:104) | daemon `cfg.ctx` from `info` |
  | `count_tokens(texts)` (:113) | op `count_tokens` → resident backend's exact `/tokenize` path (llama.py:536) — D3 chunking and C7 pack budgets keep working warm |
  | `token_pieces(text)` (:123) | op `token_pieces` (llama.py:553) |
  | `fingerprint_fields()` (:131) | the daemon's `LlamaServerBackend.fingerprint_fields()` (llama.py:273-283), fetched once in the handshake — gate math byte-identical (§6) |
  | `embed_texts(texts)` (:135) | op `embed`, batched client-side by `cfg.batch` exactly like llama.py:658-667; rows already L2-normalized server-side by the same `_l2_normalize` (per-row op ⇒ identical result to cold's batch normalize) |
  | `embed_image` / `embed_audio_wav` (:139/:143) | raise `NotSupported` locally (llama is text-only; copy the llama.py:669-679 messages verbatim) |
  | `describe()` (:147) | serve-flavored dict (`via: serve`, socket, daemon pid/version) — only reaches `status`/`backends` if a caller wires it; none do in R8 |
  | `startup()` (:150) | the connect+handshake itself; idempotent |
  | `close()` (:156) | close socket only; **never** signals the daemon |
  | `shutdown()` (:153) | alias, unchanged |

- **Where the seam lives (the one deliberate cli.py change):** `cmd_search`'s backend
  acquisition (cli.py:512-534) goes through a new `goldmine/backends/serve.py::
  connect_or_cold(cfg, name) -> tuple[EmbeddingBackend | None, str]` returning
  `(backend, via)` with `via ∈ {"serve", "cold"}`. Order: non-llama `--backend` or
  `--no-serve` or `--lexical` → cold path untouched → else discovery (§5) → connect →
  handshake (§6) → `RemoteBackend`; **any** failure (no file, dead pid, connect refused,
  proto/version mismatch, model drift, EOF mid-handshake, timeout) → cold construction +
  one stderr notice when a daemon *was* found but unusable (silent when simply absent).
  Net cli.py delta ≈ +25 lines; ingest/distill/backends/doctor keep `_make_backend`
  (cli.py:116) and stay byte-identical. The close discipline at cli.py:579-583 works
  unchanged (`RemoteBackend.close()` is cheap and side-effect-free).

### D2 — Wire protocol: line-JSON over UDS

- Transport: `AF_UNIX` `SOCK_STREAM` at `$TMPDIR/goldmine-serve-<uid>/serve.sock`
  (05 §4.4 placement stands: `sun_path` ≤ 104 bytes — verified the macOS
  `/var/folders/…/T` TMPDIR keeps a ~70-char path). One JSON object per line, UTF-8,
  `\n`-terminated. Thread per connection; the resident backend serializes llama-server
  access through its own lock/HTTP path (2 slots, llama.py:61).
- Every request: `{"op": str, "id": str?, ...params}`. Every response:
  `{"ok": true, "op": ..., "id": <echoed when sent>, ...result}` or
  `{"ok": false, "op": ..., "id": ?, "error": {"kind": str, "message": str, "tail": str}}`.
  `tail` carries the llama-server stderr ring (llama.py:290-292) so a warm-path embed
  failure renders with the same evidence a cold failure would (03 §5.7 honesty).
  Error `kind` vocabulary: `bad_request` | `model_not_resident` | `embed_failed` |
  `tokenize_failed` | `overloaded` (guard cooldown, §7) | `internal`.
- **Ops (v2.1 set — the minimal one; `search`/`reload`/`checkpoint` deliberately absent,
  §0/§11):**

  | request | response payload | notes |
  |---|---|---|
  | `ping` | `{"proto": 1, "goldmine_version": …, "pid": …, "uptime_s": …}` | liveness + version |
  | `info` | `{"fingerprint_fields": {model_id, model_sha256, dim, prompts, pooling, normalization}, "backend_id": "llama", "dim": 768, "capability": {text,image,audio}, "max_input_tokens": ctx, "model_path": str, "resident": bool}` | the handshake payload; fields are the daemon backend's own, so `fp_build` output is byte-identical to cold |
  | `embed` `{texts: [str]}` | `{"vectors": [[f32…], …], "dim": 768}` | rows L2-normalized server-side; ≤ 64 texts/request (hard cap → `bad_request`), each ≤ 1 MiB chars; f32→JSON→f32 is exact (repr round-trip) and pinned byte-equal to cold by test |
  | `count_tokens` `{texts}` | `{"counts": [int]}` | daemon may answer `model_not_resident` while guard-cooling (§7) |
  | `token_pieces` `{text}` | `{"pieces": [[int…], …]}` | byte arrays, llama.py:553-580 contract |
  | `status` | `{"pid", "uptime_s", "goldmine_version", "proto", "socket", "model_sha256", "resident", "child_pid", "clients": [{pid, connected_s, last_req_s}], "linger_remaining_s", "guard": {"level": 1|2|3, "sampled_age_s", "state": "normal|cooldown", "unloads": n}}` | faces `serve status` / doctor |
  | `shutdown` | `{"stopping": true}` then EOF | graceful exit path (§7) |

- `id` is echoed and correlated but v2.1 implements **no server-side supersede** — with
  no `search` op there is nothing to cancel; C3's stale-query `id` machinery stays
  protocol-ready for find (§11 deviation note).
- **Deadlines:** client-side only. Per-request socket timeout = `serve.timeout_s`
  (default 10 s; embed of a 16-text batch is ~20 ms — 500× headroom). Client
  retry-once on transient (EOF/refused/reset mid-request), mirroring llama.py:582-595's
  discipline, then cold fallback. Server: 30 s recv idler per connection, then close.
- **Frames:** server rejects any line > 16 MiB (`MAX_LINE`) and any undecodable line by
  closing that connection (client: transient → retry → cold). Malformed JSON line →
  `bad_request` response, connection stays open (fuzz-lite target, §9.1-T24).

### D3 — Lifecycle: flock, discovery, linger, signals, auto-start

- **Single instance:** `flock(LOCK_EX | LOCK_NB)` on `<home>/serve.lock`
  (resolve_home(cfg), config.py:131). Second `goldmine serve` prints
  `already serving (pid N)` → exit 0. The lock file is never deleted (kernel holds the
  lease; deleting races).
- **Discovery file** `<home>/serve.json`, written atomic (tmp + `os.replace`), removed on
  every clean exit:
  ```json
  {"proto": 1, "goldmine_version": "…", "pid": 1234, "socket": "<abs path>",
   "started_at": 1760000000.0, "model_sha256": "…", "model_path": "…",
   "children": [{"pid": 1235, "kind": "llama-server", "port": 51234}]}
  ```
  `children` is the **spawn receipt**: 05 §4.4's orphan rule (kill only what we spawned,
  extended with the recorded pid) — `serve start` and doctor kill a recorded child whose
  daemon pid is dead (`os.kill(daemon_pid, 0)` fails → SIGTERM→5 s→SIGKILL the child by
  exact pid, never name-matching). llama-server itself has no stdin-EOF guarantee at
  b11461, so the receipt-sweep is the SIGKILL-orphan guarantee; llama.py's spawn argv is
  not touched for it.
- **Client detection order** (each step fails soft): `GOLDMINE_SERVE` env (explicit
  socket path, env-audit entry) → `<home>/serve.json` → `pid` liveness `kill(pid,0)` →
  connect → `ping` proto/goldmine_version check (major-ish skew: any `proto` mismatch, or
  a daemon from a different `goldmine_version` → unusable) → `info` model-drift check
  (§6). Stale files are ignored by clients and **swept** (socket `unlink`, json delete)
  by the next successful `serve start`; clients never delete (read-only discipline).
- **Linger:** default 300 s (`serve.linger`, `--linger S`), any request refreshes. Zero
  connected clients + idle timer expiry → graceful shutdown (same path as SIGTERM).
- **Signals:** SIGTERM/SIGINT → stop accepting, finish in-flight requests (bounded 10 s),
  close backend (kills llama-server), unlink socket, delete serve.json, exit 0. SIGKILL →
  crash-only statelessness: stale discovery (dead pid) + stale socket + orphaned child,
  all three handled above.
- **Memory guard — pressure-aware, hysteresis, never free pages (B3, amended with the
  measured signal):**
  - Signal: `sysctl kern.memorystatus_vm_pressure_level` → **1 normal / 2 warn /
    3 critical** (the kernel's own pressure level). Measured on this machine: the
    `memory_pressure` binary's `-Q` prints **"System-wide memory free percentage: 47%"**
    on a healthy box — the free-pages/free-% trap B3 named, so that parser is rejected
    in favor of the kernel level. Read via `/usr/sbin/sysctl -n` subprocess, **cached
    30 s** (a cold sample costs ~10–20 ms and would eat the warm budget if sampled
    per-request; 04 §6.3's "before each search" is amended to "before each *model (re)spawn
    decision* + every 60 s idle + lazily on request when the cache is stale").
  - **warn (2) sustained** = two warn-or-worse readings ≥ 30 s apart → **unload**: close
    the backend (kills llama-server, frees ~484 MB), daemon stays up, enter **cooldown
    120 s** during which `embed`/`count_tokens`/`token_pieces` answer `model_not_resident`
    → the requesting client cold-falls-back (a one-shot's own 484 MB child dies at command
    end — strictly better under pressure than permanent residency). Resume residency only
    after a normal (1) reading past cooldown. This is the 不反复重启 guarantee: at most one
    unload per sustained-pressure episode.
  - **critical (3) sustained** = two critical readings ≥ 30 s apart → graceful exit 0
    (full cleanup). Never exit on a single reading, never on raw free anything.
  - Guard state is visible in `status` (`unloads` counter, last level) — 03 §5.4's
    "announce the guard exit" is the client-side notice: after a cold fallback where
    serve.json shows a recent guard exit, stderr prints
    `serve exited under memory pressure; using cold` once.
- **Auto-start: ships, default OFF** (`serve.auto = false`). When true and no live daemon
  answers, cmd_search spawns `python -m goldmine serve --linger` detached
  (`start_new_session=True`, stdio DEVNULL), waits ≤ 2 s for discovery + connect, else
  cold for this query with footer `via: cold`. Rationale for OFF default: 03 §1's
  "no daemon you didn't ask for" outranks saving one 0.7 s start; R8's story is delivered
  by `goldmine serve` + `serve.auto=true` documented in `help serve`. This is the
  re-ratification REDESIGN Q1/05 §7 q1 asked for at C4 acceptance — ON-with-opt-outs is
  amended to opt-in, recorded in §11. launchd (`G9`) stays out; linger makes KeepAlive a
  lie (05 §4.4's own note).

### D4 — Model/index multiplexing: `models_resident = 1`, model-sha check at the seam

- One llama-server per daemon, resolved from the daemon's config (same resolution order
  as cold, llama.py:120-179). **Per-index/per-client state in the daemon: none** beyond
  the connection registry `{client_pid, connected_s, last_req_s}` used for `status` and
  linger — the 05 §4.4 lease table collapses to this because the daemon holds no
  indexes. `serve.models_resident` (G10) is explicitly not built; `model use` UX is G10's.
- **Drift check at the seam (the correctness core):** handshake requires
  `info.model_path == str(resolve_model_path(cfg.llama))` (cheap stat-based, no hashing)
  AND `info.model_sha256 == <client sidecar sha>` **when the client's `<model>.sha256`
  sidecar is valid** (llama.py:246-271's cache — the common case after first ingest;
  a sidecar miss defers to the fingerprint gate, which remains the backstop: a truly
  different model produces `fingerprint_mismatch` exit 3 exactly as cold would,
  cli.py:192-206). Mismatch → cold fallback + one stderr line
  `serve: model drift (serve <sha8> ≠ local <sha8>) — using cold`. Warm and cold search
  are therefore **semantically indistinguishable**, which is the zero-search.py-changes
  contract made testable (§9.1-T6).

### D5 — Security

- Socket dir `$TMPDIR/goldmine-serve-<uid>/` created `mkdir(0o700)`, **verified** on
  every start and every client connect (`stat` mode == 0o700; else refuse-to-start /
  treat-as-absent). Socket chmod 0o600. Filesystem auth is the boundary (05 §4.4's
  single-user threat model stands).
- **No LOCAL_PEERCRED** (decided): macOS's `getsockopt(SOL_LOCAL=0, LOCAL_PEERCRED=1)`
  returns an undocumented `kinfo_proc` blob (probed: errors on the listen socket, needs
  the accepted socket + non-public struct parsing) to re-prove what the 0700 dir already
  guarantees. Cost/benefit fails; documented in `help serve`. Revisit only if the socket
  ever moves out of a per-uid directory.
- Tailscale/VPN note (03 §5.4 copy): a UDS has no network exposure at all;
  llama-server binds 127.0.0.1 on an ephemeral port exactly as v1 (llama.py:361) and is
  inherited, never widened. `doctor`'s existing non-loopback warning posture unchanged.
- `shutdown` is callable by any same-uid local process — accepted (worst case a 0.7 s
  respawn); documented, not defended.
- Caps: §D2's 16 MiB line / 64 texts / 1 MiB-per-text bounds are the DoS story; a hostile
  same-uid peer is out of threat model.

### D6 — UX surface (03 §5.4 face)

- **`goldmine serve [--linger S]`** — foreground. Startup stderr line:
  `goldmine serve: pid N · <socket> · linger 300s · guard armed (warn→unload / critical→exit)`.
  llama-server spawns **lazily on first embed** (faster start, honest idle = 0 model MB).
- **`goldmine serve status [--json]`** — human:
  ```
  serve: running · pid 1234 · up 0:12:31 · goldmine 2.1.0
    model: embeddinggemma-2-Q8_0 (sha 2188ac1d…) · resident · ~484 MB class
    clients: 1 · linger 4:32 left · pressure: normal (level 1, 12s ago) · unloads 0
  ```
  plus the memory-honesty line from 03 §5.4 (B15c): "the model server ~484 MB; index
  pages live in reclaimable file cache". `--json` = `{"schema": "goldmine/1",
  "command": "serve-status", …status payload}` via the `_envelope` builder (cli.py:124).
  Not running → `serve: not running` exit 0 + hint `goldmine serve` / `serve.auto=true`.
- **`goldmine serve stop`** — `shutdown` op; fallback SIGTERM via serve.json pid; verify
  discovery cleanup; not-running → honest `not running`, exit 0.
- **Doctor row `serve daemon`** (doctor.py:613-660 `run_checks` list): ok = running
  (pid/uptime/resident); warn = not running ("optional — start: goldmine serve");
  warn = stale discovery file (dead pid N — will self-heal); warn = version-skewed daemon.
  Never FAIL: the daemon is optional by construction.
- **`via:` footer:** one stderr line after every semantic search:
  `via: serve (0.18s)` / `via: cold (1.94s)` — stderr because search's stdout is
  data-only in both human and `--json` modes (SPEC §1.2; `render_hits` stdout stays
  byte-stable, render.py:79). 03 §5.4's "footer" is hereby pinned to stderr (§11).
  Latency = `time.monotonic()` around backend-acquisition→hits.
- **`help serve` topic** (help.py:12 `TOPICS`): lifecycle, `serve.auto`/`linger` config,
  the security note verbatim from 03 §5.4 (0600 UDS under per-uid TMPDIR, 127.0.0.1-only
  server, Tailscale non-exposure), the 484 MB honesty copy, cold-fallback promise
  ("serve problems can never break search — worst case it is slow once").

## 5. Lifecycle state machine (normative)

```
           flock ok?                      discovery write          accept loop
serve ────────────────► IDLE(all) ──lazy first embed──► RESIDENT ────────────────►…
  │ already: exit 0         │  ▲    ▲ guard resume        │  │
  │                         │  │    └──────────────────────┘  ├─ SIGTERM/SIGINT/linger/
  │                         │  └─ embed request             │  │ shutdown op → DRAIN(≤10s)
  │                         │     after cooldown            │  ▼
  │                         └──── guard warn unload ────────┘ SHUTDOWN: close backend →
  │                                                          unlink sock, rm serve.json,
  SIGKILL at any point → stale json/socket (next start sweeps) + receipt-kill child
```

Client: `absent → cold` · `stale → notice? cold` · `handshake-fail → notice, cold` ·
`ok → serve` · `mid-search failure → retry-once → cold, results still delivered`
(a serve failure must degrade latency, never lose the query — the §0 invariant).

## 6. Handshake sequence (normative, one call site)

```
connect_or_cold(cfg, name):
  name != llama or no-serve or lexical      → (cold_backend, "cold")
  discover(): env GOLDMINE_SERVE → serve.json
    liveness: kill(pid,0) + dir 0700 + connect(0.5s)
  ping   → proto==1 and goldmine_version==__version__ else unusable
  info   → model_path match AND (sidecar-sha match when client sidecar valid)   [§D4]
         → build RemoteBackend; fingerprint_fields/dim/capability cached from info
  any failure → LlamaServerBackend(cfg.llama) (cold, exactly cmd_search today)
```

The fingerprint gate (cli.py:536-540) then runs unchanged over `RemoteBackend` — its
`fp_build` output equals cold's by construction (§D1 table), pinned by test T6.

## 10. Deviations from the owning docs (for back-port)

1. **No `search`/`reload`/`checkpoint`/`hello` ops** (05 §4.4 step 4): G0's 2,030-vector
   corpus makes server-side search worthless; hello folds into `ping`+`info`;
   checkpoint is irrelevant (daemon holds no DB handle). C3 `id`-supersede becomes
   protocol-reserved only.
2. **Auto-start default OFF** (05 §4.4 "decided ON", REDESIGN Q1): re-ratified as opt-in
   `serve.auto=true`; the ON rationale (second-search benefit) now ships as one
   documented config line instead of silent residency.
3. **Guard signal = kernel pressure level** (`kern.memorystatus_vm_pressure_level`), not
   a parsed "memory-pressure percentage" (04 §6.3): the measured `memory_pressure -Q`
   prints only a free percentage (B3's trap); the kernel level with 2×30 s hysteresis is
   the same decision tree with a real signal. Sampling cadence amended to cached-30 s
   (a per-request spawn of any sampler costs 10–20 ms — real money at a 300 ms budget).
4. **`via:` on stderr**, not a stdout footer line (03 §5.4): search stdout is
   data-only/human-render-only today; adding a stdout footer would change the output
   contract for every existing consumer.
5. **Leases collapsed to a connection registry** (05 §4.4): with zero index state there
   is nothing to lease; G10's multi-model LRU reintroduces the real table.

## 12. Review amendments (2026-10-19, adversarial review — binding, pre-implementation)

Ten findings amend the sections above. Where an amendment contradicts an earlier
section, **this section wins**. All ten are absorbed into the R8 build.

### F1 (HIGH) — the <300 ms gate is END-TO-END

The gate is measured over **≥ 20 fresh `python3 -m goldmine.cli search …` subprocess
wall clocks** (p50) with the daemon resident and the model loaded. In-process timers and
the `via:` footer number are **reporting only**, never the gate. The bench is
guard-aware: if the pressure level is ≥ 2 at bench start, or the guard unloads the model
mid-run, it prints `skipped: pressure level N` — advisory, **not** a failure. `help
serve` documents that on a 16 GB dev box level-2 is ordinary during builds (residency
yields until the level returns to 1). Amends §2/§7.3 (bench definition) and D6 (footer
semantics). Build note: the sampler accepts a documented determinism pin
(`GOLDMINE_SERVE_PRESSURE_LEVEL=1|2|3`, read ONLY by `default_pressure_sampler`) so the
guard tests — and an operator who explicitly opts out of the yield for a run — are not
at the mercy of the box's ordinary build-time pressure; the default (no pin) always
reads the real kernel level, and the bench prints a loud note whenever it runs pinned.

### F2 (HIGH) — daemon hashes the model FRESH at spawn; honest residual

The daemon computes the model **sha256 fresh from the file bytes** (~0.4–1 s for the
310 MB GGUF) and uses THAT hash in `info.fingerprint_fields` and `serve.json` — never a
client-visible sidecar value. The client compares its own `<model>.sha256` sidecar sha
against the daemon's fresh hash in the drift check. **Stated residual (honest, out of
scope):** a stale-but-size/mtime-valid CLIENT sidecar can still pass the cold path too —
that is a pre-existing `llama.py:246-271` property, not introduced or solved by R8; R8
does not claim to fix it. Implementation note: the fresh hash is computed at **daemon
start** (before the first connection is accepted) rather than at llama-server child
spawn, so `info`/`serve.json` are complete from the very first handshake; the ~0.5 s
cost lands in `goldmine serve` startup (invisible to searches) instead of inside the
spawn budget. Amends D4.

### F3 (MEDIUM) — receipt sweep is verify-before-kill

The `children` receipt in `serve.json` is written **immediately after `Popen`** (before
the health wait — a crash during startup must still leave a receipt) and carries the
child's **process start-time** (`ps -o lstart=`) and procname (`ps -o comm=`) alongside
pid+port. The sweep (run by the next successful `serve start`, which holds the flock and
therefore knows the previous daemon is dead) kills a recorded child only after
verifying the pid's CURRENT start-time matches the receipt (pid-reuse guard);
start-time unavailable → procname match; neither → **do not kill, report**. Kill
discipline stays SIGTERM → 5 s → SIGKILL by exact pid, never name-matching. Field
evidence: this machine carried a real 484 MB orphan (killed 2026-10-18) from a pre-fix
test wave. Deviation from D3's "`serve start` **and doctor** kill": doctor only ever
REPORTS the stale receipt (doctor's own contract: never fixes); the sweep runs in
`serve start` (and `serve stop` falls back to a verified-SIGTERM of the daemon pid, with
the same start-time check recorded for the daemon itself). Amends D3/D6.

### F4 (MEDIUM) — honest memory-yield copy

`help serve` and `serve status` (and the doctor row for a yielded daemon) say, in
words, what actually happens: **"under memory pressure the model steps aside and stays
aside until the system recovers (last unload: <time>, current level: N)"** — not a bare
`not resident` flag. Amends D3/D6.

### F5 (MEDIUM) — guard unload does not wait for in-flight embeds

The guard's unload closes the backend immediately; an in-flight embed fails mid-request.
The client treats any mid-request daemon error as **retry-once → cold fallback** (a
`model_not_resident` answer is deterministic — no retry, straight to cold). A
`--delay`ed embed that loses the model mid-request still delivers intact results with
**exactly one stderr notice**. Amends D3 (guard action) and D2 (deadline/retry
discipline).

### F6 (LOW) — caps coherent

Embed caps: **64 texts AND 256 KiB per text** (UTF-8 bytes), both under the 16 MiB line
cap. When both are violated the **text-count error wins** (count is validated first).
Documented in `help serve`. (Honest corner: a single request of 64 × 256 KiB plus JSON
escaping can exceed the 16 MiB line cap — the line cap then closes the connection and
the client cold-falls-back; the caps bound well-formed peers, the line cap is the hard
wall.) Amends D2/D5.

### F7 (LOW) — linger refreshes only on model-touching ops

`embed` and `count_tokens` refresh the linger timer; `ping`/`status`/`shutdown` do
**not**. A status poller cannot keep a daemon alive; an idle daemon with zero
model-touching ops exits after the linger window. (`token_pieces` would have been
model-touching; it is cut by F9.) Amends D3.

### F8 (LOW) — client pid on the wire

The client's `ping` request carries its `pid` (the client sends `pid` on every request;
the daemon records the latest per connection), and the `status` op reports the clients
registry `{pid, connected_s, last_req_s}`. Amends D2.

### F9 (LOW) — scope cuts

- **`token_pieces` op CUT** (chunker-only caller; ingest stays cold in R8): the daemon
  does not implement it and `RemoteBackend.token_pieces()` returns `None` (the chunker's
  estimator fallback) — moves to **G6** with the ingest-lease work.
- **`describe()` serve flavor = stub** (returns a minimal dict pointing at `goldmine
  serve status`); no caller wires it in R8.
- **`serve.auto` config key CUT entirely** from this build (auto-start moves to **G9**):
  no dead config path is shipped untested. Starting the daemon is the explicit
  `goldmine serve`; `help serve` says so. Amends D3 (auto-start), D6 (describe), D7
  (config), and the D1 table (token_pieces).

### F10 (LOW) — stale citations + cross-batch byte-equality

The spec's `config.py:358-389` cite for env reads is refreshed by the build: env reads
live in `config.load()`'s env-override block (config.py:379-407 on the R6-green
baseline) and `GOLDMINE_SERVE` is added there. The T8 byte-equality test gains a
**cross-batch case** (20 texts, batch 16 → 16+4) proving serve and cold produce
byte-identical matrices across batch boundaries (both sides batch identically; L2
normalization is a per-row op, so batch boundaries cannot change a row — the test pins
that claim). Amends §7.1 T8.
