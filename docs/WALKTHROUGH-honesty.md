# 第四讲：诚实契约 — 这个项目的"宪法"

> 轮讲第四讲（2026-10-25）。不是单个模块，是横切全部模块的一条设计
> 纪律：**宁可少说，不可说谎；宁可报 UNKNOWN，不可装知道**。读完应能
> 答文末十问。

## 0. 契约的七条正文

1. **能力行不说谎**：每个文件四选一——content_indexed（真读真嵌）/
   metadata_only（只有名字可搜，原因写明：OCR 缺、ffmpeg 缺、后端无图
   嵌入……）/ unsupported（刻意不读：密钥、许可、构建目录——带原因）/
   failed（试了没成——带原因）。没有"差不多算读过了"这一栏。
2. **零命中是合法答案**：`nothing found` + 一条下一步建议，退出码 **0**。
   噪音查询（乱打的词）正确答案就是零——评测里有专门的 zero-hit
   honesty 指标（当前 1.0）。
3. **指纹不符就拒绝服务**：exit 3（第二讲），绝不混着旧向量答分。
   `--lexical` 是明示的逃生门，不是偷偷降级。
4. **降级必须大声**：estimate 缺 pdfinfo 时明说"按 10 页/PDF 估的"；
   后端不支持图片时 NotSupported 直说；watch 后端没起来时报告里写
   reason。没有静默的"反正也差不多"。
5. **不可读 ≠ 空**（第三讲）：TCC、弹出硬盘、路径消失守卫——外部世界
   拿走的东西不许被读成"用户删光了"。
6. **部分失败是记账不是灾难**：exit 5 + 逐行失败原因；重跑续传。
7. **证据三态**（记录层）：PASS 带原始回执；FAIL 如实；证据不全记
   MISSING——"基本通过"是禁语。

## 1. 这条契约的成本与收益（为什么值得）

成本：诚实的降级路径都要写代码（每个"缺工具"分支都是一条真实路径）、
测试要多造"没有工具时"的夹具、错误信息要人话。收益：**信任可以局部
重建**——你不需要相信"全部都对"，任何一行输出都能沿一条明示的链路
查到底（能力行→原因→修法；--why→分数分解；锚点卡→亲手复跑）。大多数
项目做不到这点不是不会，是每一条静默降级都比诚实降级省二十行代码——
省到最后没人知道系统什么时候在瞎说。

## 2. 契约在代码里的锚点（改动时先看这里）

- 能力行：`goldmine/store.py` FileRec.capability + 各抽取器的 _Outcome。
- 零命中：`goldmine/commands/search.py` 渲染尾（nothing found + 建议）。
- 指纹拒：`goldmine/fingerprints.py` gate → cli exit 3。
- NotSupported：`goldmine/backends/base.py`（后端能力面，serve/mcp 的
  错误文案与 llama.py 保持逐字一致——有对照测试）。
- 不可读≠空：walk.py 的 unreachable 标志 + compute_deletions 前缀守卫。
- visual_search：application.py 的**静态探针**（helper+mmproj 能解析才
  true）——能力宣称先于服务，宣称本身不许说谎。
- 媒体诚实：MM-D3 路由标记（raw:no-transcript(asr_status) 逐行记录
  "这条音频向量为什么存在/不存在"）。

## 3. 反面案例对照（为什么这条契约是被事故教育出来的）

DigUp 事故索引（digup-derived-plan 附录）里每条都对应契约的一条：把
不可读目录当空 → 用户的行被"合法"清掉；静默用错向量家族 → 搜索结果
跨家族比分数；截断的书标 done → 最后一章永远搜不到。契约不是审美，
是事故的化石。

## 4. 腐烂风险清单

1. **新降级路径的静默化**：加新工具依赖时，"工具缺失"分支最容易被写成
   `except: pass`——契约要求写原因、测试要求覆盖缺失路径。
2. **错误文案漂移**：serve/mcp/llama 的 NotSupported 文案逐字一致是
   对照测试钉的；改一处必须三处同步（或抽公共常量）。
3. **能力宣称超前于现实**：visual_search 这类布尔必须由探针派生，不许
   手写 true。
