## 0.5 Review amendments (2026-10-19, adversarial review F1-F8 — BINDING)

These amend the sections named in each entry; where prose below conflicts, the
amendment wins. All are absorbed in the implementation and tests.

- **R-F1 (HIGH) pass-rate floor — amends D2 (cadence), §5 (pass table), §6.2
  (config), §7.3 (live).** Measured churn case: a 4 s-periodic writer on a
  10k-file root caused 58 scans + 29 cold model spawns in 10 min (68% duty).
  Fixes, all shipped:
  (a) `min_pass_gap_s` (default **25**): no embed-bearing pass (delta, sweep,
  resume) starts within this gap of the previous one — a burst coalesces across
  it (pending changes accumulate, one pass ingests the union);
  (b) **effective poll-interval floor ≥ 2× the measured last-scan duration**
  for that root (adaptive to root size: the cheap tier may never cost more
  than ~50% duty);
  (c) **battery mode caps pass frequency too** (not just batch size): on
  battery the minimum pass gap is `max(min_pass_gap_s, battery_pass_gap_s)`
  (`battery_pass_gap_s` default 120), so a periodic writer cannot spawn a
  model every 25 s on a laptop;
  (d) the live suite gains a **duty measurement**: a 10-min churn simulation
  with a 4 s-periodic writer must produce ≤ 24 backend spawns (the
  min-pass-gap bound), counted with a llama-server wrapper script (honest
  spawn log, not self-reporting).
- **R-F2 (HIGH) loop exception policy — amends D4/D5, §5, §9.** Pinned and
  implemented: *start-time refusals* are rendered BY watch (they would
  otherwise raise outside cli main's conversion): `BackendUnavailable` → the
  universal error shape, exit 4; `FingerprintMismatch` (raised by the resume
  pass's fingerprint gate) → the universal shape, exit 3, daemon stops
  (retrying every pass would be wrong — the mismatch is permanent for this
  index+backend pair). *Per-pass* `try/except`:
  `EmbeddingError` / `BackendStartupError` / `OSError` → heartbeat note +
  exponential backoff (`min_pass_gap_s × 2^(consecutive_failures−1)`, capped
  at 600 s) + **continue — the watch loop never crashes**. A pass that could
  not START (backend construction/startup failed) KEEPS its pending change set
  (retry after backoff); a pass that aborted MID-RUN clears it (the snapshot
  reflects post-pass state; failed paths resurface via content change or
  sweep). *Session poison-file dedup*: a path with a `failed` store row
  recorded by an aborted pass is poisoned at its current (size, mtime); delta
  passes skip poisoned paths unless size/mtime changed. Sweep passes re-attempt
  by design (they are the self-heal tier) — deviation noted in §11.8.
  *SIGTERM*: the daemon holds a reference to the in-flight pipeline, triggers
  `pipeline.cancelled` (the pass unwinds at the next wave boundary), and drains
  ≤ 10 s before cleanup.
- **R-F3 (MEDIUM) startup shape — amends D1, D5, §5.** Startup is an
  **ungated walk** that seeds the snapshot AND records scope (the `roots_json`
  merge, computed with `_finalize`'s exact merge shape — no backend, no
  embedding). The embed-bearing **resume pass moves to the first loop tick**
  and respects holds (it is sweep-class: on battery it waits for AC). No work
  happens outside the gating policy, ever.
- **R-F4 (MEDIUM) pmset thermal parsing — amends D6 (thermal row).** Parse by
  substring `CPU_Speed_Limit` + first following integer **regardless of
  separator** (verified shapes: clear state has NO such line and its note
  prefix is `Note:`; a throttled machine prints `CPU_Speed_Limit = 45`).
  Hold when the value is present and **0 < N < 100** — `CPU_Speed_Limit = 100`
  means full speed and must NEVER hold (the D6 "N > 0" rule would hold a
  healthy machine forever; corrected here). Fixtures = the verbatim measured
  strings + a throttled sample + `No batteries available.`; the live test
  ASSERTS the parse on this machine's real output.
- **R-F5 (MEDIUM) battery probe failure policy — amends D6, §10 (risk
  table).** `No batteries available.` ⇒ always-AC (desktop/VM — never a
  hold). ≥ **3** consecutive unparseable battery outputs ⇒ no-hold + heartbeat
  note + doctor warn (the old "defaults to held" rule would stall a desktop
  forever if `pmset` output drifted; 1-2 unparseable readings still hold,
  fail-safe toward caution).
- **R-F6 (MEDIUM) dataset-folder parity — amends D2, §5 (delta row).** Delta
  passes evaluate dataset folders against the **watch roots + snapshot** (the
  daemon runs the same `rules.dataset_folders` over the snapshot's media
  candidates with the watch roots as context, and excludes changed paths
  inside detected dataset folders from the delta pass), not against the bare
  changed-path list (where a full pass and a delta pass could classify the
  same folder differently). The sweep/resume passes keep the pipeline's own
  detection with full-parity context.
- **R-F7 (LOW) heartbeat/staleness normative — amends D4.** The heartbeat
  `state=ingesting` is written BEFORE each pass starts (a consumer reading
  `idle` during a pass is a lie); consumers (status, doctor) key staleness on
  **pid liveness**, never on heartbeat age alone.
- **R-F8 (LOW) help copy — amends D4 (help topic).** `help watch` notes that
  ephemeral `--roots` are recorded in `roots_json` (the same thing a manual
  ingest does) and may linger in `status` output after the session ends
  (pre-existing `roots_json` behavior — remove with `goldmine reset`).

## 1. Measured ground (this machine, 2026-10-19)

Every design constant below is grounded in a probe run today:

| Fact | Value | Consequence |
|---|---|---|
| Full classified scan of `~/git` (the walk tier-1 pass: `walk_files` with real rules) | **10,950 candidates · 1.20 GB · 5.2 s wall** | The scan tier is NOT free at ~/git scale — a naive "walk every poll at 5 s" would burn ~100% duty. This is why the two-tier design (§3/D2) scans on the adaptive cadence and only *ingests* on change, and why the doctor scan-cost flag (§6.4, from 02 §5.6:459-460) is a real guard, not decoration. |
| sha256 tier (`util.sha256_file`, util.py:54-62) on many small files | 47 files / 0.8 MB in 10 ms (syscall-bound, ~87 MB/s effective on that mix; hardware-sha on bulk) | A full-roots **sweep pass** (scan + sha of every candidate) at the measured corpus projects to **O(10-20 s)**. ## 2. Ground rules (binding)

1. **Scope invariant is a hard rule** (ROADMAP.md:56-57): watch never scans, walks, or
   ingests anything the user did not explicitly name — default scope is exactly
   `[init] roots` (config.py:96-102, the record "NEVER populated by any default sweep");
   `--roots` on the command line is the only other legitimate source, because typing it
   is the same explicit act as `goldmine ingest <path>`.
2. **Zero behavior change to non-watch commands**: `search`/`status`/`doctor`/`ingest`
   keep their output bytes; the one pipeline touch is a default-preserving keyword
   parameter (§5/D3, deviation §11.1). `store.py`, `search.py`, `serve.py`,
   `render.py`, `output.py`: 0 lines.
3. **Crash-only** (05 §4.4:501-514 posture): watch owns nothing that is not
   reconstructible — its snapshot rebuilds from one walk; index state is the DB's
   (per-file atomic commits, store.py:671 `replace_segments`; pending rows re-attempted,
   pipeline.py:407-408 `state != "done"` ⇒ not skipped).
4. **stdout stays data-only** (SPEC §1.2): watch is a long-running process like serve —
   all banners, per-pass summaries and stop lines go to **stderr** (§11.5 records the
   deviation from ingest's stdout summary).

## 3. Decisions (each pinned, with rationale)

### D1 — Scope resolution: config default, explicit `--roots` override, refusal on empty

- **Default roots = `cfg.init.roots`** (config.py:96-102). Empty AND no `--roots` ⇒
  watch refuses to start with the universal error shape
  (kind `watch_no_roots`, exit `EXIT_PREREQ`=4, cli.py:54): message
  "watch refused: no folders to watch", why names the invariant
  ("goldmine only follows folders you explicitly added — [init] roots is empty"),
  fixes `["goldmine init", "goldmine watch --roots <path>"]`. This is the铁律 made
  mechanical: **there is no watch run that was not explicitly scoped by the user.**
- **`--roots PATH…` replaces the default for this session** (flag > file, the standard
  precedence, SPEC §10). It is **ephemeral for `[init] roots`**: watch never writes the
  config key — `set_config_init_roots` (config.py:371-374) stays init-only ("Nothing
  else ever writes this key"). The invariant doc line in the USER_GUIDE/init copy gains
  one sentence: "watching a folder = ingesting it; `--roots` widens the *index* scope
  exactly like a manual ingest, never the *config* record."
- **Index-scope honesty**: the startup full pass (§5) runs with the pipeline's normal
  root-recording behavior, so `--roots` paths land in `meta.roots_json` once — the same
  thing a manual `goldmine ingest <path>` does (pipeline.py:593-600). Every later pass
  records nothing (D3). Rationale: files in the index must be explainable from
  `roots_json` (`status` renders it, cli.py:810-813; `reset --reindex` re-ingests it) —
  silently indexing paths the index does not own would break that chain.
- **Validation at start**: every root is `stat`-ed; a root that does not exist refuses
  the start when *no* root exists, and is otherwise warned-and-skipped per root —
  mirroring the pipeline's phantom-root semantics (pipeline.py:143-169: a bad root is a
  per-root failure, "NEVER persisted into meta roots_json"). URL-prefixed roots are
  filtered from scan scope with a one-line notice.

### D2 — Event detection: two-tier diff, DB stays ground truth via the pipeline's own sha check

**Tier 1 — the snapshot scan (cheap, no file reads, no DB).** Each cadence tick runs
`walk.walk_files(roots, code=…, exclude=…, max_file_bytes=…)` (walk.py:56-106) — the
*same* walk ingest uses, so classification, hidden-dir policy, symlink policy, size caps
and TCC notices are inherited byte-for-byte — and builds
`snapshot: {path: (size, mtime)}` from the yielded `Candidate`s (walk.py:27-31). Diff
against the previous snapshot:

| diff class | meaning | action |
|---|---|---|
| `new` (not in prev snapshot) | dropped/created file | delta pass (§5) |
| `changed` (size or mtime differs) | edited file | delta pass |
| `gone` (in prev, absent now) | deleted file | sweep trigger (§5) |

Decided against "diff against the DB directly": the DB is **ground truth only through
the pipeline's sha check** (`_skip_unchanged`, pipeline.py:392-428), and asking the DB
per path on every scan would couple the watcher to the index and still not answer "did
the *content* change" (mtime alone can't). The snapshot answers only "**who should be
re-checked**"; the sha check decides whether work happens. A snapshot false positive
costs one sha256; the dangerous failure (missing a change) is bounded by the periodic
sweep (§5), which sha-checks everything.

- **Debounce**: a scan with a non-empty `new+changed` set sleeps `settle_s` (default 2,
  02 §5.6:458 "editor temp-file churn") and re-scans once; the delta pass ingests the
  *second* scan's diff. A burst of N editor writes collapses into one pass.
- **Adaptive cadence** (G11): after any pass that found changes — and at startup — the
  interval resets to `interval_fast` (default **5 s**); each quiet scan doubles it:
  5→10→20→40→80→120 capped at `interval_slow` (default **120 s**). One knob pair,
  deterministic, fake-clock-testable. A `hold_fast_s` "stay fast for N minutes" knob
  was **rejected** as redundant: exponential decay from reset-on-change reaches slow
  after ~4.6 quiet minutes, which is exactly the "fast right after I touch things,
  cheap when I don't" behavior, with one less config key (§11.2 for the 02 §5.8
  `interval = 10` supersession).
- **Jitter**: `sleep = interval × uniform(0.9, 1.1)`; the RNG is injectable
  (`rng: Callable[[], float]`, default `random.random`) so offline tests are exact.
- **Cost honesty**: the scan duration is measured per pass; heartbeat carries
  `last_scan_s`; `goldmine doctor` warns when a root's scan exceeds **30 s** — the
  loud-cap 02 §5.6:459-460 already specified ("suggest narrower roots").
- **Same-size-same-mtime content edits** (e.g. `git checkout` restoring mtime) are
  invisible to tier 1 — the honest, documented limitation of every rsync-class quick
  check. They are caught by the sweep tier (§5), by the next watch *start* (startup is
  a full pass), and instantly by plain `goldmine ingest <roots>` (02 G10 path). Recorded
  in `help watch`; not papered over with per-file hashing (that is what the sweep is).

**Tier 2 — the ingest pass is the pipeline, unchanged in behavior.** The changed set is
handed to `IngestPipeline.run()` as per-file roots (§5); its own walk re-classifies,
its sha check confirms, its per-file transactions commit (store.py:671), its failures
are per-file. Watch decides *when*; the pipeline owns *what* and *how* — the exact
division 02 §5.6:452-455 specified ("watch only decides when").

### D3 — The one pipeline seam: `run(..., update_roots: bool = True)`

`_finalize` merges `report.roots` into `meta.roots_json` on every run
(pipeline.py:593-600). A delta pass whose roots are *changed-file paths* would
therefore pollute the index's scope record with ephemeral file paths — the exact harm
the F10 phantom-root rule exists to prevent (pipeline.py:137-142: "a typo must not
silently become index scope"). Fix: `run()` grows one **keyword-only, default-preserving
parameter** `update_roots: bool = True` (the run signature is already keyword-only past
`*`, pipeline.py:120-133); `_finalize` skips the roots merge when False. Watch passes
`update_roots=False` on every pass except the startup full pass. All existing callers
(ingest, reset --reindex) are byte-identical. This is a recorded deviation from 02
§5.6's "run() **unchanged**" — the scope invariant forced it (§11.1).

### D4 — Lifecycle: foreground daemon session, flock, heartbeat, `watch stop`, H8 surfaces

- **`goldmine watch [--roots PATH…] [--code] [--exclude GLOB]… [--include-datasets]
  [--lexical-only] [--interval-fast S] [--interval-slow S] [--settle S] [--linger S]
  [--forever]`** — foreground, like `serve` (parser.py:183-210 precedent). **No
  `--foreground` flag** (brief's sketch amended, §11.4): there is no background mode to
  foreground — backgrounding is the user's own launchd + `--forever` (02 §5.6:467-469;
  Q14 REDESIGN.md:480 stays open). Ingest-parity flags (`--code`, `--exclude`,
  `--include-datasets`, `--lexical-only`) pass through to every pass so a watch session
  indexes with the same rules the user's manual ingests do.
- **Single instance**: `flock(LOCK_EX | LOCK_NB)` on `<home>/watch.lock` — the serve
  pattern verbatim (`_acquire_lock`, serve.py:411-433; lock file never deleted,
  05 §4.4:478-479 rationale). A second `goldmine watch` prints
  `already watching (pid N)` → exit 0.
- **Heartbeat `<home>/watch.json`** — the discovery-file pattern (atomic tmp +
  `os.replace`, serve.py:519-522; swept by the next start, never by clients):
  ```json
  {"proto": 1, "goldmine_version": "…", "pid": 1234, "start_time": "<ps lstart>",
   "started_at": 1760000000.0, "roots": ["/abs", "…"], "state": "idle",
   "interval_s": 120, "last_scan_s": 3.1, "last_pass": {"at": 1760000000.0,
   "duration_s": 4.2, "scanned": 10950, "new": 3, "changed": 0, "deleted": 0,
   "failed": 0, "unchanged": 10947}, "files_indexed_total": 42,
   "holds": {"battery": false, "thermal": false, "pressure": 1, "waiting": 0},
   "notes": ["1 root unreadable (TCC)"]}
  ```
  `state ∈ idle | scanning | ingesting | held-battery | held-thermal |
  deferred-memory | stopping`. Written every loop tick (a 200-byte atomic replace at a
  ≥1 s cadence is free), so `last_seen` is always fresh. `start_time` is the
  **spawn receipt for the daemon itself** — `watch stop` verifies it before SIGTERM
  exactly like `cmd_serve_stop` verifies the daemon receipt (serve.py:1104-1113,
  `proc_matches_receipt`, serve.py:112-127) so a reused pid is never signalled blind
  (R8 review F3 discipline).
- **`goldmine watch stop`** — mirror of `cmd_serve_stop` (serve.py:1116-1182): read
  watch.json → pid liveness (`pid_alive`) → verified SIGTERM (start-time match) → wait
  ≤ 10 s for the current pass to unwind (SIGTERM sets the stop flag AND
  `pipeline.cancelled`, which unbinds at the next wave boundary, pipeline.py:240-242,
  294-296) → SIGKILL → verify watch.json cleanup. Not running / stale heartbeat →
  `watch: not running`, exit 0 (honest not-running is an answer, serve.py:1136-1138).
- **H8 in `status`** (REDESIGN.md:367) — `cmd_status` (cli.py:690) appends one line
  when `<home>/watch.json` exists (silent when the user never used watch — no noise
  for non-users):
  ```
  watch: running · last pass 2m ago · 3 new files indexed (42 this session)
  watch: running · held (battery — 120 files waiting) · last pass 14m ago
  watch: not running (stale heartbeat, dead pid 1234 — swept by the next start)
  ```
  (`_fmt_ago` reuses the `fmt_clock` shape, output.py:42-49.) `status --json` adds the
  frozen-envelope key `"watch": {…}` / `{"running": false, "stale": true}` via the
  shared `_envelope` builder (cli.py:124-129). Rendering lives in `goldmine/watch.py`
  next to the writer so the field contract cannot drift (the `check_serve_daemon`
  placement rationale, doctor.py:760-766).
- **Doctor row `watch`** — registered in `run_checks` after `check_serve_daemon`
  (doctor.py:659): ok = running (pid, state, last-pass age); warn = not running
  ("optional — the index updates when you run goldmine ingest"); warn = stale
  heartbeat (dead pid N — self-heals); ok-with-detail = held (battery/thermal/pressure
  is working as designed); warn = scan cost (`last_scan_s` > 30 s → "narrower roots").
  **Never FAIL** — watch is optional by construction (the serve row's contract,
  serve.py:1188-1245).
- **`help watch` topic** (help.py:12 `TOPICS`, serve topic shape help.py:177): the
  scope invariant sentence, the session-vs-`--forever` story, the latency budget
  (§D8), the power holds, and the mtime limitation (D2).
- **`--json`**: watch accepts the global flag; it switches per-pass summaries to
  `render_ingest_summary(report, json_mode=True)`-style envelope lines on **stderr**;
  stdout stays empty in every mode (§2 rule 4).

### D5 — Resume / crash safety: nothing to add, and tests prove it

The ROADMAP promise "断电重启接着干，永不重复已完成的活" is a **property of the
pipeline watch inherits**, not new machinery: every file commits in one atomic
transaction (store.py:671 `replace_segments`, FTS rows in the same txn); an interrupted
file is a `pending` row that the next pass re-attempts (sha-skip only passes
`state == "done"`, pipeline.py:407-408); a finished file sha-skips in µs-class time
relative to extraction. Watch adds only: the snapshot (rebuilt from one walk at start),
the heartbeat (dead pid = honestly "not running", swept by next start — the R8 stale-
discovery posture, serve.py:435-451). **`kill -9` at any instant** leaves: at most one
half-committed file (atomic ⇒ either old or new rows), a stale heartbeat, a held flock
(kernel releases it) — all three self-heal on the next `goldmine watch`. Verified by
offline test T26 and live test L2 (SIGKILL mid-batch → restart → vector count identical
to a single-path control; second full pass reports everything `unchanged`).

### D6 — Power awareness: probe, gate the expensive tier only, report honestly

Probes (each a bounded `subprocess.run`, `util.run_tool`-style timeouts, util.py:69-108)
run **once per loop tick with a 30 s cache** (a `pmset` spawn is ~10-20 ms — never per
decision; the serve guard's cached-sample rationale, serve.py:198-199):

| Signal | Probe + parse (against today's measured shapes, §1) | Gate in R9 |
|---|---|---|
| **Thermal** | `pmset -g therm`: `CPU_Speed_Limit: N` with N > 0, OR any warning note not prefixed `No` | **Pause all ingest passes** (delta AND sweep). Scans continue (scandir is the cheap tier and keeps detection+heartbeat honest). state `held-thermal`. |
| **Battery** | `pmset -g batt`: drawing from anything other than `'AC Power'` (UPS included, conservative) | **Delta pass runs only when the changed set ≤ `battery_max_batch` (default 50)** — the DigUp "new files (≤ 50) always run; backfill waits" semantics (02 §5.6:464-466, IndexService.swift:93-96). Larger sets wait for AC: state `held-battery`, heartbeat `waiting: N`. **Sweep passes always wait for AC** (they are backfill-class: full-corpus sha). |
| **Low Power Mode** | `pmset -g` → `lowpowermode 0|1` | **Read + reported in `holds`, does NOT gate** — the LPM backfill gate is H12 v2.2 (REDESIGN.md:371); shipping half of it now would blur the v2.2 boundary. |
| **Memory pressure** | `default_pressure_sampler()` **imported from serve.py:164-190** (kernel `kern.memorystatus_vm_pressure_level`; the B3-trap-free signal; the `GOLDMINE_SERVE_PRESSURE_LEVEL` determinism pin applies to both consumers — documented) | **Level ≥ 2 at pass-decision time ⇒ defer the pass one tick** (state `deferred-memory`). No hysteresis: deferring costs ≤ one interval and self-corrects; spawning a 484 MB model under warn would fight the serve daemon that is required to step aside under the same signal (serve.py:799-839). Rationale in D7. |

**What is gated: ingest passes only.** Scans, diffing, heartbeat and status surfaces
never gate — they are the cheap tier and the honesty layer. This is the precise answer
to "full ingests vs re-checks": re-checks (tier-1 scans) always run; full ingests
(delta/sweep passes, which spawn extraction workers and the embedding backend) gate.

### D7 — Coexistence with serve: separate locks, always allowed to run together, one shared signal

- **Separate flocks**: watch holds `<home>/watch.lock`; serve holds
  `<home>/serve.lock` (serve.py:67). Both daemons can run simultaneously by
  construction — different lease files, no shared state (serve holds no index state at
  all, serve.py:1-14). Offline test T35 pins it.
- **Watch does not consume serve** (G6 cut): each ingest pass constructs a fresh
  `IngestPipeline(cfg, store, backend)` with its own cold backend via
  `create_backend` (cli.py:25, 116-117) — `run()`'s `finally` closes it
  (pipeline.py:313-316), so the pass owns its whole backend lifecycle. A burst of
  drops = one debounced pass = one spawn (~1.1 s), not per-file spawns.
- **The one interaction — pressure defer (the "minimal honest behavior" the brief asks
  for)**: before spawning a pass, watch samples the kernel pressure level via the
  **same function serve uses** (serve.py:164-190). Level ≥ 2 ⇒ defer. Rationale:
  (a) serve itself unloads/resists under sustained ≥ 2 (serve.py:261-294) — a watch
  spawn at the same moment is exactly the "restart-flap" behavior R8 killed;
  (b) the defer is *latency*, never *loss* — the next tick re-samples and runs when
  the level returns to 1, and the heartbeat names the hold so the delay is never
  silent (the honesty rule). Lexical-only watch sessions (`--lexical-only`) skip the
  defer: no model is spawned, the pass is cheap. Whether a *degraded lexical-only*
  delta pass under sustained pressure is worth the behavioral fork is an H12 question
  (§12.2) — R9 keeps one behavior.
- **Watch vs manual ingest** (the real single-writer question, 05 §4.9:734): a user can
  run `goldmine ingest` while watch runs. Correctness comes from what already exists:
  per-file atomic transactions + path-keyed upserts make interleaving safe at file
  granularity, and SQLite serializes writers (`connect_index` sets WAL +
  `busy_timeout = 60000`, store.py:309-315) — the loser of a lock race waits, never
  tears. Watch does **not** add a lock manual ingest would have to know about (that
  would violate zero-change); the worst case is both sides hashing the same unchanged
  corpus once. Test T36 pins "concurrent ingest + watch pass ⇒ consistent counts,
  no duplicate rows". The `operations` table that would make this elegant is H12
  (05 §4.8:712-722 explicitly leaves "single-writer + flock between watch/ingest" as
  the whole story until then).

### D8 — Latency: what "几分钟内" means, pinned and measured

- **Target (normative)**: a dropped file becomes searchable within
  **`current_interval + 60 s`** — the interval to detect it, plus settle (2 s) + cold
  backend spawn + extract/embed/commit for a small file (~5-20 s measured class on the
  eval corpus). At the default slow cadence that is ≤ 180 s worst case (the ROADMAP's
  "几分钟内", satisfied); inside the fast window after any recent activity it is ≤ 65 s.
- **"Searchable" = the FTS row answers a lexical query** (the commit makes it so
  atomically); semantic searchability additionally requires the vector, same pass.
  The live gate measures lexical (the floor) and prints semantic too.
- **Live test L1 pins it**: watch on a tmp root with `--interval-slow 3 --interval-fast
  1` (the interval flags exist precisely so deployment and tests share one mechanism),
  drop a ≤ 64 KB .txt containing a unique term, poll `goldmine search <term>
  --lexical` every 1 s; assert first hit ≤ 90 s wall (≈3× headroom over expected),
  print the measured breakdown (detect / settle / pass / search). Gate is hard in the
  live suite (it is the R9 acceptance number), printed with its machine context like
  the R8 bench.

## 5. The watch loop (normative state machine)

```
watch ──► RESOLVE SCOPE (D1; empty ⇒ refuse exit 4) ──► flock watch.lock
          (held ⇒ "already watching (pid N)" exit 0)   ──► sweep stale watch.json
                                                        ──► write heartbeat(state=starting)
          ──► STARTUP (ungated, no backend — R-F3):
                walk roots → seed snapshot; record scope (roots_json merge)
          ──► LOOP (until stop flag or linger expiry):
                sleep(max(interval, 2×last_scan_s) × jitter)   [R-F1b floor]
                                                     [interval = 5s reset on change,
                                                      ×2 per quiet scan, cap 120s]
                probe power (30 s cache)            [heartbeat holds/]
                SCAN: walk_files(roots) → snapshot diff
                      (new/changed/gone; measure last_scan_s)
                if new+changed: sleep(settle_s); rescan → merge into pending set
                TICK 1: RESUME PASS if unheld (full roots, update_roots=False;
                        sweep-class gating — battery waits for AC) [R-F3]
                elif pending and not held and gaps ok:  DELTA PASS
                      fresh IngestPipeline + cold backend
                      run(changed_paths, update_roots=False)
                      [min_pass_gap_s ≥ 25 between embed passes — R-F1a;
                       battery: ≥ battery_pass_gap_s — R-F1c]
                elif pending and held:               heartbeat waiting=N, state=held-*
                if gone and (throttle ok) and not held:  SWEEP PASS
                      run(file_roots, update_roots=False)   [prunes deletions,
                                                            sha-catches same-mtime edits]
                write heartbeat(state, last_pass, counters)   [every tick, atomic;
                      state=ingesting BEFORE each pass — R-F7]
                if forever is false and quiet > linger: exit 0
          SIGTERM/SIGINT → stop flag + pipeline.cancelled (pass unwinds at the next
                           wave boundary, drain ≤ 10 s — R-F2)
                           → delete watch.json → release lock → exit 0
          SIGKILL anywhere → stale heartbeat + released flock (+ receipt-swept
                             llama-server orphan on the next start); next start sweeps
```

**Pass kinds** (all reuse `IngestPipeline.run()` per D2/D3; per R-F3 the
startup pass became the first-tick RESUME pass with `update_roots=False` —
scope was already recorded by the ungated startup walk):

| Pass | Roots arg | `update_roots` | Gated by | Cost class | Purpose |
|---|---|---|---|---|---|
| resume (first tick) | the resolved file roots | **False** (R-F3) | thermal; battery (sweep-class: waits for AC); pressure ≥ 2; R-F1a gap | scan + sha of corpus | resume pending work, prune old deletions, same-mtime catch-up |
| delta | the changed file paths | False | thermal; battery if set > 50 or R-F1c gap; pressure ≥ 2; R-F1a gap | scan(trivial) + sha of changed only | freshness — the R9 promise |
| sweep | the full file roots | False | thermal; battery; pressure ≥ 2; throttle ≥ `full_period_s`/2 since last sweep (fires on `gone` detection or every `full_period_s`=6 h idle) | scan + sha of corpus | deletions ≤ ~15 min; same-mtime self-heal |

Delta-pass edge cases, pinned: a changed path that vanishes before its pass becomes a
per-root failure inside `run()` (pipeline.py:150-169) — recorded in the pass report,
harmless; a changed path that became over-cap/unsupported re-records its honest row
via the normal skip-notice path; deletions computed inside a delta pass are scoped to
the changed-file roots and are a no-op (store.py:1111-1126 `_under_roots`: a file root
matches only itself, and it exists — verified).

## 6. Lifecycle surface (user-visible contract)

### 6.1 Commands

```
goldmine watch [--roots …] [ingest-parity flags] [--interval-fast 5] [--interval-slow 120]
               [--settle 2] [--linger 300] [--forever]
goldmine watch stop
```

Startup banner (stderr, serve.py:372-376 shape):
`goldmine watch: pid 1234 · 2 roots · scan 5s→120s · linger 300s · holds: battery>50 batch / thermal pause / pressure defer`

### 6.2 Config (`[watch]`)

```toml
[watch]
interval_fast = 5        # detection floor after a change or at start
interval_slow = 120      # quiet-corpus cadence (decay ×2 per quiet scan, capped)
settle_s = 2             # debounce before an ingest pass
linger = 300             # quiet seconds before exit 0 (--forever disables)
battery_max_batch = 50   # max changed files per delta pass on battery (DigUp ≤ 50)
full_period_s = 21600    # idle self-heal sweep (deletions + same-mtime edits)
min_pass_gap_s = 25      # R-F1a: no embed-bearing pass more often than this
battery_pass_gap_s = 120 # R-F1c: minimum embed-pass gap on battery (max with the above)
```

Unknown keys WARN (config.py:290-293 discipline); flag clamps: `interval_fast ≥ 1`,
`interval_slow ≥ interval_fast`, else usage-error shape exit 2. No env additions.

### 6.3 Exit codes

No new codes: 0 normal/linger/stop/already-watching/not-running-on-stop; 4 the
`watch_no_roots` refusal; 130 Ctrl-C in the argparse/early-error funnel only (a
running watch treats SIGINT as the clean-stop path, exit 0 — the serve convention).

### 6.4 Honesty surfaces

`status` line + `status --json` key + doctor row (D4) + the doctor scan-cost warn
(30 s, §D2). A held watch says *what* it is holding and *how many* files are waiting —
a silent skip would be the one dishonesty this feature could add, so it is a pinned
field (`holds`, `waiting`), not a log line.

## 9. Constraint compliance

- **Scope invariant** — mechanical: empty-scope refusal (D1), config never written by
  watch, `roots_json` only via the explicit startup pass; T6-T9 pin all three.
- **Zero behavior change to non-watch commands** — the pipeline touch is one
  default-true keyword param (T8 pins roots_json byte-stability for normal ingest);
  status gains one conditional line + one json key; doctor gains one row.
- **Offline-first** — every constant testable with injected clock/rng/probes; the only
  subprocesses are the pmset/sysctl probes, all fixture-parsed offline.
- **Error shapes** — the start refusal and clamp errors use the universal
  `UserFacingError` shape with mandatory fixes (errors.py:53-60); runtime pass
  failures are per-file report rows (exit-5 semantics live inside each pass summary),
  never a watch crash.
- **No sudo, no launchd, no new deps** — stdlib fcntl/subprocess/pmset only; the
  background story is the user's own agent (02 §5.6:468-469).

## 10. Risks

| Risk | Mitigation |
|---|---|
| Scan cost dominates on huge roots (5.2 s measured at ~/git scale) | adaptive cadence makes scans the only recurring cost and the ingest tier strictly event-driven; doctor's 30 s scan warn names narrower roots (02 §5.6:459-460); interval flags let deployment trade latency for duty. |
| mtime-granularity misses (same size+mtime edits) | documented (D2); sweep + startup + plain ingest are the three catch-all paths; never claimed otherwise in help copy. |
| Watch pass fights a manual ingest | SQLite writer serialization (busy_timeout 60 s, store.py:315) + per-file atomicity; T36 pins consistency; H12's operations table is the elegant fix, deliberately deferred. |
| Pressure defers starve freshness during long builds | defers are tick-scoped and self-correcting; heartbeat/status always name the hold with the waiting count; `--lexical-only` sessions are immune. |
| macOS `pmset` output drift across versions | parsers key on stable substrings measured today; any parse failure degrades to "no hold" **except** battery, which defaults to *held* on unparseable output (fail-safe toward caution), noted once. |

## 11. Deviations from the owning docs (for back-port)

1. **`run(update_roots=True)`** (02 §5.6:452-455 "feed … `IngestPipeline.run()`
   **unchanged**"): the scope invariant (`roots_json` must not absorb ephemeral
   changed-file paths — the F10 principle, pipeline.py:137-142) forces one
   default-preserving keyword param; every existing caller is byte-identical.
2. **`[watch] interval = 10` (02 §5.8:515) → `interval_fast`/`interval_slow` adaptive
   pair**: G11 owns "adaptive polling" (REDESIGN.md:345); REDESIGN §5 wins the domain
   conflict per its own §0 rule. 02's single-interval + backoff shape is the same
   mechanism with the constants made explicit.
3. **Power slice**: thermal + battery + pressure gate in R9 (G11's "pmset power
   probes"); **LPM read-only**, no `operations` table, no arbitration — the full H12
   gate stays v2.2 (REDESIGN.md:371; 05 §4.8:722 "until then" branch is exactly this
   spec's single-writer story).
4. **No `--foreground` flag** (brief sketch): foreground is the only mode — a
   backgrounding daemon is the thing 03 §1 forbids ("no daemon you didn't ask for");
   `serve` set the precedent (parser.py:183-210). Deployment = user launchd +
   `--forever` (Q14 REDESIGN.md:480 open).
5. **Watch output on stderr** (ingest prints its summary to stdout, cli.py:390): a
   long-running process has no stdout consumer; the data-only stdout contract (SPEC
   §1.2) is preserved by keeping it empty. `serve` precedent.
6. **Watch ingest stays cold** (05 §4.4:548-550 expected ingest to move onto the
   daemon's server "in v2.1" via G6): the brief pins watch off G6; the pressure defer
   (D7) is the one honest interaction until G6 lands.
7. **Deletion latency is a throttled sweep (≤ ~15 min), not per-pass**: compute per-tick
   would force a full sha pass per tick; ROADMAP R9's "几分钟" promise is scoped to new
   files (the delta tier), and the help copy says so.
8. **(R-F2) Poison dedup vs the sweep tier**: session poison-file dedup gates DELTA
   passes (the daemon's own explicit path lists); sweep/resume passes re-attempt
   everything by design — they are the self-heal tier, and a persistently-failing file
   costs one attempt per `full_period_s`, not per scan. Poison entries are session-only
   (a restarted watch starts clean, like the snapshot itself).
9. **(R-F4) Thermal hold threshold is `0 < N < 100`, not D6's "N > 0"**:
   `CPU_Speed_Limit = 100` means full speed; the measured clear state prints no such
   line at all. The D6 rule would hold a healthy machine forever on a pmset build that
   reports 100; the amendment fixes the threshold and pins separator-agnostic parsing.
