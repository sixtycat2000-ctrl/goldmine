# 第三讲：摄取管线 — 一个文件从磁盘到可搜的完整旅程

> 轮讲第三讲（2026-10-25）。主入口：`goldmine/ingest/pipeline.py`（run：
> roots → waves → outcomes → commits → report）+ walk.py / extraction.py /
> commit.py。读完应能答文末十问。

## 0. 一张图

```
roots（你给的目录）
  → F10 幻影根检查：根必须 stat 得到，否则按"根失败"计入 exit-5
  → walk（确定性排序、跳过表、符号链策略、dataless 拦截）
  → 候选按 波次（workers×8，最少 16）分批，线程池抽取
      每波先算内容 sha256：没变的文件直接跳过（G10 语义）
  → 每个文件：抽取器产出 _Outcome（能力行 + 段 + 媒体段 + info）
  → 提交：一个文件一个事务（原子替换段/FTS/向量行）
  → 收尾：删除/移动检测、roots_json 合并、报告 + 退出码
```

## 1. walk：候选从哪来（第二讲已见过它的 dataless 面）

确定性是刻意的：目录项排序后走，同样输入永远同样候选序。跳过规则分
三层：目录层（SKIP_FOLDERS 构建目录、隐藏目录不下钻、包目录如 .app、
.noindex、TCC 不可读≠空）、文件层（密钥/证书、minified、许可文件、
超大小帽、特殊文件 FIFO、**dataless 占位**——在会 open 的嗅探之前拦）。
目录符号链永不跟随（防环），文件符号链跟到内容。

## 2. 波次与内容哈希跳过

抽取贵（模型、OCR、ffmpeg），所以先便宜后贵：每波先对文件算 **sha256**，
和库里存的内容哈希一致且版本新鲜 → 跳过。这就是"Ctrl-C 安全、重跑续传"
的机制基础：没动过的文件零成本。

## 3. 抽取：一切产出 _Outcome

每个文件由 kind 分发到对应抽取器（文本/PDF/图片/音视频/代码/网页…），
统一产出一个四元组：**能力行**（content_indexed / metadata_only /
unsupported / failed + 原因）、**段列表**（chunk/name/page…）、**媒体段**
（图片/音频/页图/帧，带预算与模态）、**info 字典**（页数、窗口数、路由
标记……status --json 可见）。媒体段的加工链（缩略图、窗口、帧）在抽取
期完成，但**嵌入在提交期**（一波之后）——所以缩略图放在 run 级暂存目录，
不能放在抽取函数的临时目录里（这是个真实的坑：早期版本用完即删，提交
时文件已没了）。

共享的省钱机制：**OCR 批处理**（F7）——多个截图的 OCR 请求汇进一个批次、
由一个_leader 线程一次性 spawn helper（省掉每图一次的进程启动 + Vision
冷启动）。

## 4. 提交：一个文件一个事务

`_commit` 系列全部包在 `store.write_transaction()` 里：段/FTS/向量行的
替换对任一文件是**原子**的——崩溃最坏丢这一个文件的这一次，绝不留半
个文件的段。提交期做最后几件事：文档提示词拼装后调后端嵌文本、媒体段
逐个嵌（预算决定图片进模型前的尺寸）、乱序文本的"仅含义向量"、
media_vectors 标记。第二讲的版本表在这里落进行。

## 5. 收尾三件事

- **删除检测**（compute_deletions）：当前 roots 范围内、路径在磁盘上
  消失的行清掉。A1-18 守卫：**根/子树不可读 ≠ 空**（弹出硬盘、TCC 弹窗
  绝不能读成"全删了"），这些行保留并计数。
- **移动检测**（P1-3，detect_moves）：路径消失但 POSIX 身份（dev+ino+
  大小+mtime）出现在本轮候选里 = 移动——改路径保段保向量，不删不重嵌
  （截图工具把截图挪进项目目录是常态）。
- **roots_json 合并**（update_roots）：本轮流过的范围记账进库——这是
  第一讲 A2 过滤"只在 roots 内管你"的数据来源。

## 6. 报告与退出码

退出码表（command_support.py）：**0** 全成或诚实零；**1** 运行时错；
**2** 用法错/后端起不来；**3** 指纹拒（第二讲）；**4** 前置缺失（没索引/
没装 MCP extra）；**5** 部分失败（有按文件的失败行，原因在能力行里）；
**130** Ctrl-C。部分失败不是灾难是**记账**——`goldmine status --failures`
逐行给你看谁失败、为什么。

## 7. 腐烂风险清单

1. **媒体暂存目录的生命周期**：抽取-提交跨波次的约定（run 级目录）被
   无知重构破坏时，症状是"提交期文件消失"类 flake。
2. **跳过逻辑的顺序**：dataless 拦截必须先于一切 open（TS 嗅探）；调
   整 walk 顺序时这条是钉死的。
3. **不可读≠空**：任何新的"清行"路径都必须过 unreachable 前缀守卫。
4. **波次里的全局单例**（OCR 批、暂存目录、G10 版本集）都是 run 级——
   嵌套 run / 复用 pipeline 实例时先想清楚。
