## 2. Algorithm (exact)

All of §2 lives in `goldmine/distill.py` (rewritten in place; v1 functions
`cluster`/`tfidf_terms`/`build_cards` are replaced — the module docstring at
`distill.py:1-19` and the MODULE_MAP entry `docs/MODULE_MAP.md` "### goldmine/distill.py
[v1]" (docs/MODULE_MAP.md:158) are updated in the same commit). Vectors always come from
`store.load_vectors()` (`store.py:600-659`, fp16→f32 decode, cached) — calibration,
clustering, guards, and incremental assignment all read the same decoded fp16, so
decisions are self-consistent (06 §6 fp16 risk, accepted).

### 2.1 Corpus and dedupe (unchanged from v1)

`_corpus()` (`distill.py:207-243`): all vectorized segments in scope, canonical order
`(file_id, segment_id)` (`distill.py:242`). Dedupe unchanged: sha256 of
`normalize_text` exact pass, then greedy near-dup at cosine ≥ 0.97
(`distill.py:101-139`; `NEAR_DUP_COSINE = 0.97`, `distill.py:37`). Scope filtering
(`--kinds`, `--under`, `--after`) happens in `_corpus` before dedupe (§6.2).

### 2.2 τ calibration — `measure_tau(matrix, *, manual=None) -> TauResult`

`TauResult = (tau: float, tau_source: str, tau_raw: float, histogram: list[int],
quartiles: (float, float, float))`. Pure function of the deduped matrix — no Store, no
backend — so every branch is unit-testable with synthetic arrays.

1. **Sample.** N ≤ 300: all N(N−1)/2 pairs. N > 300: row indices
   `i_k = round(k·N/300)` for k ∈ 0..299 (duplicates collapsed, order preserved —
   deterministic, no seed), gram `G = M_s @ M_s.T`, take the upper triangle excluding
   the diagonal → exactly ≤ 44,850 values.
2. **Histogram.** 256 equal bins over [0.0, 1.0]; cosine c → bin
   `max(0, min(int(c·256), 255))` (F6: negatives clamp to bin 0, never wrap).
3. **Otsu.** For every cut t ∈ 1..255: ω₀,ω₁ = cumulative/remaining counts,
   μ₀,μ₁ = class means; t\* = argmax of ω₀·ω₁·(μ₀−μ₁)². `tau_raw = (t\*+0.5)/256`
   (bin center). Degenerate all-in-one-bin histograms (max count == total) → treat as
   single-hump (step 4's fallback).
4. **Hump/valley check + mode-proximity fallback (B9).** Smooth the histogram with a
   5-bin moving average. Dominant mode m = argmax smoothed bin. σ = population std of
   the sampled cosines. Humps = local maxima with smoothed count ≥ 0.20 · dominant
   count. Fallback to the percentile path when **either**:
   - (valley) fewer than 2 humps, or the minimum smoothed count between the top two
     humps exceeds 0.60 · the smaller hump's peak (no real valley), **or**
   - (mode proximity) |tau_raw − (m+0.5)/256| ≤ 1.0 · σ (k = 1, per 06 §4.1 item 3).
   Percentile path: `tau_raw = P90` of the sampled pairs (numpy linear interpolation).
   Single source of truth for both checks — the canary's monothematic variant asserts
   `tau_source != 'otsu'` (§7.4).
5. **Clamp (every non-manual path).** τ = clamp(tau_raw, 0.55, 0.85).
   `tau_source`: `'otsu'` (Otsu path, unclamped), `'floor'` (Otsu path, tau_raw < 0.55),
   `'ceil'` (Otsu path, tau_raw > 0.85 — NEW enum value; 06 listed only
   otsu|floor|percentile, but the all-similar corpus is real and honesty beats the
   shorter enum), `'percentile'` (fallback path — recorded even when the clamp then
   bites; stats also carry `tau_raw` so the bite is visible), `'manual'` (`--threshold`/
   config override — steps 2–4 still run and populate histogram/quartiles for preview,
   but τ is the override), `'inherited'` (incremental run reusing the previous τ, §4).
   **F2a expectation:** real corpora are unimodal in pairwise cosine (median pairwise
   cos ≈ 0.661 measured) — they are EXPECTED to land on `tau_source='percentile'`
   (τ ≈ 0.72–0.80 measured on 3 real slices). That is calibrated honesty, not a bug:
   nobody "debugs" it later. The llama canary and `--report-real` print the source so
   the expectation stays visible.
6. **Scale statement (B10, D3).** Preview and run-header print:
   `τ calibrated on pairwise cosines; assignments compare cos-to-centroid, which reads
   ~1.1–1.6× higher`. Centroid-scale calibration (recompute the sampled gram against
   running centroids) is the pre-approved contingency if the llama canary over-merges;
   it would set `tau_source='centroid'` and change exactly one function.

### 2.3 Clustering v2 — `cluster_v2(items, tau, min_members) -> (clusters, dropped_hist)`

Leader loop over the canonical order; replaces `cluster` (`distill.py:145-170`):

- Per cluster keep the unnormalized running sum `S_c` and count `n_c`; the compared
  centroid is ĉ = S_c/‖S_c‖ (renormalized each comparison, as v1 did at
  `distill.py:156`).
- A chunk joins the FIRST cluster c (lowest index on ties, v1 rule `distill.py:158-160`)
  where **both** hold (D4):
  - `cos(x̂, ĉ) ≥ τ`, and
  - `cos(x̂, S_c)/n_c ≥ τ_lo` with `τ_lo = max(τ − 0.10, 0.35)` — average-link admission
    as one extra dot product (the 06 §4.2 simplified form; the dead `0.5·τ` branch is
    dropped per the 2026-10-16 amendment).
- Fails both → founds a new cluster (append; sums/clusters stay index-aligned).
- min_members drop is unchanged in MECHANISM but v2 returns the full size histogram
  (buckets `1`, `2`, `3-5`, `6-10`, `11-25`, `26-100`, `100+`, kept and dropped
  merged into one dict) instead of a bare dropped count — `--preview` and stats report
  it (06 §4.2 "no longer silently").

Order-robustness: leader remains order-dependent by nature; the admission guard shrinks
the disagreement band. The two-pass merge fallback (06 §4.2) stays UNBUILT until the
canary's shuffle variant (§7.4, run in CI on mock) ever fails.

### 2.4 Two-level topics — `split_two_level(clusters, tau) -> (cards, headers)`

After the leader pass, per cluster with n ≥ 12:

- Mean intra-member cosine `s̄ = (‖S_c‖² − n)/(n(n−1))` (exactly 06 §4.2; computed from
  the running sum — one norm, no second pass).
- If `s̄ < τ − 0.12`: recursive leader at `τ_sub = τ + 0.08` on that cluster's members,
  depth ≤ 2 (top clusters = depth 0; children = 1; grandchildren = 2; no depth-3).
- Accept the split only when the children's size-weighted mean s̄ improves by ≥ 0.05:
  `s̄_parent − Σ(|c|·s̄_c)/Σ|c| ≥ 0.05`; else keep the single card.
- Leaves become cards; every accepted internal node becomes a card row with
  `status='header'`, `size = Σ child sizes`, its own terms/excerpts computed over the
  union of descendant members (it renders as a markdown section header, never counted
  in `clusters_kept`). `parent_id` references the header card row — the FK is ON
  (`store.py:228`), so headers-in-DB is the only FK-honest encoding of "parent retained
  as a section header (not a card)" (06 §4.2); D5.

### 2.5 Card content — medoid, coverage excerpts, terms, title

Per final cluster (canonical member order):

- **Medoid (primary excerpt, D11):** `m* = argmax_i (1/(n−1)) Σ_{j≠i} cos(x̂_i, x̂_j)`
  over the within-cluster gram (one small matmul; n=1 → that member). Ties → lowest
  segment id (argmax-first on the canonical order). Replaces max-cos-to-centroid
  (`distill.py:282-285`).
- **Coverage excerpts (≤ 2 extra):** greedy k-center on the remaining members —
  repeatedly add the member with max min-cosine-DISTANCE (distance = 1 − cos) to
  already-picked excerpts; stop at 3 total or when the next best min-distance < 0.25.
  Ties → lowest segment id. Roles: `primary`, `coverage`. Text via
  `util.excerpt` (`util.py:137-142`, 240-char cap unchanged). Every excerpt keeps its
  own `(path, kind, loc, loc_end)` — the Tier-1 byte-traceability property (06 §1)
  is preserved and re-asserted by tests.
- **Terms (D10):** token filter tightens `_tokenize_terms` (`distill.py:92-95`) to:
  len ≥ 3, contains a letter, letters ≥ digits, not hex-shaped `^[0-9a-fA-F]{6,}$`,
  not unit-shaped `^\d+(\.\d+)?(kb|mb|gb|tb|px|hz)$`, not a stopword
  (`search.STOPWORDS`, as today). Cluster-df gate: a unigram must appear in ≥ 2
  DISTINCT members (`.fid`-distinct, so a 10-chunk single-file card still needs 2
  members — members here are chunks, df counts chunks per 06 §4.3 "distinct members" =
  distinct chunks; single-chunk contributions never mint a term). Bigrams: adjacent
  eligible-token pairs within one member's text; bigram df ≥ 2; scored with the SAME
  tf-idf formula (tf × log(n_clusters/df), ties → alphabetical — the v1 sort at
  `distill.py:194-200`); a bigram that outscores BOTH its halves replaces them in the
  final top-8. `n_clusters` = number of kept clusters + headers (never 0 → idf
  degenerate case is gone with the mega-cluster; max(1, ·) kept as belt-and-braces).
- **Title (extractive only, R6):** first sentence of the medoid member's FULL text
  (sentence split on `(?<=[.!?。！？])\s+`, fallback = whole text), trimmed at a word
  boundary ≤ 70 chars; fallback to the v1 terms-join when no sentence boundary exists.
  `title_kind`: `'sentence'` | `'terms'`. The terms line stays visible under the title
  in markdown either way (06 §4.3).

### 2.6 Weights and ordering

`card_chunks.weight` keeps its v1 meaning (member cos-to-final-centroid, rounded to 6
places, `distill.py:304-306`) — the column is unchanged and doctor/`--json` consumers
stay compatible. Card ordering: `(-size, first member (fid, sid))` exactly as v1
(`distill.py:310`); headers excluded from the ordered card list but numbered in the
markdown TOC as sections. `topic_id` (json `id`) = 1-based index over kept cards;
headers get ids after all cards (deterministic, unused by consumers).

### 3.2 Why dropping cards is safe (the announcement's substance)

Cards are (a) **derived** — rebuilt from segments+vecs by one command; (b)
**fingerprint-bound** — v1 already kept exactly one generation and wiped it per run
(`store.py:732-734`), so no user data can span generations today; (c) **snapshotted** —
ladder rule 6 (`migrations.py:20-23, 341-353`) takes `<index>.pre-v4.sqlite` (VACUUM
INTO, integrity-verified) for any index > 1 MB before the step, so the old cards stay
recoverable by hand; (d) announced BEFORE the next distill run, not silently at open.

### 3.3 The migration step `_v3_to_v4(db, from_version) -> 4`

Inside the standard one-transaction ladder (BEGIN IMMEDIATE, per-step user_version
stamp, history entry — `migrations.py:140-177`, kill-safety already verified for DDL):
the DROPs + CREATEs above, plus two meta writes:

- `_set_meta(db, "cards_v2_rebuild_note", ...)` — the announcement (verbatim text):
  > "cards v1 tables were replaced by the v4 schema (2026-10-19 R6): cards are derived
  > data and were recreated EMPTY — run `goldmine distill` to build v2 cards. A
  > pre-migration copy of the old cards is in <index>.pre-v4.sqlite (if the index was
  > over 1 MB)."
- `meta.schema_version = '4'`.

The announcement is SURFACED (not buried in meta): `cmd_status` and

`notices += [{"code": "cards_rebuild", "message": <note text>}]` (F11 — the message is

Fixture tests follow `tests/test_migrations.py` patterns (`_strip_to_v1` at

## 4. Incremental distill (D7–D9)

### 4.1 View identity and run rows

- `scope_json` (canonical: sorted keys, expanded paths): `{"under": [...]|null,
  "kinds": [...]|null, "after": ts|null}`. `view_id = sha256("leader-avglink.v2" +
  canonical scope_json)[:16]` (D7 — τ is NOT part of the view; a τ change is a full
  rebuild of the same view).
- `distill_runs.id = sha256(algo_str|repr(tau)|canonical scope_json|corpus_hash|mode)`.
  Repeat identical runs collapse into the same row via
  `INSERT … ON CONFLICT(id) DO UPDATE` (F3) — history is append-only up to
  identical-content repeats. The view's live state = its latest run row
  (`created_at` desc, `id` asc tiebreak). Run `stats_json` additionally carries
  `embed_id` and the member-file list — the incremental eligibility inputs (§4.3),
  snapshotted at run time so later card mutations cannot rewrite them.

### 4.2 corpus_hash (D9)

```
corpus_hash = sha256(canonical_json({
    "embed_id": meta.embed_id or "",     # v2 per-file embed identity (meta key set by ingest)
    "files": sorted([[path, sha256], ...])   # in-scope files with ≥1 vectorized segment
}))
```

`embed_id` inside the hash is the fix for the re-embed hole: a model switch re-embeds
the SAME files under the SAME paths/shas, and only `corpus_hash`-equality would wrongly
bless reuse of centroids from the old vector space. (`meta.embed_id` is empty on
legacy/keyword-only indexes — distill refuses those at the fingerprint gate anyway,
`cli.py:1041-1060`.) File mtime/chunker/extractor versions deliberately NOT in the
hash: mtime churn must not force recompute; a re-chunk changes segment ids, which
dissolves memberships (§4.4) and degrades gracefully without a hash bump.

### 4.3 Incremental eligibility and flow

Eligible iff ALL of: a previous run exists for (view_id, algo); `tau` equal (an explicit
`--threshold` must match the previous run's τ; when unset, the incremental run INHERITS
the previous τ — calibration is skipped, see step 4); `embed_id` equal (current
`meta.embed_id` vs the previous run's snapshotted value — F4: this is where the re-embed
hole is closed, NOT via corpus_hash); deleted member files / previous member files ≤ 0.20
(F8b: a MODIFIED file is not deleted — only paths that vanished count); and not
`--refresh`. `corpus_hash` never gates eligibility (F4) — it is audit/diff identity only.
Else full.

Incremental run (F8's four decision points are marked):

1. Load the corpus (§2.1) and — BEFORE any mutation (F8a) — the previous run's active
   cards + decoded centroids (`util.unpack_fp16`, `util.py:119`) with each card's member
   vectors loaded ONCE (F8d: the guard's member set is the ORIGINAL members; chunks
   joining this run never raise the bar mid-run).
2. **New chunks** = corpus chunks whose segment id is not in this view's active
   `card_chunks` (join through `cards.view_id` — membership is per-view, not global).
3. Assign each new chunk (canonical order) to the FIRST existing card (lowest card
   index — F8c, consistency with `cluster_v2`; NOT the nearest) with
   cos-to-stored-centroid ≥ τ AND average-link ≥ τ_lo (mean over that card's ORIGINAL
   member vectors); first index wins on ties. Joining updates the card's `card_chunks`
   (weight per §2.6), size/n_files, and centroid — the stored centroid is
   recomputed as the renormalized mean over the FULL member set and re-packed fp16
   (not an online running update of the fp16 blob — fp16 rounding error must not
   accumulate across runs).
4. Existing memberships are **frozen** — no chunk is ever reassigned away (06 §4.4);
   τ is inherited from the previous run (`tau_source='inherited'`, `tau_inherited:
   true` in stats; D8 — recalibration would move frozen labels).
5. The remainder (unassigned new chunks) goes through `cluster_v2` → new cards.
6. `dissolve_pass` (§4.4) runs BEFORE step 2 conceptually — order of operations in one
   transaction: dissolve → assign → leader remainder → save_run.

Full run: §2 end-to-end + calibration, mode='full'.

### 4.4 Dissolve and tombstones

Segments deleted since the last run leave `card_chunks` rows pointing at gone segment
ids (v1's `card_chunks.chunk` FK has no CASCADE and v1 never needed one — it wiped
everything; the v2 DDL above keeps that shape deliberately: chunk rows are removed by
the dissolve sweep, not by segment deletion). `dissolve_pass`:

1. `DELETE FROM card_chunks WHERE chunk NOT IN (SELECT id FROM segments)` scoped to the
   view's cards; recompute affected cards' size/n_files/centroid from surviving
   members.
2. A card falling below `min_members` → `status='dissolved'` (rows kept — history and
   diffability, 06 §4.4); its surviving members re-enter the remainder of step 5.

Full-recompute triggers (any → full): no previous run for the view; algo or τ or scope
change; embed_id change; > 20% member-file deletions; `--refresh`.

### 4.5 `--refresh`

"forget incremental state, rebuild" (06 §4.4): full pipeline for the view; the previous
run row STAYS in distill_runs; cards for the view are deleted and rewritten in the same
`save_run` transaction. `--rerun NAME --refresh` composes (refresh a saved view).

### 4.6 The incremental gate metric (R6 完成标准 "增量 <10% 重算")

F5: the honest, falsifiable form. `stats["reclustered_chunks"]` = number of EXISTING
(previous-run) chunks sent through the leader pass (dissolve survivors + re-entered
members); `stats["chunks_reassigned_into_existing_cards"]` = new chunks absorbed by
existing cards (reported so silent absorption is visible — measured 213/230 on a real
slice when this was invisible). Gate ratio:
`reclustered_chunks / corpus_after_dedupe ≤ 0.10` (denominator = the CURRENT run's
after-dedupe count). The ROADMAP standard ("增量更新不全量重算") is a compute-liveness
gate — no full recompute work performed — not a quality claim; quality lives in the
canary gates. Brand-new chunks are first-time work and don't count as reclusters. Canary
step (§7.4 incremental variant): add 10 docs to the distilled 100-doc fixture → 0
existing chunks reclustered → 0% ≤ 10%, plus the run must SKIP calibration (no new
sampled gram; τ inherited) — asserted.

## 5. Determinism contract (D14)

1. Canonical order `(file_id, segment_id)` for corpus, members, medoid/excerpt
   tie-breaks (`distill.py:242` kept).
2. No RNG anywhere: stride sampling (§2.2.1), sorted() everywhere iteration order could
   leak (dict → sorted keys in scope_json/corpus_hash canonicalization).
3. Ties: lowest cluster index (assignment), lowest segment id (medoid, coverage),
   alphabetical (terms, `(−score, term)` sort as v1 `distill.py:194-200`).
4. fp16 discipline: all math on decoded-fp16 f32 vectors; stored centroids =
   renormalized f32 mean → `util.pack_fp16` (`util.py:111-117`); guards/assignments
   read the same decode path (`store.load_vectors` + `unpack_fp16`) — self-consistent
   per 06 §6.
5. Byte-stable outputs: same index + flags → byte-identical markdown AND `--json`.
   `--json` v2 carries NO wall-clock fields (stats: run_id/corpus_hash are input-derived
   hashes; `created_at` lives only in DB rows). Floats in JSON rounded as today
   (weights 6 places; τ/percentiles 4 places).
6. `scripts/eval_distill.py` fixture generation: pure string templating, no RNG
   (§7.1) — eval outputs are byte-stable too.

## 7. Canary eval — `scripts/eval_distill.py` (D12)

Pattern copied from `scripts/eval_relevance.py` (structure, argparse, `--json`,
tmp-home convention; `eval_relevance.py:282-297`).

### 7.1 Fixture (deterministic, no RNG)

`build_corpus() -> list[PlantedDoc]` in the script (importable — tests use it too):
**100 docs** (count pinned, F9) = 8 planted topics × 10 docs (topic vocabularies in a
TOPIC_TERMS dict, `eval_relevance.py:35-60` pattern; per-doc variation by rotating the
topic term order and varying filler count — the validated probe recipe, header note) +
12 noise docs (filler-only, no topic vocab) + 8 twin docs (4 near-dup pairs, one
sentence changed; counted in their original's topic — 80+12+8 = 100). Known member sets:
`doc_id -> topic` is the expect-list (DigUp methodology, 06 §3). Topics chosen disjoint
from eval_relevance's where practical to avoid shared-sha collisions in one tmp home.

### 7.2 Metrics (computed, not judged)

Over the post-dedupe corpus, chunk → doc → planted label:

- **Purity** = Σ_cards size·dominant-fraction / Σ_cards size (cards = active, size ≥
  min_members; headers/dissolved excluded). **Gate ≥ 0.70.**
- **ARI** = adjusted Rand index between planted labels and card assignment; singleton
  and dropped-small chunks get their own singleton label. Implemented in-script
  (numpy, ~15 lines, contingency-table formula) — no sklearn (REDESIGN §8 kill list).
  **Gate ≥ 0.50.**
- **Canary recovery** = planted topics rendered as exactly ONE active card whose
  membership contains ≥ 80% of the topic's docs. **Gate ≥ 6 of 8.**
- **Excerpt fidelity** = every excerpt string ∈ set of `util.excerpt` over stored
  segment texts. **Gate 100%.**
- **Degenerate τ** (§7.4): single-topic variant asserts `tau_source != 'otsu'`.

### 7.3 Offline decision (the prompt's CAN-mock question — answered)

**CI runs the full metric suite on the mock backend, offline.** Justification: the
probe (header note) shows templated-fixture mock geometry is cleanly separable
(0.84 vs 0.23) — purity/ARI/recovery on mock are honest END-TO-END regression gates
for corpus→chunk→embed→calibrate→cluster→cards, and they RUN on every test pass
instead of hiding behind GOLDMINE_LIVE. What mock cannot validate is τ calibration
against REAL llama cosine distributions (narrow high band, the B10 centroid offset,
floor 0.55's real-world value). That stays with:

- **`--backend llama` mode** (GOLDMINE_LIVE=1, like `tests/test_live_pack.py:21-24`):
  same fixture + gates, prints the llama τ/tau_source/quartiles report; run manually
  and recorded in the release checklist. If it over-merges → the pre-approved
  centroid-calibration contingency (D3).
- No baked binary fixture in git (rejected: 06 §1 already weighed it; a committed
  sqlite of vectors rots with the model pin and contradicts the repo's
  generated-at-test-time leaning, REDESIGN §9 Q2). A pure-unit `measure_tau` test with
  synthetic pair arrays covers the real-geometry Otsu math without any backend.

### 7.4 Variants (all in the script, flag-selected)

- `--variant main` (default): the 100-doc canary + all gates.
- `--variant single-topic`: 20 docs, ONE planted topic → assert `tau_source !=
  'otsu'` (B9 normative assertion) and no crash; purity defined but only the
  tau_source assertion gates.
- `--variant micro`: 20-chunk corpus → runs, honest stats, no crash (06 §6 risk row).
- `--variant shuffle`: same corpus, docs re-ingested in reversed order → recovery
  unchanged (order-robustness assertion, 06 §4.2; CI-cheap on mock).
- `--variant incremental`: distill 100 docs → ingest 10 more (new 9th topic) →
  `--rerun` → assert mode='incremental', `tau_inherited=true`, reclustered ratio ≤
  0.10, recovery of the original 8 unchanged (§4.6 gate).
- `--variant hard` (F1, the real offline gate): the filler-heavy fixture — 3× SHARED
  filler in every doc pushes cross-topic pairwise cosine to ≈ 0.68 (real-corpus
  geometry). Gated on the DIFFERENTIAL: v1 rules (τ=0.70 fixed, centroid-only
  admission) must FAIL (purity < 0.70; ≈ 0.20 measured — one mega-card) and v2 rules
  must PASS (purity 1.000 measured + the standard gates). Proves the algorithm, not
  just the fixture, does the work.
- `--report-real DB` (F2b, mode not variant): open an EXISTING index read-only, run
  calibration + clustering in memory, print the calibration report, the card-size
  distribution, and the biggest-card share (no writes). When the top-card share
  exceeds 0.8 the report prints the F2c contingency line (switch calibration to
  centroid scale — pre-approved, documented, not implemented here). Numbers recorded
  in the release checklist.

### 7.5 Exit codes

All gates green → 0; any gate red → 1 with the failing metrics printed (same
report-then-verdict shape as the R4 gate, `docs/v2.1-pack-eval.md` D13). In-suite
pytest wrappers (`tests/test_eval_harness.py` pattern) run `--variant main single-topic
micro shuffle incremental` on mock so the gates are CI-enforced, not just
script-honored.

### 8.0 Review amendments (adversarial review 2026-10-19 — all mandatory, absorbed)

The adversarial review of this spec found eleven issues. Each amendment below is
normative and supersedes the conflicting line above it.

- **F1 (CRITICAL) — the offline canary must discriminate, not smoke-test.** The templated
  fixture is so separable (same-topic 0.84 vs cross 0.23) that even v1 rules and a broken
  τ=0.40 pass it: it tests the FIXTURE, not the algorithm. Fix: add the filler-heavy HARD
  variant fixture — same 8 planted topics, every doc carries 3× SHARED filler (all 100 docs
  repeat the same filler sentences), pushing cross-topic pairwise cosine to ≈ 0.68, the

  variant's gate is the DIFFERENTIAL: run under v1 rules (τ=0.70 fixed, centroid-only
  admission) it must FAIL (purity ≈ 0.20 measured — one mega-card), and under v2 rules it
  must PASS (purity 1.000 measured). The main fixture stays for determinism/e2e only and
  gates nothing about algorithm quality. This differential is the real offline gate.
- **F2 (HIGH) — real corpora run the percentile fallback; expect it, report it, pre-arm
  the contingency.** (a) Real corpora are UNIMODAL in pairwise cosine (measured median
  pairwise cos 0.661 on 3 real slices): Otsu's valley check never fires and calibration
  lands on `tau_source='percentile'` with τ ≈ 0.72–0.80. This is EXPECTED behavior —

- **F3 (HIGH) — repeat identical runs must not collide on the run PK.** Pinned: `save_run`
  uses `INSERT … ON CONFLICT(id) DO UPDATE SET stats_json, created_at` — a repeated
  identical run (same algo/τ/scope/corpus/mode, e.g. after `--refresh` on an unchanged

  History claim weakens from "append-only" to "append-only up to identical-content
  repeats"; run_id stays a pure input-derived hash (determinism contract intact).
- **F4 (MEDIUM) — corpus_hash is audit-only.** It exists for run identity and diffing,

- **F6 (MEDIUM) — histogram bins clamp, never wrap.** Negative cosines are legal;
  `bin = int(c·256)` wraps them to the top. Normative: `bin = max(0, min(int(c·256), 255))`.
- **F7 (MEDIUM) — the fp16 guard shortcut is forbidden and tested.** Normative: the
